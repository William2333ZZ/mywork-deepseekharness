# MyWork 交互设计：一件事的延续

## 核心主张

1. 深度研究的单位是"一件事"。它比一轮对话长（几周到几个月，几十轮，好几个版本），又比一位同事窄（同一位同事手上可能同时有跟踪、三份深度、一次核对）。现在这件事在产品里没有地方放，所以找不回、没有版本、超时就丢（任务书 3.2-4/7/8）。
2. 我在同事之内只加一层，叫「卷」。一卷是同事文件夹里的一个子文件夹，放这件事的全部状态：卷首（问题、范围、来源、验收、预算）、事实表、结论表、各版交付物、进展日志。卷里不放对话。
3. 对话仍然只有一条。属于某一卷的几轮带一个卷标，点卷标就"只看这一卷"；引用某张卡回复，就是对那一卷说话。卷没有列表页，没有"新建"按钮，不进任何全局看板。它只能从对话里开（同事提议，你在开卷卡上点头），也只列在这位同事的右栏里。
4. 引擎按卷分上下文。每卷一个会话，例行每次从卷里的文件重新接上。同事和你随口聊天的主会话因此保持轻。
5. 交付物是卷里的文件，有版本，也有"取代"关系。结论是结论表里的一行，带依据，也写明什么情况要重看。三个月后要找的就是这一行。
6. 核对以事实为单位。先登记事实，再写成文。正文里的数字只能引用事实编号。核对顺序是：脚本逐字核，另一方二审，剩下的按风险排给你。你点"不对"，就出一个新版本，并且提出一条规矩。
7. 长任务就是卷里按步骤跑的计划。每一步的结果都存成文件，中断了从断点续；中途改方向，就是改计划。
8. 例行交出来的是"这一卷变了什么"，不再是又一份简报。没有变化时只留一行灰字，不再把东西藏起来。
9. 记忆分三层，每层一个文件：关于我、这位同事的规矩、这一卷的口径。写进去要你点头；什么时候用到，卡片上写明；能用脚本检查的规矩，变成交付前的一道检查。

## 读法

- "据"后面是出处：任务书节号（3.2-4 指第 3.2 节第 4 个断点）、本目录的材料文件、需求报告编号（F1、R1、I1 等），以及任务书 4.1 节列出的做法（用做法的名字）。
- 【推断】表示我的判断，没有直接证据。
- 文件名和表头都用中文，沿用 EDITIONS 的约定"表头保持中文，只往后加列"。

## 1. 对象模型

### 1.1 一览

| 对象 | 用户看到什么 | 存在哪 | 界面里出现在哪 | 生命周期 | 为什么现有的不够 |
|---|---|---|---|---|---|
| 同事（不变） | 名字、职责、一条对话 | 现状 | 左栏 | 现状 | — |
| 卷（新） | 一件事的名字加一个状态词 | `mates/<id>/卷/<卷名>-<短id>/` | 对话里的卷标，右栏「卷」页签 | 提议 → 常设或进行中 → 搁置 → 合上 → 可以重开 | 现在一件事只是对话里的一轮，样子和日更一模一样，没有地方放计划、版本、中间结果（据 3.2-4/7/8；评估走查 1） |
| 卷首（卷的第一页） | 一页可以改的约定 | `卷首.md` | 开卷卡，卷页顶部 | 开卷时同事起草，你改；之后的纠正追加成口径 | 职责是整位同事的长期指令（上限 2000 字），装不下一件事的问题、验收和预算 |
| 事实（新） | 正文里带下划线的数字，核对面板里的一条 | `事实.csv` 加 `原始/` 里的快照 | 阅读视图、核对面板、结论卡 | 登记 → 机检 → 二审 → 你核 → 被取代或被驳回 | 数字和出处不成对（据 3.2-1：一份简报中位 48.5 个数字、1 个链接）；核验员只看得到调用过哪些工具（kernel verification） |
| 结论（新） | 一句话、依据、状态、什么时候重看 | `结论.csv` | 卷页、结论卡、变化卡 | 定下 → 成立 / 动摇 / 推翻 / 到期结算 → 被取代 | 旧结论找不回（据 3.2-4）；"当初为什么没选"没有被记成任何东西（评估走查 4） |
| 交付物（改） | 文件卡，多一行版本和一行核对回执 | `交付/` 下的文件加 `版本.json` | 对话、文件页 | v1 → v2（取代 v1）…… | 正文存在 JSON 里，没有版本（据 3.2-8），同事自己读不到（3.2-4），和文件夹分成两套（3.2-10） |
| 规矩（改，原「它记住的」） | 一条条规则，带来源和用过几次 | `AGENTS.md`；还没确认的放在 `.mywork/待确认.jsonl` | 右栏资料页「规矩」 | 提议 → 你点头 → 生效 → 改或删 | 7 天只记了 3 行，全是偏好，纠正落不到实处（据 3.2-6） |
| 例行（改） | 和现在一样，多了所属的卷和预检 | `routines.json` 加 `juanId`、`precheck` | 右栏例行、卷页 | 现状 | 每次都叫模型，靠回话末行判断有没有变化（据 3.2-3） |

计划和进展日志是卷内部的文件，不算给用户的新概念，它们通过进行中卡和卷页露出来。"判断"（金融的观点、假设）和"决定"（技术经理的选型）不另立对象，都是结论表里的一行，只是类型不同。这样少了两个概念。依据是三处需求都落在同一种东西上：一句话 + 依据 + 到期或触发条件 + 状态。分别见 ai-berkshire 的 thesis-tracker、alpha-desk 的预测台账、ADR 的 revisit date（understand-finance-projects；research-decisions-and-materials）。

### 1.2 卷是什么

- **常设卷**：没有终点，挂着例行。比如"自选 12 只""在用的 AI""课题 · 长上下文压缩"。只能暂停，不能合上。
- **有期卷**：有验收、预算和截止日期。比如"恒瑞 · 三季报前深度""投稿前引用核对""DeepSeek 10 月变更"。合上时，结论并回常设卷的结论表。

两种结构完全一样，用户看到的只有一种"卷"。同事满足下面任一条时提议开卷（写进 persona）：这件事要跨好几轮；预计超过 20 分钟；要交一份以后会改版的东西；用户说了"跟踪 / 长期 / 每天 / 投稿前 / 选型"。其余照旧是零散的一轮，零散产出以后可以"归卷"。

为什么常设跟踪也算一卷：买方分析师自建体系的教训是，按公司各开各的项目，就没法跨公司、跨季度关联，知识应该按覆盖范围整体建（understand-finance-projects，"美股大白话"条第 7 点）。所以 12 只票是一卷，不是 12 卷。

### 1.3 卷和任务有什么不同，为什么这不是在和产品作对

| | 被否决的任务 | 卷 |
|---|---|---|
| 怎么开始 | 用户在任务页或新任务页填写 | 只从对话里开：同事提议，你在开卷卡上点头。没有新建按钮，没有表单 |
| 有没有自己的对话 | 有，一条单独的线程 | 没有。所有往来都在同事那一条对话里，卷只是给其中几轮挂一个标签 |
| 终点 | 做完就结束 | 不以做完为终点。常设卷不结束；有期卷合上以后结论并回常设卷，还能重开 |
| 装的是什么 | 一次交办的指令和结果 | 这件事的状态：卷首、事实、结论、版本、日志、花费 |
| 列在哪 | 全局任务列表或看板，等用户逐个处理 | 只在这位同事右栏的「卷」页签里。不进全局列表，也不算"等你看" |
| 占不占注意力 | 要你验收 | 卷本身不要你看。需要你的东西照旧走找你卡和铃铛 |

Rakazo 反对两件事：把同事缩成提示词预设，以及把同事缩成孤立的一次性任务（任务书 1）。卷两样都不是。卷由同事保管，是它"手上的东西"：离开同事就不存在，不能单独打开聊天，也不能转给别人。卷补上的，正是 Rakazo VISION 自己要求"同事状态可检查、可导出、可恢复"而我们还没做到的部分（survey-persistent-agents，Rakazo 条），也对应 OpenClaw 那句"模型只记得存到磁盘上的东西"。

dots 走的是另一条路：每个派出去的任务一条可见线程（任务书 4）。我不走这条路，因为它把一件事的往来拆到另一个地方，正是被否决过的形状。我只把一件事的状态拆出去，往来留在原处。

一条永续对话撑不住，证据是 Dispatch 被下架、OpenClaw 的话题互相混。我的回答是：上下文按卷分（引擎），状态按卷存成文件，视图可以按卷过滤（只看这一卷），对话入口不分。

**这是对现有模型的四处改动，其余不动**：
1. Run 多一个可选字段 `juanId`；
2. 同事文件夹里多一个 `卷/` 目录；
3. 引擎每卷一个会话；
4. 右栏多一个「卷」页签。

左栏、对话本身、"跳到那一轮并高亮"的规则都不变。

### 1.4 怎么对某一卷说话

- **在完整对话里直接发**：进主会话。同事判断这句话属于某一卷时，调用 `mywork_juan_attach`，回复下方出现「归入：恒瑞深度 ▾」，点 ▾ 可以改归属或取消。要动手干活时，它把这句话交给那一卷的会话；下一轮开头会带卷标，不另出一行"转交"字样，以免变回被否决的交办行。
- **引用某张卡回复**：悬停卡片出现线条图标「引用」，输入框上方显示引用条；或者在"只看这一卷"里发。这两种情况直接进那一卷的会话。
- **引用进行中卡**：插进正在跑的那一步（steer）。
- **阅读视图里选中一句话**，点「问它」：引用条里带上这句话和它的事实编号。现在没有"针对某一句追问"的入口（kernel threadItems），这一条补上。

路由一律显式。依据是 Dust 放弃在一条对话里 @ 多个智能体，理由是只有一对一的中途插话才可靠（任务书 4）。

**只看这一卷**：点任何一个卷标，中栏顶部出现一条横栏「只看 · 恒瑞三季报前深度 · 23 轮 · 卷首 · 退出」。对话只显示这一卷的轮次，输入框占位变成「对『恒瑞三季报前深度』说……」。它是同一条对话的过滤视图，像微信的"查找聊天记录"，不是另一条线程。

```
mates/<id>/

  .mywork/待确认.jsonl            想记但你还没点头的
  卷/恒瑞三季报前深度-j7k2/
    卷首.md                      人读、人改
    卷.json                      引擎写：状态、计划步骤、花费、例行、会话
    日志.md                      只追加：做了什么、走不通的路、改方向、作废了什么
    事实.csv   结论.csv           两张固定表
    其他底稿表（可比表.csv、引用台账.csv、在用清单.csv……）
    材料/                        你给的文件，加解析结果（页图、bbox 索引）
    原始/                        抓下来的网页快照，按内容哈希存（默认折叠）
    交付/                        各版交付物，加 版本.json
    核对.jsonl                   每条核对记录：谁、什么时候、对或不对、原因
```

原始抓取单独放进 `原始/`，右栏默认折叠。这是因为现在文件夹被原始网页淹没（据 3.2-10：一位同事 4 天 101 个文件，99 个是原始网页）。

### 1.6 卷首

```
# 恒瑞医药 · 三季报前深度
状态：进行中 · 10/06 开 · 预算 ¥20 · 已花 ¥12.80 · 截止 10/20
## 要回答的问题（不超过 3 个）
## 范围
## 来源       一手：…  可用：…  不用：…  已知读不到：…
## 交付       底稿（按章）· 事实表 · 一页结论
## 怎么算做完  每个数字都有事实编号；计算全部由脚本完成；没核到的单列
## 遇到这些停下来问我   年报和研报口径差超过 5% / 来源打不开 / 超预算
## 体例       每次报这几个数：…（锁定标签）
## 口径       收入按地区拆（10/08 你定的，来自第 12 轮）
## 当前结论    （从结论表生成，不手写）
```

"体例"一节把卡片上关键数字的标签锁住，对应 3.2-13 的问题：同一条例行 4 次运行出了 4 组不同标签。"怎么算做完"和"停下来问"借的是"先写下怎么算做完和什么时候必须停"这条做法。

### 1.7 事实

`事实.csv` 的列：编号（F0311）、对象、说法、值、单位、期间、口径、来源层级（一手 / 可用 / 二手）、来源（文件或网址）、位置（页码、段落、单元格）、摘录、取于、算式（计算出来的数才有）、机检、二审、你核、状态（有效 / 过期 / 被驳回 / 被取代）、取代（被哪一条取代）。列的来源：天风事实包的七个字段、国投叶青的 evidence_index、liteparse 的页码和 bbox（understand-finance-projects）。

界面上合成四种状态。强调色只给后两种"和你有关的"：
- **已对上**：机检通过，并且二审判"支持"；
- **需要你看**：机检没找到、二审判"弱"或"说不准"、来源互相冲突、只有二手来源；
- **有问题**：复算不符、二审判"不支持"、被你驳回；
- **未核到**：来源打不开，后面跟原因。

你亲手核过的，额外加一个"你核过"标记。

### 1.8 结论

`结论.csv` 的列：编号（C2）、对象、结论、类型（看法 / 判断 / 决定）、依据（事实编号）、定于（日期和哪一版交付物）、状态、重看条件、重看日期、方向 / 阈值 / 期限（只有判断类有）、结算、取代。

几个依据：
- 判断必须写成方向、阈值和时限三项，否则不进表（鸣山）。
- 结算由脚本裁决（alpha-desk）。
- 状态变化只比证据，不比措辞（thesis-drift）。
- 决定类借 ADR：没选的方案和理由、什么情况重看、被谁取代（research-decisions-and-materials）。
- 决定的状态词借技术雷达的环：在用 / 试用 / 观察 / 暂停。

## 2. 第一次见面

**新同事表单**：在现有的"它负责什么 / 类型 / 名字 / 头像"上方加一行模板选择：覆盖研究 · 课题跟踪 · 盯我们在用的 AI · 空白。模板来自版本包（EDITIONS 第 5 节结构）。底层是现成的 createMate 和结构化 createRoutine（任务书 3.3）。

**自我介绍那一轮可以问，最多 3 问**（现在不能问，见 engine.js:174 introPrompt）。每问一张找你卡，新加一种"材料"类问题：可以拖入文件、粘贴清单、贴截图。依据：
- Rakazo 建 bot 时会先访谈用户，CHANGELOG 记了"建好不出声"导致误解职责要到第一次干活才暴露（survey-persistent-agents）；
- Financial Analyzer v3 首次使用聊 4 轮，把 client_rules.md 逐条念给用户确认，状态从 TEMPLATE 变 ACTIVE 之后才允许干活（understand-finance-projects）。

我把它压到 3 问，因为第一周就要能用。

**3 问之后**，同事起草常设卷的卷首，发一张开卷卡。你开工前要确认这几件事：
1. 范围：一张表，比如 12 只票、在用清单、种子论文；
2. 来源分级，以及已经知道读不到的来源；
3. 报什么、不报什么（什么算变化）；
4. 例行时间（结构化，比如"交易日 07:30"）；
5. 每月预算上限，附估算依据；
6. 模板自带的初始规矩，可以逐条删。

按钮：「开始」（马上出第一份，作为基线）/「改卷首」/「先不建例行」。第一份基线不会被判成"没有变化"，避免产品雷达第一次例行被整份藏掉的问题（3.2-3）。

**空白同事**只问一句（choice）："要我长期盯着什么吗？"选"有"就起草常设卷，选"没有，有事找你"就保持现状。MyWork 建的同事，它转交的第一件事就成为第一张开卷卡。

## 3. 日常节奏

### 3.1 例行到点以后

1. **先跑预检脚本**：比较公告列表、价格是否越过你设的线、models.dev 的 JSON、arXiv 列表。来源都没变，就不叫模型，只在对话里留一行灰字。据：任务书 3.3"例行先跑脚本、没变化不叫模型"；49 轮例行只有 3 轮安静，而安静的那几轮照样花了完整的模型费用。
2. **来源有变化**：在这一卷的会话里叫模型。它从卷首、上一张变化卡和底稿表接上，不往无限长的主会话里追加。
3. **它用 deliver 交一张变化卡**，变化分组放在结构化的 data 里。引擎按分组判断安静与否："动到你的结论"和"更新了底稿"都空，才算安静。不再读回话末行的"变化：无"（据 3.2-3）。

```
例行 · 自选 12 只 · 07:30
自选 12 只 · 10/21 的变化
动到你的结论 1
  恒瑞 C2「创新药收入过半」→ 动摇
  三季报创新药收入占比 47%〔F0311 · 三季报 p.12〕
  [记下] [改结论] [以后别报这类]
更新了底稿 3     公告库 +2 · 药明 跌破你设的 52
看过没变 8 家 ▸
读到 23/24 个来源 · 没读到：雪球（要登录）→ 已放进待你办
¥0.38 · 2m
```

分组借鉴：鸣山和雪球作者的"重复 / 噪音 / 新变化"三分，以及"被筛掉的要看得见"；条目上的三个动作借带原因的收件箱（"处理完 / 稍后 / 别再提醒"）。点「以后别报这类」，写进卷首"报什么"一节，并出一行小字说明。

**没有变化时**：一行灰字「例行 · 自选 12 只 · 07:30 · 看过 12 家公告和行情，没有变化 ▸」。连续几次合成一行「10/03–10/07 · 5 次没有变化」。展开能看到每次看过什么。不算未读，不发通知。

两条硬规则：
- **来源读失败，不算没有变化**：要么出"没读到 n 个来源"，要么进待你办。依据 EDITIONS 第 7 节"失败不等于没有新闻"。
- **第一次运行永远显示**。

### 3.2 只有你能解决的事

新加一种不挡运行的找你卡，叫"待你办"（askKind `notice`）。**例行里也可以发**。例行照样做完能做的部分，卡片一直留在铃铛"需要你"里，写清原因，比如"登录 X · 技术雷达、产品雷达都卡在这"。按 key 去重（比如 `login:x.com`），几位同事卡在同一件事上，只出一条，上面写"2 位同事在等"。动作有三个：「去处理」（登录就是 takeover，只能在桌面做）/「先不管 3 天」/「别再提醒」（把这个来源写进卷首的"不用"）。

依据：例行不许提问，而近三分之二的轮是例行；X 登录的问题在两位同事的报告正文里重复了 4 天（3.2-2）。

同时去掉"24 小时不答就按假设继续"在 approval 和 takeover 两类上的适用：有后果的动作和登录不能自动越过（kernel constraints，engine.js:826-840）。

### 3.3 几位同事早上一起交东西

- **少跑**：预检让大多数例行不叫模型。同一时刻（比如 9:00）排队的模型运行变少。据：评估里 9:00 有 3 条例行同时到点，第三位每天排队约 1 分钟。
- **MyWork 晨报改成目录卡**：内容由代码从各位同事的变化卡和待你办里生成，模型不写一个字，所以不会再"说没有依据的话"（据 3.2-5）。晨报是 MyWork 本来就有的例行，所以这是一张消息卡，不是一个页面。08:40 先出一版，之后在原卡上更新，直到上午其他同事的例行全部交完（最晚 11:00），顶部写「更新于 9:07 · 还在跑：产品雷达」。用户喜欢总管式的汇报（任务书 4）。可以关掉。

```
MyWork · 晨报 · 10/21
待你办 1     登录雪球（覆盖研究在等 · 第 2 天）  需要在电脑上
动到你的结论 2
  覆盖研究 · 恒瑞 C2 → 动摇
  盯 AI · deepseek-chat 涨价，影响 2 个业务（截止 10/15）

新交付 1       课题 · 3 篇相关新论文
没有变化     9 次例行 ▸

```

- **铃铛按原因分组**：需要你 / 动到结论 / 在干活 / 刚完成。仍然是现有铃铛，不新开看板。

看晨报目录 → 点"动到结论"的条目，读两行和原文摘录图 → 点「记下」或「以后别报」→ 批开卷卡 → 抽核 3 条 → 把登录这类事推到晚上。详见第 11 节和场景 5。

## 4. 核对

### 4.1 核对链

1. **写之前先登记事实**（"事实包先于成文"）。同事用 `mywork_fact` 登记值、出处和摘录，引擎当场存快照：文件取 liteparse 那一页的文本、页图和 bbox，网页取页面文本，按哈希存进 `原始/`。正文里的数字写成 `[F0311]`，渲染成下划线。这样也解决了"核验员看不到工具返回的内容"（kernel verification）。
2. **机检（脚本，不是模型）**，在 `engine.deliver()` 这一处做，不通过就拒收，模型看到报错会重做（cheapExtensions"交付前用脚本核对数字"）。查这几项：
   - 摘录在原文快照里能逐字找到，数字在摘录里能逐字找到（借 dsh-research-verify 的字面核查）；
   - 有算式的重新算一遍（移植 ai-berkshire 的 financial_rigor）；
   - 期间、单位和正文一致；
   - 能机检的规矩逐条过（第 5 节）；
   - 关键数字两个来源相差超过 1%，标"冲突"（ai-berkshire financial-data）。
   - 正文里出现没有引用编号的数字，拒收。年份、日期、章节号、区间不算，排除规则借 report_audit。这条只在卷首写了相应验收的卷里生效，零散聊天不受影响。
3. **二审（另一方）**：只审机检定不了的事实（转述、语义），以及全部结论行（依据是否撑得住结论）。二审方只拿到"说法 + 原文摘录"，不拿执行者的叙述和"我修了什么"（ARIS reviewer-independence）。判词四种：支持 / 弱 / 不支持 / 说不准，每条必须引出原文句子。
4. **你核**：按风险排好的队列（4.4）。另有「我来抽 3 条」，系统随机给 3 条（"随机抽检"反过来由人抽）。

### 4.2 文件卡上的回执

```
恒瑞 · 三季报前深度底稿                         v2 · 取代 v1 · 改了 4 处 · 对比
事实 236 · 已对上 181 · 需要你看 38 · 有问题 5 · 未核到 12 · 你核过 80
二审：Kimi（另一家）   按规矩：#3 #4（#4 机检拦下 1 处）
卷 · 恒瑞三季报前深度 · 10/16 21:40                                     打开
```

这一行替代现在的 passed / checked / issues / notes 印章。那个印章不显示，也没法逐条处理（据 3.2-1：38 份文件标出 115 处问题，一处都没显示）。二审用的是哪家模型直接写在卡上。

### 4.3 核对视图

- **桌面**：阅读视图顶部加一个「核对」开关。打开后中栏是正文，"需要你看"和"有问题"的数字用强调色下划线。右栏临时换成核对面板，从上到下是：
  - 「第 7/30 条 · 最该看的」，以及为什么排在前面（比如"支撑结论 C2 · 只有二手来源"）；
  - 说法、值 / 单位 / 期间 / 口径；
  - 原文摘录，数字高亮。PDF 来源附页图裁切，带 bbox 框；
  - 来源、层级、取于；机检结果；二审判词和它引的原句；
  - 按钮：「对」(Y) /「不对」(N) /「跳过」(S) /「打开原文」；
  - 最下面是依赖这条事实的结论。

  J / K 翻条。「打开原文」把网页送进实时浏览器，网址带 `#:~:text=` 文字片段（Chrome 的滚动到文字功能）；PDF 带 `#page=N`。右栏切到「电脑」，有「← 回到核对」。全程不用 iframe（任务书 1）。
- **手机**：全屏卡片，上半是说法，下半是摘录图，左右两个大按钮。逐条点判在手机上比读全文合适（"评审式逐条过"那条做法里的手机落点）。

### 4.4 排序规则【推断，没有现成做法】

任务书 4.3 说"按风险给出抽查顺序"是空位。我的规则是加权计分：

| 情况 | 分值 |
|---|---|
| 支撑某条结论 | +3 |
| 机检没通过 | +3 |
| 二审判弱 / 不支持 / 说不准 | +3 |
| 来源冲突 | +2 |
| 只有二手来源 | +2 |
| 有时效且取得早 | +2 |
| 属于"上次错过"的类别（来自规矩和被驳回的记录） | +2 |
| 是计算出来的数 | +1 |

"最该看的"取前 max(5, 10%) 条。每条都显示它为什么排在这里。依据：实验里按"最可能被用户改动"高亮才有效，按模型概率高亮没用（任务书 4.2；understand-patterns 反模式）。

### 4.5 进度怎么显示

文件卡回执、阅读视图顶部的分段条、卷页都写"你核过 80/236"。你核过的数，如果后来一版里变了，自动退回"未看"（借 GitHub 的 Viewed 标记）。

### 4.6 你说"这条不对"之后

1. 选原因，一次点选：数字错 / 出处不支持 / 过期了 / 口径不对 / 其他，可以加一句话。记进 `核对.jsonl`，事实状态改为"被驳回"。
2. 依赖它的结论状态变成"动摇（待复核）"。
3. 自动排一轮修正，归在这一卷：重新取数，登记新事实（旧的标"被取代"），脚本重算依赖它的数，只改受影响的段落，出 v(n+1)，文件卡写"改了几处"。
4. 原因能推广成规则的，回复下面出「记一条？」（第 5 节）。
5. 改内容（换掉或删除引用、改结论）永远要你批；只改元数据的可以自动做（ARIS 的规则）。

### 4.7 谁先挑错

顺序是：脚本 → 另一家模型 → 你。

- 设置里分开选"干活用"和"二审用"两个模型。默认只有 DeepSeek 时，第一次用到核对，提示接一个国产的另一家（Kimi / Qwen / GLM，能开国内发票）。依据：ARIS 推荐的替代审稿人就是 Kimi 或 Qwen；国内研究者的痛点是海外账号和发票（需求报告 6.9-2）。
- 只有一家时，用同一家模型新开会话，只喂说法和摘录。回执写明"二审：同一家模型，独立性弱"，不假装独立。
- 现有的核验（同一个模型、看不到工具返回）整体换掉（任务书 4.2"同一个模型审自己"）。

### 4.8 "没核到"怎么列

回执末尾单独一段，按原因分组，每组写清怎么补：

- 打不开（需要登录：万得、雪球）→ 待你办，登录；
- 付费墙 → 你手上有就拖进来；
- 只有二手来源 → 列出来，由你判断能不能用；
- 资料里没有 → 写"没查到"，不写"不存在"；
- 引用数据库没收录 → 写"没查到 ≠ 不存在"。

文案借 hallucinator："这是怀疑，不是证明"。

### 4.9 门设在哪

不强制核对后才能交付。依据：强制确认最有效，也最不受欢迎（任务书 4.2）。门只设三处：
1. 改内容的修改；
2. 写进长期记忆；
3. 有期卷合上时，"需要你看"还剩的条目，要么处理掉，要么点「带着未核的合上」，卷页会永久记下"带 12 条未核合上"。

对应"把核对做成必经的一步"那条做法里的三处门。

### 5.1 三层，加上日志

|---|---|---|---|---|
| 关于我（所有同事都读） | `$DSH_HOME/AGENTS.md` | MyWork 资料页、设置 | 你直接改；同事只能提议 | 要 |
| 这位同事的规矩 | `mates/<id>/AGENTS.md` | 右栏资料「规矩」 | 你直接增删改；同事只能提议 | 要 |

"关于我"现在在产品界面之外，同一句偏好被用户 2 分钟内说了两遍（据 3.2-6），所以把它搬进界面。

### 5.2 一次纠正怎么变成一条规矩

```
（同事回复下方）
想记一条规矩：引用财务数字用最新一期披露；用旧期间的，标「旧数」并写原因。
范围：这位同事 ▾   能机检：能（交付前比对事实的期间和最新定期报告日期）
来源：10/21 第 34 轮 · 你驳回 F0412 的原因「过期了」
[记] [改一下] [不记]
```

没有处理的留在「规矩 · 待你确认 n」，不写进 AGENTS.md，也不进上下文。依据："记忆分草稿区和正式区、进正式区要人点头"；HN 上的说法是，没人看过的条目半年后会变成很自信的错话（understand-patterns）。`mywork_remember` 改成只提议，不再直接追加。

### 5.3 怎么知道它下次用到了

- **能机检的规矩**变成交付关口里的一项检查。它拦下东西时，卡上写"规矩 #4 机检：拦下 1 处旧数，已换成三季报"。这是脚本的结果，不是同事的自述。
- **只能自述的规矩**（比如"语气克制"）：deliver 加一个 `rulesApplied` 参数，卡上写"按规矩 #6（自述）"。同时，这一类别在核对排序里加分，让你更容易抽到它。
- 规矩面板每一条显示"10/06 定 · 用过 9 次 · 机检拦下 3 次 · 上次 10/20"，点来源跳回定下它的那一轮。借 ChatGPT 2026-05 的做法：回复上能看到这次用了哪些记忆（survey-beyond-the-thread）。
- **主动摆出"上次错在哪"**（任务书 4.3 列的空位）：开卷卡上加一行「上次在这类事上错过：把 TTM 当成年度（9/12），这次已加机检」。

### 5.4 体检

每月一条例行，结果是一张卡：「这 3 条 30 天没用过 · 这 2 条互相矛盾 · 这 1 条可能过时」。每条可以删或改。依据：Karpathy 的 wiki 有体检这项操作；"规则文件太长本身就拖慢、变贵"（understand-patterns）。

### 6.1 开工前看到什么

```
开一卷：XX 公司深度底稿
要回答  ① 份额能否守住  ② 新品毛利  ③ 海外放量节奏
步骤    1 读材料建事实（年报、3 份研报）  2–9 按你的框架逐章  10 机检和二审  11 一页结论

        资料充裕程度：A（年报齐全，研报 3 份）
交付    底稿（9 章，约 40 页）· 事实表 · 可比表.csv · 一页结论
算做完  每个数字有事实编号；计算全部由脚本；二手来源的数单列
会停    年报和研报口径差超过 5% · 来源打不开 · 到 ¥40

预计    2–3 小时 · ¥25–40（按默认表估；这位同事还没有同类历史）
[开始] [先试一小段：第 1 章 + 20 条事实] [改计划] [改卷首] [这次不开卷]
```

借鉴来源："开工前可改的计划"，"计划是可改的步骤清单"，"先写下怎么算做完"，"跑之前给档位和上限"，ai-berkshire 的资料充裕程度 A/B/C 评级。「改计划」把步骤变成一个可以直接编辑的列表：每步一行字，可拖动顺序，可删可加。这是 Cocoa 做法的缩小版。

**什么时候自动开工**：预计不超过单次自动上限（默认 ¥5，可以改），并且在预算之内，同事说"已开始，可随时停"直接开工。超过上限就等你点「开始」：不倒计时，也不会 24 小时后自动开工。依据：Devin 默认 30 秒后自动开工，但"30 秒对离开屏幕的人等于没问"（understand-patterns）。

**估算怎么来**【推断，没有产品做过开工前估价，任务书 4.3】：各步骤类型的默认量（每 100 页 PDF、每个网页、每千字成文、每条二审）乘以价格，再用这位同事的历史校正，给一个区间，并写明"按什么估"。卷合上时，卷页显示"估 ¥25–40 / 实际 ¥31"，让你看得到估得准不准。

**先试一小段**：跑完试点就停，出检查点卡，四种回答借 ARIS：「行，继续」/ 任意文字（当作补充指令）/「跳过第 N 步」/「停」。来源还有 Elicit 的"按列抽取先小样试跑再全量"。

### 6.2 中途看到什么

进行中卡在原处刷新：

```

```

左栏第二行显示「在干活 · XX 深度 · 第 5/11 步」。用到浏览器时，右栏「电脑」是实时画面，可以接手。这些借自"干活时看得见、能打断、能接手、能回到上一步"。

### 6.3 改方向

引用进行中卡，写"不看海外了，只看国内三家"。这句话插进正在跑的那一步。同事必须调用 `mywork_plan_update`，进行中卡上出改动：

```

预计剩余 40 分钟 · ¥9（比原计划少 ¥6）                         [撤销（2 分钟内）]
```

费用不增加就直接继续。会超预算的，出找你卡。作废的文件挪进 `日志.md` 记下的作废清单，不删。依据：评估走查 7 指出，现在改了方向以后，没有交代前面哪些作废、哪些保留。

### 6.4 超时、中断和续跑

- 计划执行器把每一步派成一轮运行，单轮上限仍是 20 分钟。每步结束时文件存好，并在 `卷.json` 里打勾。
- 某一步超时：从这一步开头自动重试一次；再失败就出找你卡：「重试 / 跳过 / 停」。
- 中断（重启、关机）：重新开机后，12 小时以内并且预算允许的，自动从断点续；超过 12 小时的，进行中卡显示「中断于第 5 步（服务重启）· 续跑」。
- 换代：上下文太满时开新一代会话，从卷首、日志和计划接上，进行中卡上一行小字「已从卷首和日志接上」。依据："总计划加进展日志"那条：没有日志，后面的会话会把同一条死路再走一遍（understand-patterns）。

```
历史  C1「2025 年过半」· 被 C2 取代（10/14）▸
[打开 v2 第 3 章] [只看这一卷] [重看]
```

### 7.3 依据留多久

- 快照按哈希存在 `原始/`，跟着卷一直留。
- 过程记录不再只留全体最新 60 轮：卷里那几轮的工具过程，摘要写进日志。
- 运行记录超过 2000 条上限时，按同事归档到磁盘，不再丢掉（kernel constraints）。

### 7.4 版本与取代

- 同一卷里，同名交付物再交一次，自动成为新版本。`版本.json` 记录：来自哪一轮、改了什么（同事写的摘要加计算出的差异）、核对状态延续（没变的事实保留你的核对，变了的退回未看）。
- 旧版文件卡读当前版本表，显示灰色的「已被 v3 取代 →」（照新同事卡读当前名册的样板）。
- 文件页按同事和卷分组，只列最新版，有「显示旧版本」开关。
- 结论的取代写在结论行里。新的有期卷合上时，它的结论取代常设卷里的旧结论。

### 7.5 跳转规则

在现有规则之外只加一条：凡是看结果，跳到那位同事对话里的那一轮；凡是看依据，打开那一卷里的那一行（事实、结论、交付物的段落锚点）。表格加行锚和高亮属于 cheapExtensions。

## 8. 三种用户各自的第一位同事

### 8.1 金融版：「覆盖研究」

**给谁**：先给独立投资者和 5–9 人的私募（任务书 2.2 的首批候选）。买方研究员用的是同一个模板，主场是有期卷里的深度底稿。

**常设卷「覆盖 · 我的 N 家」**：
- 覆盖.csv：代码、简称、市场、你为什么看、你的线（价格或指标阈值）、启用；
- 公告库.csv：沿用 EDITIONS 的列；
- 事实.csv；
- 结论.csv：每家 3–7 条核心假设，带验证方式和频率（借 thesis-tracker），加上带方向、阈值、期限的判断行。

不用 0–100 的评分。依据：investor-skill 删掉聚合分数，理由是"把主观直觉藏进数字里"；daily_stock_analysis 的分数是模型主观给的。判断照样可以给（负责人的规则是不设合规过滤），但必须能结算。

**例行**：
- 交易日 07:30 出变化：预检公告增减、行情越线、到期的结论；
- 交易日 21:30 公告入表：静默，除非动到结论；
- 周日 20:00 对账：脚本结算到期的判断，三值是命中 / 部分命中 / 落空。

**交付**：变化卡、对账卡（累计命中情况）；深度卷交底稿、一页结论和核对回执；财报季交"新数 vs 你的预期 vs 上期"的对照表。一致预期要靠终端，拿不到就标"未取到"。

**借用**：stock-sdk（命令行）、巨潮和交易所直连（Node 脚本）、liteparse、ai-berkshire 的做法和移植后的脚本、alpha-desk 的结算规则、金十 / 妙想 / iFinD 的 MCP（按同事挂载）。

**后续模板，各一句**：
- 一级市场：企查查主体确认 + summary-skill 纪要卷，事实片保留可见；
- 宏观固收：research-skills 的 data_contract 和三档阈值。

### 8.2 AI 版：先给技术经理，两个模板都带

**为什么先给技术经理**：
- 他们的核心需求全部落在"卷 + 结论 + 预检脚本"上，本机就能做：运营类变化、在用清单、决定留档和到期重审、向上解释（任务书 2.4）。
- 做 AI 研究的人最硬的需求是实验台账和夜间实验（R9、R10），得进远程 GPU 机器。我们没有任何 SSH 支持（任务书 3.3）。
- 研究者的引用核对是每篇投稿用一次的按需检查（R1 段末）。他们付费意愿接近零，对手 ARIS 免费，还跑在同一个底座上（任务书 2.3、5）。
- 首次打开问"你主要是：带团队做 AI 决定 / 做 AI 研究"，选后者就给课题模板（8.3）。两者共用核对界面，研究者模板的增量小。

**「盯我们在用的 AI」**（名字由同事自己起）：

- **常设卷「在用的 AI」**：
  - 在用清单.csv：类型（模型 / 接口 / 工具 / 框架 / 套餐）、名称、厂商、版本、用在哪个业务、负责人、账号主体、能否开票、月用量和花费、替代、状态（在用 / 试用 / 观察 / 暂停）、来源（账单 / 配置 / 你说的）；
  - 观察点.csv：对象、网址、读法、盯什么、上次哈希、上次变化、连续失败次数；
  - 结论.csv：决定行。
- **"我们在用什么"怎么让它知道**：第一次见面时拖入上月账单导出、网关配置、几个项目的 package.json。同事抽出候选行，出逐条确认卡（是 / 不是 / 改）。之后每月一条清单体检：账单里出现清单外的模型 ID，就列成候选。发现文件里有密钥时说明"只读了模型名，没有保存密钥"，并提醒不要拖真实的 .env（任务书 1：同事不能拿密码和 token）。
- **事件驱动的节奏**：
  - 每 4 小时预检，只跑脚本：models.dev 的 JSON、deprecations.info 的 RSS、厂商的定价页和更新日志、用到的框架的 GitHub Releases、OpenRouter 模型列表。
  - 变化碰到在用清单才叫模型，出影响卡（一条一件，同一更新合并，借 Dependabot / Renovate 的做法）。
  - 截止日期在 14 天以内的，立即推 IM；其余进晨报目录。
  - 每周五只有一行灰字「这周看过 31 个观察点，没有影响到你们的变化」。
  - 不出日报。依据：技术经理多数人明说不需要每天追；Simon Willison 付费档卖的是"给你发得更少"（research-keeping-up）。
- **向上解释的一页纸**，从决定行生成：

```
一句话：客服继续用 DeepSeek V4，不换 Kimi K3。要你决定的：无。
理由   在我们 40 条客服样本上：V4 82 分，K3 83 分 [我们测的 · 10/21]
       单价 K3 是 V4 的 1.3 倍 [一手价目表 · 10/21]
       两家都能对公开票 [一手]
没选   K3：分差 1 分，不值 30% 的价差 · GPT 系：国内采购没有正规渠道
代价   维持现状 ¥0；若换 K3，每月 +¥1,900，切换约 3 人日
会改主意  K3 降价超过 20% · 我们样本上的分差超过 3 分 · 下次重看 2027-01
依据   6 条（5 条已对上，1 条只有厂商说法）▸
```

  每个数后面标"我们测的 / 一手 / 厂商说"。依据：他们信自己团队跑出来的结果和一手出处，不信厂商数字和 AI 的归纳（任务书 2.4）。版式借 ADR 和 RFC，以及 Larson"高管只读开头一段"。另外有"给 CFO 的版本"：钱放第一行，不用术语。文字写得平实，因为管理者自己用 AI 写的材料被下属一眼认出会掉信任（任务书 2.4）。
- **决定的留档和到期重审**：决定行写重看条件（能机检的：价格变化超过阈值、同家族出新版本、我们样本上的分差缩小）和重看日期。触发时出变化卡「C3 到了重看条件：Kimi 发布 K3」，按钮「重看（开卷）/ 推迟到……」。新决定取代旧决定，两行互相链接。
- **在自己的任务上反复测**：卷里放 样本.csv 和评分脚本。有新候选时，问要不要跑一遍，附费用估算。结果登记成事实，标"我们测的"。用的是用户自己的各家 key。跑法借 autoresearch 的"固定评测 + TSV 台账"；工具可以用 promptfoo（Node 写的命令行，**不在本目录材料里，是我的建议，要验证**）。
- **看下属交上来的材料**：把报告拖进来，走同一条核对链，交回执："哪些有一手出处 / 哪些只是厂商说法 / 哪些查不到"（任务书 2.4 最后几条）。

### 8.3 AI 研究者模板：「课题跟踪」

- **常设卷「课题 · ……」**：文献台账.csv，列为编号、标题、arXiv、日期、和课题的关系、最像库里哪几篇、状态（新 / 已读 / 待读 / 排除及原因）。
- **例行**：工作日 09:00 预检。脚本拉 arXiv 和 papers.cool 的 feed，用 zotero-arxiv-daily 的 rerank 算法（移植成 Node，十来行），通过 zotero-mcp 读本地 Zotero 库排序。只有前 N 篇叫模型写"相关在哪"。页尾列出被排除的论文和原因（dailypaper-skills）。第一次见面问"每天看全量还是筛过的"，因为国内有研究者明说不用算法先筛，怕漏（需求报告 6.9-1）。
- **有期卷**："投稿前引用核对"（场景 3）、"相关工作查全"：交付物要写搜了哪里、还缺哪类（R2）。
- **明说不做**：实验和复现。没有远程执行，在介绍里就讲清楚。

## 14. 去掉什么

- **回话末行的"变化：有 / 无"**：改为脚本比对，或按变化卡的分组判断（3.2-3）。
- **"有用 / 没用"评价**：66 份交付物里一次都没用过。用核对标记和变化条目上的「记下 / 以后别报」代替。
- **核验印章（passed / checked / issues / notes）**：换成逐条的回执。
- **approval 和 takeover 的 24 小时自动续**：有后果的动作和登录不能被自动越过。
- **"它维护的表 = 文件夹里所有 csv"的推断**：改成卷页列出的底稿；原始抓取收进 `原始/`。
- **交付物正文存在 deliverables.json 里**：改成文件，JSON 只留索引。
- **晨报的模型散文**：改成代码生成的目录（3.2-5）。
- **每次运行自由换标签的关键数字**：由卷首的"体例"锁住（3.2-13）。
- **mywork_remember 直接追加**：改成提议。
- **保留不动**：回话先给一两句结论、文件另放；默认按假设做完；MyWork 当分诊口；本机真实浏览器加接手；跳转规则（只加"看依据跳到那一行"一条）（任务书 3.2 末段）。

## 15. 走一遍场景

### 场景 1：个人投资者，12 只票，三个月

1. **新建同事**，选模板「覆盖研究」。它问 3 问：① 把自选贴给我（他拖入一张截图，识别出 12 行）；② 你更看重长线基本面还是事件，每只票你现在的看法一句话（可以跳过，他写了 5 只）；③ 你手上有哪些数据（只有同花顺 App）。
2. **开卷卡**："覆盖 · 自选 12 只"。来源：一手是巨潮和交易所公告、定期报告，可用是金十和妙想，不用自媒体。报公告、业绩、越过你设的线、动到你的结论；不报日常涨跌。例行：交易日 07:30、21:30，周日 20:00。每月约 ¥40（估）。他写的 5 句看法成为 5 条"看法"类结论，重看条件先空着，同事建议了阈值让他确认。他点「开始」。
3. **基线**：自选.csv 12 行，公告库补近 30 天，最新季报的关键数登记成事实。卡上写"第一次：建基线，不算变化"。
4. **每天**：多数日子是一行灰字。有变化时出变化卡；动到结论的那条，他点「记下」或「改结论」。
5. **三次深度**，每次开一个有期卷，比如"恒瑞 · 三季报前深度"：先试第 1 章，确认后跑完，交底稿、一页结论和回执。他核了"最该看的 10 条"，驳回 1 条（TTM 当成了年度），出 v2，并提议一条规矩，他点「记」。合卷时 3 条结论并回常设卷，取代旧的 C1。
6. **三个月后**，他在手机或桌面问"上次对恒瑞的结论和依据"，得到结论卡：C2 现在是"动摇"，什么时候、因为哪条事实；依据三条，各自的核对状态；历史里有 C1。点「打开 v2 第 3 章」，再点 F0204，看到年报页图和高亮。

**仍然不够**：
- 电脑必须开着；
- stock-sdk 和公告接口是没有服务承诺的公开接口，挂代理会失败；
- 重看阈值要用户自己定，很多人不会定；
- 三个月下来事实表可能有几千行，现在的表格视图只读前 512KB，要加筛选和分页；
- 63% 的人只是偶尔用 AI，他会不会去核对，没有证据。

### 场景 2：买方研究员，40 页底稿，核 80 个数

1. **在覆盖同事那里**说"按我的框架给 XX 做深度底稿"，拖入框架.docx、3 份研报 PDF 和年报。对话出一行小字："收到 5 份 · 已解析 · 年报 286 页，其中 2 页是扫描件"。同事问扫描件要不要用在线 OCR（会上传），他选"跳过，标未核到"。
2. **开卷卡**（见 6.1）。他点「先试一小段」，看了第 1 章和 22 条事实，回"收入按地区拆，不按产品"。这条进了卷首口径（「记一条？」，范围选"这一卷"），继续跑。
3. **跑了 2 小时 10 分**：第 6 章那一步超时，自动重试一次成功。共花 ¥31。
4. **交付**：文件卡回执写"事实 236 · 已对上 181 · 需要你看 38 · 有问题 5 · 未核到 12"。未核到里，8 条是万得截图需要他来核，4 条是研报里的图表数字读不出来。
5. **核对**：先过"最该看的 30 条"，再按章节筛选第 4–6 章，凑够 80 条，每条 10–20 秒。他驳回 4 条：2 条把半年报当成全年，1 条万元和亿元弄混，1 条出处不支持。
6. **修正**：v2 改了 4 条事实，脚本重算了 11 个依赖它们的数，改了 3 段。他已核过的数里有 2 个变了，自动退回未看。同事提议 2 条可以机检的规矩：期间必须填，并且和正文一致；金额统一用亿元。他都点了「记」。

**仍然不够**：
- 不写他的 Excel 模型（F5：Excel 是主力工具），界面里也读不了 xlsx；
- 图表里的数字读不出（liteparse 在图表上的得分接近 0）；
- 40 页 Markdown 没有图片和脚注；
- 耗时估算没有被验证过；
- 机构的电脑可能不许装。

### 场景 3：博士生，跟课题新论文，投稿前核 60 条引用

1. **模板「课题跟踪」**，3 问：课题一句话加 Zotero 分类名；每天全量还是筛过（她选筛过，但要看到被排除的）；投稿目标（NeurIPS，截止日期）。
2. **每天**一张变化卡："3 篇直接相关"，每篇写为什么相关、最像库里哪篇；"看过 241 篇，排除 238：不在课题 201 · 与已读重复 22 · 低相关 15 ▸"。
3. **投稿前**拖入 paper.pdf 和 refs.bib，说"核一下引用"。开卷卡的步骤：
   ① 存在性和元数据：脚本依次查 arXiv、CrossRef、Semantic Scholar、DBLP；
   ② 每一处引用取上下文句和被引原文段：Zotero 本地 PDF 按页读，没入库的抓 arXiv；
   ③ 另一家模型判支持 / 弱 / 不支持 / 说不准，并引原句；
   ④ 排给她。
   60 条引用一共 85 处使用，预计 50–80 分钟、¥6–12。超过 10 条没查到就停下来问。
4. **按批次跑**，每批 10 条。引用台账.csv 每一处使用一行。
5. **回执**："已对上 48 · 元数据要改 9（已改好，见 refs-v2.bib 对比）· 需要你看 7 · 有问题 2 · 没查到 3（2 条 workshop 论文、1 条技术报告，没查到不等于不存在）"。替换和删除引用一律由她逐条决定。
6. **核对面板**：左边是她论文里的句子，右边是被引原文段和页码。她过了 12 条。

**仍然不够**：
- 判"支持与否"的仍然是模型，会误判（ICLR 2026 的误报先例）；我们只是让核对变便宜；
- 读 .tex 源文件没有实测；
- 只配了 DeepSeek 时，二审独立性弱；
- 她最大的时间黑洞（复现、实验）一点没碰；
- ARIS 免费。

### 场景 4：技术经理，关心和在用的模型、框架有关的变化；老板问"为什么不用 X"

1. **模板「盯我们在用的 AI」**：拖入账单和网关配置，确认 11 条在用；回答向谁汇报（CEO 关心是否落后，CFO 关心钱）、有哪些国内约束。这些进了关于我。
2. **平时**：只有影响卡和周五那一行灰字。8 月他让同事开过一卷"客服模型选型"，留下决定 C3："不用 Kimi K2，我们样本上低 6 分，单价 1.8 倍；重看条件：同家族出新版本"。10/02 K3 发布时出过"C3 到了重看条件"，他点了推迟。
3. **今天老板问**"为什么不用 Kimi K3"。他在手机上问同事。同事找出 C3，出一张选择卡：「先给现在能说的（约 5 分钟，2 条依据是 8 月的旧数，会标出来）」/「先在我们 40 条样本上跑 K3（约 25 分钟，¥6）」。他两个都要。
4. **4 分钟后**出一页纸 v1，旧数标"旧数 · 8/12"。22 分钟后出 v2，取代 v1，用的是新跑出的数（8.2 节的样例）。他导出 PDF 发给老板，前后共 27 分钟。

**仍然不够**：
- 没有样本集，就拿不出"我们的任务上"的数，半小时只能给公开数据，而且会明说；
- 跑对照需要候选模型的 key；
- 国内厂商的观察点靠自己维护的页面监视，页面一改版就坏；
- 这类人会不会装桌面产品，证据中等。

### 场景 5：4 位同事早上各自交了东西，他在手机上只有 5 分钟

1. **07:30–09:00**：12 次例行里 9 次在预检就结束了。09:07 晨报目录定稿，IM 推了一条："待你办 1 · 动到结论 2 · 新交付 1 · 需要你核 6"。
2. **他打开手机**，MyWork 对话顶部就是目录卡（3.3 节样例）。
3. **恒瑞 C2 → 动摇**：点进去看到变化卡的那一条，两行字加三季报 p.12 的摘录图。他点「记下」，结论改不改留到晚上在桌面做。
4. **deepseek 涨价**：点「出影响评估」。开卷卡预计 ¥3，没超过自动上限，直接开工。
5. **课题 3 篇**：扫过标题，对其中一篇点「今晚精读」，排了一条一次性例行。
6. **「抽 3 条」**：三张卡，判了对、对、不对（原因：过期了），触发修正。
7. **登录雪球**：标着"需要在电脑上"，他点「今晚 20:00 提醒我」。一共用了大约 4 分钟。

**仍然不够**：
- 没有原生推送，得先配好 IM；
- 中继在大陆手机网络下能不能连，没测过；
- 电脑必须开着；
- 手机上判断结论要不要改，信息不够，只能推迟。

### 场景 6：同事用了过期的数字，用户纠正；两周后会不会再犯

1. **变化卡**里写"XX 毛利率 38%"（F0412，2024 年报），而 2026 年中报已经是 35.2%。他点这个数字，选「不对」，原因「过期了」。
2. **修正**：取中报 p.9，登记 F0530，F0412 标"被取代"。结论 C5 复核后仍然成立，出 v2。回复下方出「记一条？」（5.2 节样例），能机检，他点「记」，成为规矩 #4，来源链接到这一轮。
3. **两周后**，另一只票的例行里，同事先登记了 2025 年报的数，而三季报已经出了。交付关口按规矩 #4 拦下，同事重新取数后才交。卡上写"规矩 #4 机检：拦下 1 处旧数，已换成三季报"。规矩面板显示"#4 · 拦下 3 次 · 上次 10/20"。
4. **如果是不能机检的规矩**（比如"用扣非口径"）：卡上写"按规矩 #6（自述）"，扣非相关的事实在核对排序里加分。

**仍然不够**：
- 要判断"最新一期"，每类对象都得有披露日期的数据源。模型价格这类没有披露日期的，只能退成"取于超过 N 天就标出"；
- 自述的规矩只是自述，不是证明；

### 场景 7：一件要跑两小时的事，用户中途想改方向

## 16. 没把握的地方

**要用户验证的**：
1. 用户愿不愿意接受"卷"这一层，宁愿一条对话一直接着说，还是每件事分开。需求报告第九节第 6 条还没有答案。这是我整套设计最大的赌注。
2. 用得浅的人（63.72%）会不会去核对。如果不核，核对界面就只服务少数重度用户。
3. 个人投资者会不会定阈值和重看条件；技术经理会不会维护样本集。
4. 早上真正会看完的，是不是晨报目录（需求报告第九节第 3 条）。
5. 技术经理的证据是中等可信，复核还在进行；他们会不会装桌面产品、会不会付费，都不知道。

**我的推断，要工程验证的**：
1. 核对的风险排序规则、自动开工上限 ¥5、撞线时 10% 余量、12 小时内自动续跑，这些数都是我定的。
2. 开工前的费用估算准不准。目前没有任何产品这样做过。
3. 模型能不能稳定地先登记事实、再按编号引用；交付关口的拒收会让成本和重做次数增加多少。
4. 在 dsh 0.1.6-alpha.2 上，每卷一个会话、每位同事同时跑两个会话，资源和压缩怎么表现；`ctx.tokenMeter` 能不能从插件里取到；按同事放 skill 和 MCP 能不能成立（kernel unknowns）。
5. 实时浏览器能不能保留文字片段和 `#page=N` 定位；liteparse 在 Windows 上和中文年报的跨页表、合并单元格上的 bbox 质量如何。
6. 只有一家模型时，二审的独立性弱到什么程度，用户会不会因此不信任回执。
7. 晨报目录虽然是 MyWork 对话里的一张卡，负责人会不会觉得它变相成了全局的"等你看"。如果会，可以退回去：只保留铃铛按原因分组，不出目录卡。

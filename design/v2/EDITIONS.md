# 一个内核，两个产品

2026-10-05。回答「AI 从业者和金融从业者这两个产品，怎么用现在的同事结构来做」。

- 它把 [design/ECOSYSTEM.md](../ECOSYSTEM.md) 的「内核 / 领域包 / 发行版」改写到同事模型上。那份文档写在同事模型之前，里面的「领域包认领输入」已经不成立。
- 依据是一次两轮的开源调研，清单见 [docs/research/2026-10-05-open-source-supply.md](../../docs/research/2026-10-05-open-source-supply.md)；三个独立方案和三份评审的原文在 [docs/research/oss-2026-10/panel/](../../docs/research/oss-2026-10/panel/)。
- 选型不看许可证，也不为合规设限：金融同事可以像热门项目那样给评分、关键价位和仓位想法。

## 0. 结论

1. **对外是两个产品，对内是一套代码。** 两个产品只在四件事上不同：第一次打开问什么、第一位同事是谁、一句话承诺、带哪些信源和做法。其余全部共用。
2. **每个产品的第一版只有 MyWork 加一位同事。** 调研里三个方案都排了 6–7 位，三位评审一致认为太宽。其余同事由 MyWork 按用户实际问过的事逐个提议，同意了才建（这个能力已经做好）。
3. **AI 版靠「你的栈」取胜**，不靠聚合新闻。现成的免费聚合（AIHOT）已经做了打分、合并和去重。别人做不了的是：你在用的模型调价或下线、你依赖的仓库发了破坏性更新、你盯的公司改了定价。
4. **金融版靠「你的票」取胜。** 第一行就说你的自选股昨晚的公告改了什么、在第几页；每只票一行结论、评分和关键位；每条观点进台账，到期按收盘价结算。
5. **先补内核，否则两个产品都发不出去。** 评审从代码和运行日志里量出来几件事（见第 6 节），比名册重要：例行越跑越贵、关窗就停、装好以后没法更新、时间表不认交易日。
6. **顺序是先 AI 版、后金融版。** AI 版的同事已经在开发环境里跑着；金融版多两个前置条件（交易日历、Windows 实机）。

## 1. 调研改变了哪些判断

| 之前以为 | 调研和复核的结果 |
|---|---|
| AI 资讯简报是空位，做聚合就有价值 | 聚合已经被免费服务做好了。空位是「跟我有关的变化」和模型价格跟踪 |
| 金融数据要靠 Python（akshare 一类） | 公告、快讯、行情、研报列表、日历用纯 Node 都能直连；Python 只在少数场景必需 |
| 要自己想办法拿金融数据 | 同花顺、万得、金十、妙想、且慢都出了官方接口，多数免费或有免费额度，用固定请求头就能接 |
| X 和公众号必须登录或付费 | 有第三方做成了免登录的 RSS（160 个 X 账号、375 个公众号），但它们是个人运营的，随时可能失效 |
| 借来的 skill 放进去就能用 | 几乎都要改：假设有子代理、自带自动安装和更新、用 Python 或 bash（Windows 上没有 bash） |
| 「没变化就不打扰」已经省钱了 | 没有。安静是模型跑完以后才判断的。开发环境 40 次例行只有 2 次安静，每次都花了完整的模型费用 |
| 多做几位同事更有价值 | 同一件事会在几份简报里各出现一次，早上几个同事同时说话，和「高信息密度」相反 |

## 2. 结构

```
产品      MyWork AI 版 · MyWork 金融版        两个安装包、两句承诺；同一个程序
版本包    ai · finance                       数据：同事模板、信源、做法、连接预设、日历
内核      MyWork Kit                         同事引擎、例行、表、浏览器、手机、IM
底座      DeepSeek Harness（dsh）            不改
```

**内核（代码，两个产品共用）**：同事、对话、文件夹、例行、记忆、交付、提问卡、MyWork 建同事、侧栏、手机网页版和中继、IM 推送、真实浏览器。要补的见第 6 节。

**版本包（数据，不是插件）**：
- 同事模板：职责、头衔、分组、头像、例行、表结构和种子行、第一件事。
- 信源行：带层级、读取方式、备用地址。
- 做法：改写过的 skill（纯文字加 Node 脚本）和简报版式。
- 连接预设：厂商接口的地址、请求头名字、去哪里领 key、额度。
- 交易日历（金融版）。

**两个产品只差四样**：

| | AI 版 | 金融版 |
|---|---|---|
| 一句话 | 你的技术栈有变化，它先告诉你 | 你的票昨晚出了什么事，它开盘前告诉你 |
| 第一次打开问什么 | 在用哪些模型和框架、依赖哪些开源项目、盯哪些公司 | 把自选股贴给我；偏短线、中线还是价值 |
| 第一位同事 | AI 早报（暂名） | 自选股早报（暂名） |
| 带的版本包 | ai | finance |

**两个包可以并存。** 建议是一个程序、两个安装包只是预设不同；装了一个以后，另一个包能在应用里添加。你自己的环境里技术雷达和财联社记者就同时在跑。这一条需要你确认（第 9 节）。

**品牌不动。** 应用叫 MyWork，默认同事 MyWork 和它的标不变。产品名只出现在安装包名、关于页和第一次打开的引导上。

## 3. AI 版

**给谁**：AI 产品经理、技术负责人、AI 投资人和分析师、做 AI 内容的人。

**对手和差别**

| 对手 | 它有什么 | 我们的差别 |
|---|---|---|
| AIHOT、follow-builders 这类免费聚合 | 打分、合并、去重都做了，免装 | 人人一份。我们把它当上游线索，自己做一手确认和「和你有什么关系」 |
| RSS 阅读器、每日 arXiv 的 GitHub Action | 自己能配信源 | 不记得你看过什么，不能追问，要自己搭 |
| 带定时功能的通用 agent 加 skill | 能定时、能推送 | 没有常驻的信源表和台账；数据不在你电脑上 |

### 第一位同事：AI 早报（暂名）

它是开发环境里技术雷达和产品雷达合并后的形态。模型、开源、产品、价格在第一版是它的几节和几张表，不是另外几位同事。

- **职责**：每天早上一份，最多 8 条。固定先写「你的栈」：关注表里的模型有没有调价、下线、出新版；依赖的仓库有没有发版，破坏性变更排最前；盯的公司有没有改更新日志或定价页。然后是必看（最多 3 条）和值得看（最多 5 条，一行一条）。
- **例行**：每天 08:00 早报；每天一次快照对比（脚本做，没变化不叫模型）；周五 17:00 用自己的情报库写一份周报。
- **它维护的表**（沿用现有中文表头，只往后加列）：
  - 关注表.csv：`类型,名称,别名,官网或仓库,更新日志地址,定价页地址,为什么关注,权重,启用`
  - 信源表.csv：现有 6 列 `类型,名称,地址或账号,关注什么,权重,启用`，后面加 `层级,读取方式,备用地址,需要,来源`
  - 情报库.csv：现有 6 列 `日期,标题,信源,链接,级别,一句话`，后面加 `事件ID,类型,信源数,一手链接,状态,已报日期`
  - 模型表.csv：`模型ID,厂商,上下文,输入价,输出价,缓存价,币种,来源,核对日期,状态`
  - 价格变更.csv：`日期,模型ID,字段,旧值,新值,一手链接,已核对`
- **每份简报的页首一行**：数据截至几点 · 读到 n 个信源里的 m 个 · 哪些没读到。
- **用到的供给**：
  - 快照对比：models.dev、OpenRouter 模型列表、厂商文档的 Markdown 版更新日志和定价页、各仓库的发版 RSS。
  - 线索：AIHOT 接口、Hacker News、GitHub Trending、官方博客 RSS、量子位和 36 氪的 RSS。
  - 做法：hermes 的「关注合同」、AIHOT 的打分和合并规则、TrendRadar 的兴趣写法。
- **用户会转告同事的那一刻**：它比我先发现我们用的模型要调价或下线。

### 之后的同事

MyWork 根据用户前一天问了什么，每天最多提议一位，同意了才建，第一周不超过 4 位。专门同事加入后，早报把那一段让出去，改成引用对方的表，专门同事早上不单独出声。

| 同事 | 做什么 | 主要供给 |
|---|---|---|
| 论文 | 按方向表筛当天论文，最多 3 篇精读 | arXiv、papers.cool；精读提纲借 PaperForge |
| 开源 | 新晋项目里和你有关的；关注仓库的版本变化 | GitHub Trending RSS、发版 RSS、Hacker News |
| 圈内 | 人物表里的人今天说了什么，共识和分歧 | X 和公众号的免登录 RSS、即刻公开页；清单外的用 OpenCLI 加用户自己的登录 |
| 竞品 | 盯约定公司的更新日志、定价页、招聘页 | 快照对比；简报格式借 competitive-brief |
| 深度研究（按需） | 一个问题查到底，带出处 | 方法借深度研究类 skill，改成一步一步做 |

## 4. 金融版

**给谁**：先按「有自选股、每天要看盘前信息的人」来做，包括研究员和认真的个人投资者。机构里的研究员多在公司管控的 Windows 上，已有万得，他们要的研报和一致预期放在第二步。这个取舍需要你确认（第 9 节）。

**对手和差别**

| 对手 | 它有什么 | 我们的差别 |
|---|---|---|
| daily_stock_analysis（6.6 万星） | 自选股仪表盘、推送到企业微信和飞书 | 它要 Python 或 GitHub Actions，只单向推送。我们双击安装，能追问「为什么 62 分」，每人一套表 |
| go-stock | 本地桌面、DeepSeek、定时、记忆、回测自己的推荐 | 形态最近。我们的差别是同事对话、手机、用户自己登录的浏览器 |
| 同花顺、万得、妙想的官方 skill 和助手 | 各自的数据 | 每家只有自己的数据，是问答工具。我们把几家拼成一份早报，它们是我们的数据层。同花顺把主力资金等最好的数据留给了自己的 AI 客户端 |
| 财联社早知道、券商晨会纪要 | 编辑写的，质量稳定 | 人人一份，不围着你的票 |

### 第一位同事：自选股早报（暂名）

- **职责**：交易日开盘前一页，两分钟读完。顺序是：
  1. 今天最要紧的一件事。
  2. 你的票昨晚的公告：改了什么、在第几页、利好还是利空、强度。
  3. 每只票一行：结论、评分、关键位，以及和昨天比变了什么。
  4. 今日日历：数据公布、解禁、财报。
  5. 隔夜外盘。
- **例行**：交易日 08:00 早报；交易日 21:30 扫当晚公告（只写表，有重大公告才出声）；周日 20:00 对账：上周每条观点按收盘价结算，给命中率。
- **它维护的表**：
  - 自选股.csv：`代码,简称,市场,分组,成本价,仓位,关注理由,支撑位,压力位,启用`
  - 公告库.csv：`公告ID,代码,简称,披露时间,类别,标题,影响,强度,一句话,PDF链接,页码,状态`
  - 观点台账.csv：`观点ID,日期,代码,方向,评分,依据,关键位,建议仓位,期限,失效条件,结算日,结算价,结果`
  - 日历.csv：`日期,时间,事件,重要度,前值,预期,实际,关联,来源`
  - 信源表.csv、情报库.csv 同 AI 版。
- **数字由脚本算，模型只解释。** 评分和关键位用固定公式（均线、前高前低、量比一类）在脚本里算出来；简报里出现的每个数字，交付前由脚本对照这次取回的原始数据核一遍。评审的结论是：靠提示词要求「别编数字」不管用，热门项目都是用脚本把关的。
- **观点台账从第一天就有。** 给了评分和价位却不结算，就和别的项目没有区别。
- **用到的供给（全部不要 key、不要 Python）**：
  - 公告：巨潮、上交所、深交所直连；正文用 liteparse 读，带页码。
  - 行情：stock-sdk（腾讯源）。
  - 日历和快讯：华尔街见闻日历、金十和华尔街见闻快讯。
  - 版式：daily_stock_analysis 的仪表盘结构、Anthropic 的晨会纪要一页纸、万得的「30 秒结论 + 表 + 失效条件」。
- **第一份不用等到明早。** 装好就出一份「此刻版」，回补最近 3 个交易日作为基线；非交易日出「过去一周加下周日历」。
- **用户会转告同事的那一刻**：我那只票昨晚的减持公告，它第一行就说了。

**第一版不做盘中盯盘。** 每 10 分钟让模型看一次，又慢又贵，专门的提醒工具做得更好。以后做也是脚本按阈值触发，模型只在触发时说话。

### 之后的同事

| 同事 | 做什么 | 主要供给 |
|---|---|---|
| 复盘 | 交易日 18:00：情绪、资金、题材、龙虎榜、龙头，给明日观察清单 | stock-sdk 的涨停池和龙虎榜；格式借 vibe-astock 和 daily_stock_analysis |
| 快讯 | 五家快讯按事件合并，分三档 | 发布方直连接口（已有的财联社记者） |

| 宏观 | 今日日历；数据公布后给实际、预期、前值 | 华尔街见闻日历、中国货币网；可选金十 |

### 接上会更好

第一份简报之后，按增益一次只推荐一项：
1. 金十（免费，登录后点一下）：快讯全文和财经日历更稳。
2. 同花顺（内测期免费，App 扫码）：涨停梯队、龙虎榜、异动原因。
3. 妙想（免费，每天 150 次）：搜公告、研报、政策。
4. 万得（每天 300 积分）：公告和新闻、宏观数据库。
5. Python 数据包（一键启用）：akshare 等更全的数据。

## 5. 版本包长什么样

随安装包带，首次启动复制到用户目录。先不做成单独分发的包。

```
editions/<id>/
  edition.json            名字、第一位同事、第一次打开问什么、默认晨报
  mates/<同事>/
    mate.json             名字、头衔、分组、头像、例行、要用的 skill、可选的连接
    duty.md               职责（就是它的指令，2000 字以内）
    seed/*.csv            表头和种子行（默认信源）
    formats/*.md          简报版式
  skills/<名字>/          SKILL.md 加 scripts/*.mjs（只用 Node）
  connectors/*.json       厂商接口预设：地址、请求头、去哪里领 key、额度、测试调用
  calendar/               交易日历
```

几条约束，都来自评审：
- **例行的时间用结构化写法**，不靠一句话去解析。
- **脚本一律是 Node 文件。** Windows 上没有 bash；借来的 skill 里的 Python 和 bash 写法都要改。
- **第一位同事自给自足**，不依赖还没上岗的同事的表。
- **表头保持中文**，只往后加列。表是给人在手机上看的。
- **人改的表和脚本写的表分开。** 信源表由人和同事改；信源状态（上次成功、连续失败、原因）另放一张表，只由脚本写。现在同事自己维护的表已经出现格式漂移。

## 6. 内核要补的

按先后排。「依据」一栏是评审从代码和日志里查到、我又抽查确认过的。

| # | 补什么 | 依据 |
|---|---|---|
| 1 | **v2 安装包，带版本预设**，并在真实 Windows 上走通 | 现在的安装包还是第一版；Windows 包从没在实机上跑过；体积 680–860 MB |
| 2 | **常驻**：托盘、开机自启、到点不休眠；过期的例行按规则处理（盘前过了就不补，其余补发并排好先后） | 现在关掉窗口程序就退出；错过的例行开机后一起排队，早报到手可能已经开盘 |
| 3 | **能更新**：装新版后内核和版本包真的生效；信源行、站点脚本、交易日历能单独热修 | 现在只在第一次启动时复制一次模板；财联社签名这类东西说变就变，没有通道就得让用户重装 |
| 4 | **例行认交易日**：结构化时间、交易日历、盘中时段 | 实测「交易日 07:30」解析不出来；「周日 20:00」被当成一次性；调度只往后找 8 天，交易日判断写得不小心，长假会把例行停掉 |
| 5 | **例行先跑脚本，没变化不叫模型；例行不在那条永久对话里越滚越大** | 实测一位同事 3 天 13 轮，单步上下文从 2.4 万涨到 20 万 token，没有压缩；40 次例行只有 2 次安静，且安静不省钱 |
| 6 | **按模板建同事，加第一次打开的引导卡** | 现在只能从一句话建；自我介绍和例行运行里不能提问、不能建同事，引导不能走模型提问这条路 |
| 7 | **按同事裁工具** | 现在每一步固定带 94 个工具的说明，约 2.4 万 token；工具表一变，所有同事的缓存全部失效。dsh 有按同事限制工具的原生手段，还没验证 |
| 8 | **覆盖行和信源状态表** | 「没读到」和「没有新消息」现在分不开 |
| 9 | **数字核对脚本**：交付前对照本次取数核对 | 现在只有模型核验，默认还是关的 |
| 10 | **连接预设和密钥**：领 key 的引导、测试调用、额度提示 | 同花顺的接口 key 错了也返回成功，必须真调一次才知道 |
| 11 | **分域名走代理或直连** | 开发环境里实际出过事：挂着代理时小红书触发风控，不挂时 X 打不开 |
| 12 | **运行记录不挤掉对话** | 运行记录上限 2000 条，超了丢最旧的，也就是对话历史 |
| 13 | **可选的 Python 环境**（uv 管理，放在应用自己的目录里） | 见供给清单的「运行环境」 |
| 14 | **同事导出和导入**（不带对话、记忆、密钥） | 模板分享是之后的增长手段 |

另有一件不属于内核但会卡住后面的事：**dsh 锁定的版本落后三代**，生态里活跃的插件已经要求更高版本。什么时候升级需要排期。

## 7. 可靠性

- **信源分层，最脆的一层缺了简报也要完整。** 从稳到脆：官方一手和交易所 → 用户自己的厂商 key → 公开直连接口 → 第三方聚合 → 个人运营的桥和登录态。个人运营的桥在信源表里同时存账号本身，坏了能换。
- **失败不等于没有新闻。** 每份简报页首写覆盖情况。
- **聚合站只能提名**，报出去要有一手链接；拿不到一手页（比如没有代理）就标「未核对一手」。
- **送达不只靠手机中继。** 晨报默认同时走 IM（飞书、微信推送已经有了）。中继在 workers.dev 上，大陆手机网络能不能连还没有实测。
- **有人每天检查。** 每天在一条大陆线路上把默认信源全跑一遍，坏了当天走热修通道。
- **第三方 skill 只带改写过的一小份。** 去掉自动安装和自动更新的步骤。这不是合规，是因为公开市场里的 skill 有相当比例带恶意代码，金融类被仿冒得最多。
- **花钱或对外的动作照旧先问**：付费接口、往群里推送、下单，都走现有的批准卡。观点、评分、价位、仓位想法照常给。

## 8. 节奏

卡时间的不是写代码，是真机测试和真人试用。

| 阶段 | 做到哪 | 过关标准 |
|---|---|---|
| 0. 能装、准时、不贵 | 内核 1–6：v2 安装包、常驻、能更新、交易日历、脚本先行、模板和引导卡 | 一台干净机器上，从安装到第一份简报不超过 10 分钟 |
| 1. AI 版第一位同事 | AI 早报，加内核 7–8 | 5 个真实用户连续 5 个工作日按时收到 |
| 2. 金融版第一位同事 | 自选股早报和观点台账，加内核 9–10；真实 Windows 验证 | 5 个真实用户连续 5 个交易日按时收到 |
| 3. 第二位同事和连接 | 按提议节奏上第二、三位；金十和同花顺的连接；周报 | 第二周还在用的比例 |
| 4. 传播 | 同事导出导入；可选的 Python 包；按试用结果决定后面的同事 | — |

两条退路，来自三个方案的共识：
- 如果试用下来用户只留下一位同事，就把名册和模板体系收小，两个产品收成「一位同事加可选信源包」。
- 如果大陆不挂代理时默认信源可用不到七成，AI 版要先解决信源托管，再谈名册。

## 9. 要你定的事

1. **一个程序还是两个程序？** 建议一个程序、两个安装包只是预设不同，装了一个以后另一个包能在应用里加。另一种是两个完全独立的应用，各有各的数据目录。
2. **金融版先给谁？** 建议先做「有自选股的人」（自选股早报、复盘），机构研究员要的研报和一致预期放第二步。
3. **「准时」怎么定义？** 允许应用开机自启、在简报时刻阻止休眠吗？不允许的话，对外只能承诺「开机后几分钟内」。
4. **早上谁说话？** 建议只有一位领域同事时由它出早报；有两位以上时由 MyWork 的晨报合并，其余同事早上只写表。这需要版本包能调整 MyWork 默认晨报的时间和内容（名字和标不动）。
5. **更新从哪里下？** 信源行、站点脚本、交易日历需要一个热修通道。没有自有域名的前提下，可选 GitHub Releases、Gitee 或 npm 国内镜像。应用可以自动拉取吗？
6. **测试资源你来提供？** 一条不挂代理的大陆线路、一台 Windows 机器、每个产品 5 个试用的人。
7. **dsh 什么时候升级？** 继续锁在 0.1.6，还是排一次升级到 0.2。
8. **名字。** 两个产品的后缀名（AI 版、金融版还是别的），以及两位第一同事的名字。

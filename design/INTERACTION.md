# 交易工作台 · 定位与交互逻辑

配合 [POSITIONING.md](POSITIONING.md)（立意与 v2 形态）读。那份回答「它是什么」，这份回答「为什么是这个定位」和「用户怎么用它」。

## 1. 定位与立意

### 一句话

**你的市场研究员：只看交易数据，给出概率，敢被复盘。**

### 为什么是研究员，不是助手

助手替你做事，研究员替你判断。个人交易者缺的不是又一个能聊天的东西，是一个不带情绪、不讲故事、每个结论都能被打分的判断来源。研究员这个身份决定了三条：

- 它的产出是**报告**，不是回复。报告有结论、概率、时间窗口、依据、来源，能被存档和对照。
- 它**不执行**。研究员不下单，也不该有下单按钮。执行是用户的事，这条边界让它永远站在用户这边。
- 它**接受评价**。每份报告事后标对错，同一问题的概率连成历史。愿意被打分，是研究员和网红的区别。

### 立意的根

市场里的噪音顺着情绪走，只有价格是被真金白银投过票的。所以它只用交易数据：预测市场、期权、国债曲线、机构持仓、内部人交易、资金流。不引用新闻和观点，不是清高，是因为那些东西已经在价格里了。

### 为什么现在能做

三件事同时成立了：agent 能自己取数、交叉、写结构化报告；十三个数据源全部免费无 key；模型便宜到可以再跑一遍核验。两年前这是一个团队的活，现在是一台笔记本的活。

### 用户与三个时刻

有持仓、有想法、没有研究团队的个人投资者，同时看 A 股、美股、商品、加密。一天三次：

| 时刻 | 他想知道 | 产品的动作 |
|------|----------|-----------|
| 盘前 | 隔夜有什么变了，我的仓有没有事 | 先于他开工：简报已经在飞书里，打开首页第一屏是变化 |
| 盘中 | 这只 / 这件事到底怎么看 | 一句话下任务，几分钟后一份报告 |
| 盘后 | 我上次的判断对不对 | 催他给报告打分，胜率自己长出来 |

### 不做什么

不画 K 线（行情软件的事），不推新闻（资讯的事），不荐股，不下单，不接券商。每一条都会让它更像别的东西，而不是更像研究员。

### 北极星

被验证过的报告数，以及验证后的胜率。报告写得多不算数，被打分并且对的多才算数。这个指标只有研究员形态能长出来，聊天形态长不出来。

## 2. 交互逻辑

### 四个对象

用户只需要认识四个词：**标的**（他关心的东西）、**任务**（他提的问题或点的标的）、**报告**（任务的交付物）、**简报**（每天自动的那份报告）。持仓和自选是标的的属性；巡检是简报的开关；市场先知、dsh、模型、会话都不出现。

### 一条主线

```
输入 ──▶ 任务（后台跑）──▶ 通知 ──▶ 报告（页面）──▶ 打分 ──▶ 下一次输入自带历史
                 ▲                                              │
                 └──────────── 简报（每天自动生成一个任务）◀────┘
```

所有交互都在这条线上。任何一个按钮，最终都是「创建任务」或「打开报告」。

### 八条原则

1. **一句话即任务。** 输入框里的一句话、标的行上的「研究」、简报里的「深入」，都创建一个任务。没有第二种发起方式，也没有需要先填的表单。
2. **任务是异步的。** 创建后立刻返回一张任务卡：排队、取数、推理、核验、完成，每步有耗时。用户可以离开；完成时应用内和飞书各通知一次，不多。
3. **交付物是页面，过程可展开。** 报告页是一份文档：结论与概率在最上，然后信号表、矛盾、场景、阈值、来源、核验。对话原文折叠在最下面，叫「过程」，给想追究的人。
4. **数据自带，不用复述。** 任务创建时系统附上当前市场状态、这只标的的报价与持仓、同题的上一份报告。用户只说问题。
5. **每个数字能点开来源。** 报告里的数值链接到取数记录：哪个数据源、什么时间、原始值。核验徽章「已核验 n/n」说明有多少数字对上了工具返回。
6. **系统先于用户。** 简报每天先到；两周没打分的报告会被催；标的行上显示上一份报告的概率，让「再问一次」有对照。用户大多数时候是在回应，不是在发起。
7. **不打断。** 没有弹窗，没有「选模型」「选工作区」「选模式」。模型档位按任务类型自动定：快问用轻档，报告用重档。数据源失败时报告里标注「缺失维度」，不假装完整，也不弹错误框。
8. **一切可复盘。** 报告有对 / 错，同题历史一条线，胜率在报告页顶上。判断留下来，才有第二次。

### 状态与通知

- 任务状态只有五个：排队、取数、推理、核验、完成（失败归入完成并标明原因）。状态点用形状加颜色，不只靠颜色。
- 通知只在两种情况：任务完成、简报生成。进行中的任务不通知，进度在卡片上看。
- 简报每天一次；阈值告警（价格、信号）触发即推，同一阈值一天最多一次。

### 每个界面在主线上的位置

| 界面 | 主线上的角色 | 上面只有什么 |
|------|-------------|-------------|
| 今日 | 输入与回应 | 一句市场状态、输入框、今天的简报、进行中的任务、我的标的 |
| 任务 | 进行中与历史 | 任务卡列表，每条一句结果 |
| 报告 | 交付物 | 报告列表与报告页；筛选、同题历史、打分 |
| 持仓 | 标的的管理 | 自选与持仓一张表，每行「研究」 |
| 设置 | 一次性的事 | 通知账号、涨跌配色、风格、数据源状态 |

### 三个微交互

- **输入框**接受三种东西：一个问题、一只标的的名字或代码、一条模板。回车即任务；框下的芯片只是把话填好。
- **任务卡**在完成的一刻从「步骤名 + 耗时」变成「概率 + 一句结论」，同一张卡，不跳页。点开才是报告。
- **报告页**右上四个动作：对 / 错、再问一次（带着这份报告开新任务）、导出（图片或 PDF）、过程。没有第五个。

### 衡量交互对不对

- 从提问到报告，用户是否可以离开。是。
- 完成一次分析要点几次。最多两次：一次输入，一次打开报告。
- 报告的结论能否在三十秒内读完。能，因为它在最上面。
- 用户需要认识几个名词。四个。

# 代码研究的规矩

照 Simon Willison 的 research 仓库：每个问题一个文件夹，边做边记，最后写报告；没经人审的都是草稿。

## 一个问题怎么做

1. 新建文件夹 `YYYY-MM-DD-短名/`（短名用英文小写和连字符，例如 2026-10-05-markdown-libs）。
2. 边做边往 `notes.md` 追加：试了什么、命令、输出的关键几行、踩的坑。
3. 跑出结果后写 `README.md`：
   ```
   # 问题（一句话）

   > 未经你审

   ## 结论
   两三句。

   ## 怎么验证的
   跑了哪些命令、在什么机器上、关键输出（贴几行）、图在哪。

   ## 没验证的和局限
   ```
4. 代码、脚本、数据、图都放在这个文件夹里；只留自己写的代码和改动，别把别人的整个仓库拷进来（clone 到 /tmp 或文件夹里的 .work/，报告里写版本号）。

## 只认跑出来的

- 每条结论都要能对上一条跑过的命令和输出。
- 跑通能证明「可行」，没跑通证明不了「不可行」：写清卡在哪。
- 数字要写在什么机器、什么版本上测的。

## 未经你审

- 用户打开报告点「审过了」，程序把「> 未经你审」改成「> 审过：日期」。你不要自己改这一行。
- 引用或转述没审过的报告时说明「这份还没审」。

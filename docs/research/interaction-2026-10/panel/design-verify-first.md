# MyWork 交互设计：从核对出发

2026-10-05 · 交互设计方案之一

## 核心主张

1. 能不能把活交给同事，要看核对是否明显比自己重做便宜〔B§2.1〕。所以同事交回来的每个数字、每段引文，都先记成一条「事实」，带出处快照、页码或位置和取得时间。成稿只引用事实的编号。核对的单位是一条事实，不是一份文件。
2. 核对分三层，从便宜到贵：
   - 程序先核：字面对得上、复算一致、时点没过期、文献真的存在。
   - 换一家模型只挑错，从不说「通过」。
   - 人只看程序按风险排出来的「先看这几处」，一般不超过 7 处。
3. 你点的「对 / 不对」记在事实上，换一份成稿也继续有效。来源一变，这条自动退回「未核」。所以每天要你核的只有新的和变了的。
4. 点一次「这条不对」，同时发生三件事：
   - 改这条事实，引用它的底稿和成稿跟着出新版本。
   - 这次错误记在这条事实上，下次排在最前面，挑错方也会知道。
   - 提议一条规则。你点头才生效，能由程序检查的部分由程序执行。
5. 只新加四样东西：事实、判断（你的看法和它的检验条件）、规则、计划（超过一轮的活）。都是同事文件夹里的文件。基本单位还是同事和它的那一条对话。
6. 其余功能都接在这套东西上：
   - 例行只报「哪些事实变了、碰到了哪条判断」。有没有变化由程序判断，没变化也留一行能点开。
   - 只有你能解决的事，是事实的一种状态（打不开 · 需要登录），几位同事碰到同一件事时合成一条，进「需要你」。
   - 长任务的第一站，永远是先给你核 5 条样本。
   - 找回从判断进去，依据是当时存下的出处快照。
   - 手机上做的是一条条核、一条条认。
   - 费用按每轮、每条例行、每次挑错分别记账。
7. 停下来等你的门只有五处：改你的判断、规则进长期、替换你核过的内容、超预算、对外动作。其他事默认做完，事后可以核。

**依据标注**：〔B§x〕任务书章节；〔断点 n〕任务书 3.2 的第 n 条；〔P n〕understand-patterns 第 n 条做法；〔反〕任务书 4.2 不该做的；〔空位〕任务书 4.3；〔评估〕evaluate-our-current-form.json；〔内核〕understand-kernel.json；〔需求 F1/R1/V4〕user-needs 报告的需求编号；〔技经·文件·n〕research-*.json 里 needs 的第 n 条；项目名照写。〔推断〕表示没有直接证据。

## 1. 对象模型

### 1.1 不变的部分

一位同事 = 一条对话 + 自己的文件夹 + 例行 + 记忆 + 本机浏览器〔B§1〕。新加的四样东西都放在它的文件夹里，在对话里以卡片出现，在右栏以列表出现。没有任务页，也没有跨同事的看板。

### 1.2 文件夹布局

```
mates/<id>/
  AGENTS.md        「## 规则」一节 + 原有内容；dsh 每轮载入
  资料/             你给它的文件（PDF、xlsx、.bib、.tex），旁边是解析结果 *.parse.json
  底稿/             它维护的表（csv，中文表头）＝现在的「它维护的表」
  成稿/             交付物正文 <id>.md，头部写：版本、取代谁、引用了哪些事实
  底账/
    事实.jsonl      一条事实一行；改动是追加新版本，不覆盖
    判断.jsonl      你的判断和检验条件
    纠正.jsonl      每一次「不对」（只追加）
    检查.json       规则里能由程序检查的部分
    待定.jsonl      它提议、你还没点头的规则和判断改动（不载入）
  出处/             来源快照 <hash>.txt + .meta.json（网址或文件、取得时间、页码映射）
  计划/             超过一轮的活，一件一个 .md
  .cache/           原始抓取，7 天清理，界面上不列
```

〔据：断点 10，技术雷达 101 个文件里 99 个是原始抓取；P23 一事一文件；finance crossCutting 14「记忆全部在文件里」〕

### 1.3 七样东西

| 东西 | 新/旧 | 存在哪 | 界面在哪 | 生命周期 |
|---|---|---|---|---|
| 资料 | 旧，补上入口 | 资料/ | 拖进对话框；右栏「电脑 → 文件夹 → 资料」 | 放进来就解析出页码和坐标；不自动删 |
| 事实 | 新 | 底账/事实.jsonl + 出处/ | 成稿里的编号；阅读视图的核对条；右栏「底账」表；搜索 | 同事写入 → 程序核 → 你核 → 被纠正或来源更新时出新版本；旧版本保留 |
| 判断 | 新 | 底账/判断.jsonl | 右栏「资料」里的「判断」一栏；详情在中栏 | 同事起草、你认了才算数；例行盯它的检验条件；状态只有你能改 |
| 规则 | 新，取代「它记住的」 | AGENTS.md「## 规则」+ 检查.json | 右栏「资料」里的「规则」一栏 | 你说的直接进；它提议的要你点头；可以停用 |
| 计划 | 新 | 计划/*.md | 对话里一张原地更新的计划卡；右栏「在做的」 | 开工前出 → 分段跑 → 交付后归档 |
| 成稿 | 旧，换存法 | 成稿/<id>.md | 文件卡、阅读视图、文件页 | 每改一次出一个新版本，旧版标「已被取代」 |
| 底稿 | 旧 | 底稿/*.csv | 右栏「它维护的表」 | 原地更新，变了的行可以看前值；「出处」列写事实编号 |

### 1.4 事实

一条事实就是一个能拿去对出处、或能用程序复算的东西。字段如下：

- 编号：F0412。跨同事引用写成「同事名:F0412」。
- 键：主体 / 指标 / 期间或时点 / 口径。例：宁德时代 / 营业收入 / 2026Q3 / 合并。同一个键出新值，就是同一条事实的新版本；换了期间，就是另一条事实。只报变化、纠正挂在哪、核对能不能继承，都靠这个键〔天风事实包七字段；叶青 evidence_index〕。
- 值、单位、所属日期（asOf）。
- 类型，只有三种：
  - 原文：出处里写着的。
  - 计算：程序用别的事实算出来的，记着公式和输入事实的编号。
  - 自测：我们自己跑出来的结果，附脚本和输出。
- 出处：快照编号、位置（PDF 的页码和坐标，或网页段落，或接口字段）、不超过 300 字的摘录、取得时间。
- 机器状态、人的状态、纠正记录、被谁引用（程序维护的索引）。

估算和推断不算事实。它们是成稿里的句子，句末标〔估〕或〔推〕，后面跟着它依赖的事实编号〔P3「写的人只许引用事实编号」；B§2.1「分清事实、估算和推断」〕。

所有界面上的状态只用下面这些词：

| 谁给的 | 词 |
|---|---|
| 程序（原文） | 对上 · 对不上 · 没查到 · 打不开 · 没去查 |
| 程序（计算） | 复算一致 · 复算不一致 |
| 程序（规则） | 过期 · 违反规则 Rn |
| 挑错方（推断句） | 支持 · 弱 · 不支持 · 拿不准 |
| 人 | 未核 · 你核过 · 你改过 |

「没查到」永远不写成「不存在」〔需求 6.9-5；hallucinator 的文案；反：把没查到写成不存在〕。

### 1.5 判断

判断是你的看法，加上「什么情况下它可能错」。字段：

- 主体
- 一到三句话
- 依据（事实编号）
- 检验条件，四种：
  - 到期结算：方向 / 阈值 / 期限，由代码按收盘价判。
  - 指标门槛：指标 / 比较 / 值 / 数据从哪里取 / 检验日。
  - 事件：某类事实出现，比如「这个型号出现下线公告」。
  - 日期：到某天重新看。
- 触发后做什么：只告诉我 / 让它查一遍 / 起草状态变更。
- 状态：有效 · 存疑 · 失效 · 撤回 · 被取代。

技术经理的「决定」就是判断的一种，另外加「选项和不选的理由」。个股论点、选型决定、可结算的预测，都用这一个东西〔ai-berkshire 论点文件与卖出条件；dsh-alpha-desk；ADR；finance crossCutting 13「判断要能结算，必须在下判断时就写成结构」〕。

### 1.6 规则

规则是这位同事做事的规矩，偏好也算在里面。每条记：

- 文本
- 来源：你说的 / 来自对 Fxxx 的纠正 / 它提议你同意的
- 程序能不能检查：机查 / 靠它自觉
- 用到几次、上次什么时候、被违反几次、是否启用

### 1.7 计划

计划记这些：要回答的问题、来源分级、会交什么、做到什么算完、在哪些情况下停下来问你、预算、步骤和各自的状态、已经花了多少、每一段的记录。

### 1.8 哪些不是新东西

- 核对：是一个动作和一个视图。
- 变化：是事实前后两版的差。
- 今天先看：MyWork 现有晨报换成的一张卡。
- 需要你：铃铛里已有。
- 挑错方：后台机制，不是同事。

### 1.9 为什么现有的不够

- **事实**：现在交付物是一整块 Markdown，数字和出处配不上对。财联社记者每份简报中位 48.5 个数字、1 个链接。核验员看不到工具返回的内容，只能给整份文件一个结论〔断点 1；评估 realUse 5、9〕。所有认真的金融流程都先落中间底稿再写成稿〔finance crossCutting 1〕。没有事实这一层，核对没有落点，纠正也没有地方记〔空位〕。
- **判断**：例行要报「相对我的框架变了什么」〔需求 F9、F12〕，技术经理要决定的依据留得住、到期能重审〔技经·decisions·6、10〕。现在没有地方放「我的框架」，只能让模型从全局 4 行「关于我」去猜〔评估 走查 4〕。
- **规则**：7 天 7 位同事只记了 3 行，全是偏好，没有一条来自纠正。记忆写入也没人审〔断点 6；内核 memory〕。
- **计划**：单轮最长 20 分钟，超时就失败，没有检查点〔断点 7〕。

## 2. 第一次见面

### 2.1 入口

点「+」新同事，右栏表单顶部多一排模板：金融版是「覆盖与判断」，AI 版是「文献与引用」和「在用与变化」。下面照旧可以只写一句「它负责什么」。MyWork 分诊时也可以提议用某个模板〔评估 strengths 6〕。

### 2.2 上岗：三张卡

现在的自我介绍一轮不能提问〔内核：introPrompt，engine.js:174〕。改成：模板里写好「上岗卡」，引擎直接把它画成一种新卡片，照新同事卡的样板做〔内核 cheapExtensions 1〕。它不走 mywork_ask，不占每轮 2 次提问的名额。没有模板时，同事在自我介绍里起草这三张卡的内容，卡照样出现。

- **卡 1「它管什么」**：
  - 个人投资者贴「宁德 比亚迪 平安……」。同事用 stock-sdk 查代码，唯一命中的直接锁定，有歧义的给最多 5 个候选让你点。锁定后只用代码，不再用名字〔企查查的主体确认交互；finance crossCutting 16〕。
  - 技术经理粘贴或导入「在用清单」。
  - 博士生写一句课题，加正词、负词，可以再选一个 Zotero 分类。
- **卡 2「从哪取、多严」**：
  - 来源分三级：一手 / 可用 / 不用。模板给默认值，点一下就能改〔P9〕。
  - 核对要求：金融默认「财务数字要两个来源，相差超过 1% 标出来」〔ai-berkshire financial-data.md〕；AI 研究默认「引用逐条核」。
  - 每月预算和单次上限〔P24〕。
- **卡 3「什么时候干活」**：时间用结构化的写法（交易日 21:30、每月 1 日、财报日），不再靠解析一句话〔内核 routines：实测「交易日 07:30」解析不出来〕。每条例行一行：做什么 · 什么时候 · 没变化时怎样。
- **可选的卡 4「你现在怎么看」**：每个主体写一句判断，可以全部跳过。跳过的，等第一次有相关公告时同事在回话里提一句，不弹找你卡〔推断：写判断是一道门槛，见第 16 节〕。

### 2.3 开工前你确认什么

只确认四样：覆盖清单、来源级别、例行时间、预算。列名、脚本、表结构由模板定，不问你〔反：到处加强制确认〕。确认就是点卡片底部的「就这样开始」，以后都能在右栏改。

### 2.4 试一次（10 分钟内）

确认后马上跑一份「此刻版」：一份小成稿，含 5–10 条事实。

- 金融：最近 3 个交易日的公告。
- 技术经理：在用清单里每个模型的现价和下线状态。
- 博士生：最近 3 天课题新论文的前 5 篇。

打开时核对条已经亮着：「先看 3 处 · 点数字看出处」。这是教用户用核对的唯一一课〔EDITIONS「第一份不用等到明早」；推断：第一份东西就让人点到出处〕。

## 3. 日常节奏

### 3.1 例行到点

1. **先跑脚本，不叫模型**：按来源表取新内容（公告列表、定价页、更新日志、arXiv 列表），和上次的出处快照比哈希〔B§3.3「例行先跑脚本、没变化不叫模型」〕。
2. **没有新内容**：不叫模型，照 3.2 处理。
3. **有新内容**：叫模型，只给它变了的来源、相关的事实和判断。它写新事实或新版本。
4. **能用代码算的检验条件由程序判**：价格、阈值、日期、某类公告出现〔P5、P16；鸣山「由代码裁决，不允许模型自评」〕。
5. **交付**：回话 1–3 行 + 一张文件卡。

### 3.2 「没有变化」怎么处理

- **由程序判断**：这一轮没有新事实、没有事实的值变化、没有碰到判断，才算没有变化。不再看回话最后一行有没有写「变化：无」〔断点 3〕。
- **第一次运行永远不算没有变化**，它是在建基线〔评估 realUse 7：产品雷达第一次的日报被误藏〕。
- **没有变化也留一行居中小字**：不亮未读、不弹 toast、不推送。例如：「例行 · 晚间公告 · 没有碰到判断的变化 · 查了 37 份 · 打不开 0」。
  - 连续几次没变化合成一行：「近 4 次没有变化」。
  - 点开能看到查了什么。如果有交付物，照常进文件页，标「没有变化」。被藏的东西不再找不到〔断点 3〕。
- **打不开不等于没有变化**：「打不开 2」单独列出，点开看是哪两个、为什么〔EDITIONS 内核第 8 条〕。

### 3.3 有变化时对话里出现什么

回话先说碰到判断的，再报其余的数量：

> 宁德时代三季报：毛利率 21.3%〔F0412〕，低于你判断 J3 的门槛 22%。另外 2 份公告与你的判断无关。

文件卡从上到下：

```
晚间公告 · 10/29
碰到判断 1 · 新变化 3 · 重复 2 · 筛掉 9
待你核 2 · 打不开 0 · 挑错中
21:34 · 打开
```

卡上原来由模型自己起名的「关键数字」，换成固定的状态计数，因为那些标签每天都在换〔断点 13：财联社 4 次运行 4 组标签〕。模板可以另外固定 2–3 个标签。点「筛掉 9」能看到每条为什么被筛：重复了哪条，或者按哪条规则算噪音〔P11；dailypaper-skills 在页尾列出被排除的〕。

### 3.4 只有你能解决的事

- **例行里遇到登录、扫码、缺资料**：同事调用一个新工具 mywork_flag。它不打断这一轮，只把这件事挂进「需要你」，这一轮照常把能做的做完〔断点 2；内核：例行运行不能 ask〕。
- **它本质上是事实的一种状态**，例如「打不开 · x.com 需要登录」。同一个站点、同一个账号被几位同事碰到，合成一条：「x.com 需要登录 · 卡住 技术雷达、产品雷达」〔断点 12〕。
- **你点「去处理」**：右栏电脑页打开那个站，可以接手。你点「我登好了」：被卡住的几位同事只重取那几个来源，不整轮重跑。
- **挂起的事不写进报告正文**，所以不会出现「X 登录」连续 4 天出现在报告里〔评估 realUse 8〕。3 天没处理的，改成每周提醒一次。

### 3.5 「需要你」

铃铛里三组照旧：需要你 / 在干活 / 刚完成〔评估 strengths 9〕。「需要你」里每条写明原因，按这个顺序排：

1. 判断触发
2. 有截止的事（比如某型号 10/12 下线）
3. 待你核：只收被结论或判断依据用到、程序又没对上的
4. 只有你能做：登录、给资料
5. 问你（找你卡）
6. 计划检查点、超预算
7. 失败

另有一行「提议 n」（规则提议、判断改动提议），不计数，不亮红点。

每条都有三个动作：处理 · 稍后（明早再出现）· 这类以后别叫我（只对例行来的条目有，会写成这条例行的一条规则）〔P15〕。

### 3.6 多位同事早上一起交东西

MyWork 默认的晨报不再写综述，改成一张「今天先看」卡：

- 程序从所有同事的「需要你」里取第 1–4 类，按上面的顺序排，最多 7 行。
- 最后一行是数量：「其余：变化 11 条不需要你 · 待核 9 处不在结论里」。
- 点任何一行，跳到那位同事对话里的那一条，跳转规则不变。
- 卡在 08:40 出，到中午之前原地更新（「9:02 更新 +1」），9 点才交东西的同事也算在里面〔断点 5〕。
- MyWork 最多加一句话，而且只能引用卡上的条目，因为现在的晨报会说素材里没有的话〔评估 realUse 9〕。

MyWork 的名字和标不变，也没有给它新角色，只是它现有的晨报换了做法〔B§1〕。

### 3.7 手机上 5 分钟

手机首页顶部就是「今天先看」，一条一屏，每屏一个决定。详见第 11 节和场景 15.5。

## 4. 核对

### 4.1 写的时候就可核

1. 同事取到一个来源，先存快照（新工具 mywork_source）：网页存正文文本，PDF 用 liteparse 存每页的文本和坐标，得到一个出处编号〔P1；liteparse〕。
2. 再写事实（新工具 mywork_fact，可以批量），每条必须挂出处和位置。计算类事实写公式和输入事实的编号。
3. 成稿里，陈述事实的数字后面跟编号，比如「营收 1,032 亿元〔F0412〕」。估算句标〔估〕并写出假设，推断句标〔推〕并跟上依据的编号。
4. 所有交付都经过 engine.deliver〔内核 cheapExtensions 4〕，程序在这里检查两件事：
   - 正文里带单位的数字有没有编号或〔估〕。没绑的超过两成，第一次退回并列出是哪几行，让它补；第二次照收，剩下的进「没核到」。年份、日期、序号、文件编号不算数字（ai-berkshire 的 issue 79 曾把「2026」「10-K」误当成数据）。
   - 编号对应的值和正文里写的值是否一致。不一致直接退回：这是笔误，不该留给人去发现。

### 4.2 程序先核

四项检查全是确定性代码，结果写进事实的机器状态：

| 核什么 | 怎么核 | 借谁 | 状态 |
|---|---|---|---|
| 字面 | 值和引文能在绑定的快照片段里找到（单位和千分位先归一） | PerryLink dsh-research-verify 的规则 | 对上 / 对不上 / 没查到 |
| 复算 | 计算类事实用十进制重算 | ai-berkshire financial_rigor，移植到 Node | 复算一致 / 不一致 |
| 时点 | 事实的所属日期对比规则里的时效；正文写「最新」「本周」而事实比窗口旧 | 天风审查的「时点」项；2026-06 地产周报把旧政策标成新政策的事故 | 过期 |
| 存在 | 文献查 arXiv、CrossRef、Semantic Scholar；主体查信用代码 | ARIS verify_papers、refchecker；企查查 | 对上 / 作者不符 / 没查到 / 查询失败 |

### 4.3 独立的第二方先挑错

- **是谁**：后台一次只读会话，由现在的核验机制改造。用户在设置里选「挑错用的模型」。
  - 默认建议另一家：执行方是 DeepSeek 时用 Kimi 或 Qwen，按 ARIS 的家族表算异家族。
  - 没有第二家的 key：用同一家模型、全新会话、只给文件，卡上写明「同一家模型挑的，独立性有限」〔P8；反：同一个模型审自己〕。
  - 代码上，verify() 本来就把 selection 传给 openSession（engine.js:617），改成读设置里的另一家即可。
- **给它什么**：只给文件路径，包括成稿、事实账、出处快照目录、你的原话和规则、这位同事近 30 天的纠正记录。不给同事的自述、过程摘要和上一轮意见〔ARIS reviewer-independence：禁止把「我修了什么」传给审稿方；沿用同一线程时分数从 3/10 涨到 8/10〕。
- **让它做什么**：只挑错，重点是程序核不了的部分：
  - 推断句是否被它所引的事实支持（支持 / 弱 / 不支持 / 拿不准），必须摘出原文句子。
  - 引文是否支持论断，前后有没有矛盾，该写反面证据的地方有没有写。
  - 逐条输出：位置、类型、理由、原文片段。
- **怎么显示**：「挑错（Kimi）：看了 22 句推断，挑出 3 处」。从不出现「通过」或「已核验」；一处没挑出就写「没挑出问题（不代表没有问题）」〔反：模型说已验证就当验证〕。
- **什么时候跑**：你发起的活和计划的成稿都跑；例行只在碰到判断时跑；没变化的不跑。它不挡交付，卡上先显示「挑错中」。挑错的费用单独记（见第 10 节）。

### 4.4 你：先看这几处

程序给这份成稿里的所有事实和推断排一个顺序，前 7 处进「先看」，其余折叠：

1. 对不上、复算不一致、挑错判「不支持」，并且被结论或判断用到的。
2. 违反你规则的。
3. 你以前纠正过同类的：同一个指标、同一个来源、同一种错〔P25「摆出上次错在哪」〕。
4. 结论直接依赖、但程序核不了的：推断、估算、打不开的。
5. 其余对不上、没查到的。
6. 随机抽 3 条「对上」的。看不看由你，看了就记成「抽检 3/3」，用来知道程序可不可信〔P7〕。

没进前 7 的全部折叠，只显示数量：已对上的、你核过且来源没变的、不在结论里的。

这套顺序是我们自己定的，现有产品里没有人做过〔空位〕。第一版按上面写死，以后按你实际纠正最多落在哪一类来调权重〔推断〕。

### 4.5 核对条（阅读视图）

打开成稿，顶部一行：

```
先看 7 处 · 已核 3 · ‹ 上一处  下一处 › · 全部 86 条
```

点「下一处」，正文滚到那句话，句子下面展开一张小卡：

```
营收 1,032 亿元                     F0412 · 原文
为什么让你看：结论里用到 · 程序没对上
出处：宁德时代 2026 年三季度报告 · 第 3 页 · 10/28 取得
摘录：「……营业收入 1,023.47 亿元……」（对应处加底色）
[对]  [不对]  [打开原文]
```

- 「打开原文」在右栏电脑页的实时浏览器里打开。PDF 加 #page=3；网页打开原网址；原网页没了就打开快照〔B§3.3；B§1 不用 iframe〕。
- 键盘：J/K 切上一处、下一处，1 是对，2 是不对。
- 正文里每个编号都能点，弹出同样的小卡。编号默认是灰色，只有待你核的用强调色〔B§1 强调色只给和你有关的〕。
- 数字多时，点「全部 86 条」切到表格模式：一行一条事实，列是值、出处、程序、你；可以按状态筛，逐行按 1 或 2〔推断：量大时表格比在正文里翻快〕。
- 手机：同样的小卡，一屏一处，左右滑；「打开原文」只给快照文本，因为手机不做电脑画面。

### 4.6 进度怎么显示

- 文件卡上先显示「待你核 2」（强调色），核完变成「核过 7 · 抽检 3/3」（中性色）。
- 你核过的事实带一个线条对勾，换一份成稿也有效：明天的报告引用同一条事实、来源没变，它就不再进「先看」。来源一变，自动退回未核〔P14 GitHub：看过的文件之后又变了才退回未看〕。
- 不核也能用。导出成稿（PDF 或复制）时，末尾自动附一段核对状态：「86 个数字：程序对上 71 · 你核过 9 · 没核到 6（见列表）」。这正好回答技术经理的问题：下属交上来的材料，哪些验证过〔技经·decisions·4〕。

### 4.7 你说「这条不对」之后

1. 你点「不对」，小卡里多出一行：「正确的是」（可以空着）+ 一键选原因：过期了 / 口径不对 / 出处不对 / 算错了 / 不支持这句话 / 其他。
2. 这条事实出新版本：你填了值就用你的值，标「你改过」；没填就标「待重查」。纠正写进纠正.jsonl，挂在这条事实上〔空位：把一次具体的纠错记到那条事实上〕。
3. 错的值和出处哈希记成一条「负记录」：以后同一个出处再给出同一个值，程序直接标「你 10/29 纠正过」〔PerryLink 负知识〕。
4. 改动往下游传：
   - 用到它的计算类事实由程序重算，不问你，因为结果是确定的。
   - 底稿里「出处」列写着它的那几行原地更新，旧值留在行历史里〔P10：更新不覆盖，变了的看得见〕。
   - 成稿由程序替换数值，出一个新版本。含这个数的句子标「数改了，话可能要改」，同事接一轮小活去改这些句子。
5. 对话里出一行居中小字：「你纠正了 F0412（营收）· 影响 1 份成稿、2 行底稿 · 在改」。改完后文件卡显示「第 2 版 · 因你的纠正改了 3 处」。
6. 如果改动碰到你核过的句子或你的判断，第 2 版先用改动视图给你看：旧的划掉、新的上色，每处可以「留」或「退」〔P14；ARIS：动内容的替换一律问人〕。没碰到这些的直接生效。
7. 提议一条规则，见第 5 节。
8. 别的同事也引用了这条事实的，同样出新版本，并在它们的对话里出同一行小字。

### 4.8 「没核到」怎么列

| 词 | 意思 | 你能做什么 |
|---|---|---|
| 没查到 | 在指定来源里找过，没有（不等于不存在） | 给它资料 / 算了 |
| 打不开 | 付费墙、需要登录、403、解析失败、图表里的数 | 去登录（进「需要你」）/ 给文件 |
| 没去查 | 超出来源范围或预算，主动没查 | 放宽来源 / 加预算 |
| 核不了 | 推断、估算，程序无从核 | 只能你看（进「先看」第 4 类） |

成稿末尾固定有一节「没核到」，正文里的原位也保留标记，不为了成品好看把缺口挪出正文〔finance crossCutting 3：PerryLink 坚持在正文保留标记；P6〕。

### 4.9 门只设在哪

| 停下来等你的地方 | 为什么 |
|---|---|
| 改你的判断（状态、内容、检验条件） | 判断不交〔B§2.1〕 |
| 规则和关于我进长期 | 不经人看就进长期记忆是反例〔反〕 |
| 替换你核过的内容 | 动的是内容〔ARIS：REPLACE / REMOVE 要人批〕 |
| 超预算，或计划预计超出上限 | 撞线时停下来问〔P24〕 |
| 对外动作（发消息、付费、提交） | 沿用现有规矩；approval 和 takeover 不再 24 小时后自动续跑〔内核 asks〕 |

不设门的地方：日常交付、写事实、程序对上的、规则被用到、预算内开工、元数据修正（作者拼写、DOI）、确定性的重算。

门本身的数量也要控制：「今天先看」最多 7 行；每位同事的提议每天最多攒成一张卡〔P25：最有效的门最不受欢迎〕。

## 5. 纠正与记忆

### 5.1 一次纠正怎么变成一条规则

- 不是每次「不对」都提规则。只在两种情况下提：原因是「过期了 / 口径不对 / 出处不对」这类能推广的；或者同一类错出现了第二次。
- 提议是对话里的一张小卡（新卡种）：

```
想记成规则 · 来自你对 F0412 的纠正
季度财务数字只用最近一期已披露的；比最近一期旧的，正文写明期间。
程序能检查：能（数据所属期 ≥ 该公司最近一次披露的期间）
[记]  [改一下]  [不记]
```

- 规则尽量写成能检查的样子：来源级别、时效、口径字段、单位，能检查的部分写进检查.json；写不成的标「靠它自觉」〔P19 终点要可检验〕。
- 你点「记」，它才写进 AGENTS.md 的「## 规则」一节，带编号 R5 和来源链接。点链接跳回那次纠正所在的那一轮〔P22：Devin 提议的知识可以改、可以重生成、可以不要〕。
- 你自己说「以后……」「记住……」，这句话本身就算点头，直接记，对话里出一行小字「已记成规则 R6」。

### 5.2 怎么让你知道它下次用到了

- **能检查的规则**：每次交付前由程序执行。违反的事实在交付前退回同事；它没改好的进「先看」第 2 类，写明「违反你的规则 R5」。成稿页脚写：「按规则程序检查：R5 时效（14 个数字都是最近一期，交付前拦下 1 个）」。
- **靠自觉的规则**：同事在 deliver 的 data 字段里声明用到了哪几条〔内核 cheapExtensions 5〕。页脚写「它说用到了：R3」，措辞故意不同，表明这是它自己报的。
- **右栏「规则」每行显示**：文本 · 机查或自觉 · 用到 12 次 · 上次 11/12 · 拦下 1 次 · 被违反 0 次。
- **被违反**：你又纠正了同类的错，这条规则标「被违反 1 次」，这次纠正也进挑错方下一次拿到的「上次错在哪」。

### 5.3 记忆分几层

| 层 | 是什么 | 在哪看 | 谁能改 | 进入要不要你点头 |
|---|---|---|---|---|
| 关于我 | 你是谁、做什么、东西怎么交给你 | MyWork 的资料页 | 你直接改；同事只能提议 | 要（你自己说的除外） |
| 规则 | 这位同事做事的规矩，偏好也在内 | 同事资料页的「规则」 | 你可以直接改、停用；同事只能提议 | 要（你自己说的除外） |
| 底账 | 事实、判断、纠正 | 右栏「底账」、成稿里的编号 | 事实：同事写、程序核；判断：只有你 | 事实不要；判断要 |
| 对话与过程 | 上下文 | 对话 | — | — |

- 「关于我」从界面外的 $DSH_HOME/AGENTS.md 搬进 MyWork 的资料页〔断点 6〕。
- 同事听到一句像是关于你的话（比如「我是做产品的」），就提议记进「关于我」。所有同事共用这一份，避免同一句话对两位同事各说一遍〔评估 realUse 10〕。
- 待你点头的提议最多 5 条，再多就丢掉最旧的，并说一声〔P22：草稿区会无限变长〕。

### 5.4 「它最近错过的」

右栏「规则」下面一小节，列最近 30 天的三类错：你退回的、挑错方挑出且你确认的、对账落空的。各一行，带日期，点了跳回原处〔P25〕。挑错方每次拿到的「上次错在哪」，就是这份清单。

## 6. 长任务

### 6.1 什么时候出计划

同事估计一件事超过一轮（约 15 分钟）、要读 20 页以上、或要核 20 条以上，就先出计划卡。你说「做个计划」也会出。其余照旧，说一句它就做〔推断：这几个阈值以后再调〕。

### 6.2 计划卡（一张卡，原地更新）

```
计划 · 宁德时代深度底稿
要回答：① …… ② …… ③ ……
来源：一手 巨潮公告、公司官网 · 可用 你给的 4 份研报 · 不用 自媒体
会交：底稿表（约 80 条事实）+ 成稿 1 份（每个数字带出处）
做到什么算完：80 个数字每个都有出处和状态；没核到的单列
会停下来：① 先做 5 条给你看  ② 资料打不开  ③ 花到 ¥8
预计：70–110 分钟 · ¥4–7（估算，按你过去 3 次同类）
[开始]  [改]
```

- 「做到什么算完」和「会停下来」两行是固定的〔P19；ARIS 验收契约〕。
- 预计时间和费用：有同类历史就按历史给一个区间；没有就按步骤数乘平均值，标「粗估」〔空位：长任务开始前给费用估算〕。
- 什么时候开工：
  - 预计在预算内、问题也清楚：不等你，卡上写「已开始 · 随时改」。
  - 超预算或它拿不准：等你点「开始」〔P17〕。
  - 不做倒计时自动开工，因为对已经离开屏幕的人，倒计时等于没问。
- 改计划就在对话里直接说（steer），不做可编辑的步骤块〔P18：这部分放不进对话〕。

### 6.3 第一站永远是样本

做出前 5 条事实（或前 5 条引用核对）就停，出一张样本卡：

- 5 条，每条带出处摘录，可以逐条点「对 / 不对」。
- 底部四个回答：照这样做下去 / 改（直接说）/ 跳过第 N 步 / 停〔P2 先小样试跑再全量；ARIS 检查点的四种回复〕。
- 30 分钟没回答，就照计划往下做。成稿上标「样本你没看」，这 5 条排进「先看」最前面。
- 样本卡和预算卡是计划检查点，不是 mywork_ask，不占每轮 2 次的名额。

### 6.4 中途看到什么、能做什么

计划卡原地更新：

- 步骤一行一个，状态是：未开始 / 在做 / 完成 / 卡住〔叶青章节台账的状态机，简化后〕。
- 一行进度：「事实 34/80 · 对上 28 · 没查到 3 · 已花 ¥2.1 · 41 分钟」。

你能做的：说话改方向；点「停在下一个检查点」；点「停」。过程折叠照旧在。

### 6.5 中途改方向

你说「别管海外了，只看国内三家」，同事改计划文件，计划卡上多出一行对照：

> 作废 3 步 · 新增 2 步 · 已收集的 28 条事实保留（7 条海外的留在底账，不进成稿）· 剩余预计 50–70 分钟 · ¥3–4

事实都在底账里，改方向不会丢掉已核的部分〔评估 走查 7：现在改了方向，不交代前面哪些作废、哪些保留〕。剩余预计超出上限，就停下来问你。

### 6.6 分段、超时、中断、撞线

- **分段**：引擎把计划拆成每段不超过 20 分钟的运行。每段结束写计划文件和底账，再自动接下一段（新的运行触发类型「计划」）。20 分钟从此只是一段的上限，不再是整件事的上限〔断点 7〕。
- **一段超时**：失败气泡变成「第 4 段超时 · 已存到第 37 条 · [续上]」，并自动重试一次。现在的失败气泡没有任何操作，这里补上〔内核 threadItems 9〕。
- **服务重启**：重启后按计划文件续上。
- **撞预算**：在最近的检查点停下，先交已有的成稿和「没核到」清单，出一张卡：「加 ¥3 继续 / 就交这些」。硬停会丢掉做了一半的结果〔P24：Quesma 30 分钟烧完额度，什么结果都没有〕。

### 6.7 会话怎么分（这是对现有模型的一处改动）

现在一位同事只有一条 dsh 会话，例行和长任务都追加进去，上下文越来越大〔内核 constraints；EDITIONS 第 6 节第 5 条：3 天 13 轮，从 2.4 万涨到 20 万 token〕。

改成：

- 你看到的对话仍然只有一条，不变。
- 计划的每一段、有变化的例行，各开一个短会话。短会话从文件起步（规则、相关的事实和判断、计划文件），结果照样写回这条对话。
- 你直接和它说话，仍走主会话。主会话需要知道例行做了什么时，去读底账，不靠上下文。

依据〔P23；finance crossCutting 14；Claude Code 文档：定时任务每次触发都带着全量上下文〕。要改的是 engine.js 里「一位同事对应一条会话」的映射（中等改动）。这条依赖「记忆放在文件里」，任务书标它为假设，需要验证。

## 7. 找回与延续

### 7.1 三个月后找回「上次对某只票的结论和依据」

- **从右栏「判断」进**：一只票一条或几条。点开后中栏显示：
  - 一句话、状态、检验条件。
  - 时间线：建立 · 依据 · 每次触发 · 状态变更 · 你的修改。
  - 依据事实：每条能点到出处快照，原网页改版或下线了快照还在。
  - 相关成稿的各个版本。
- **用搜索**：结果分组为判断 · 事实 · 成稿 · 对话。成稿做全文检索，不再只看前 2,000 字；底稿和底账也进搜索；可以按同事、主体、时间筛〔断点 4：39% 的正文搜不到，表不进搜索〕。
- **直接问同事**：它有工具读自己的底账和旧成稿（成稿已经在它自己的文件夹里），回答里带编号〔断点 4：同事读不到旧交付物〕。

### 7.2 老板问「为什么不用某个新模型」，半小时内拿出依据

从「决定」进去：当初有哪些选项、为什么不选、依据是什么（对照结果、价格、合规）、重审条件是什么。新模型不在当初的选项里，同事就给出它现在知道的情况（厂商自报的标「未独立核实」），并提议跑一次对照，写清要多久、花多少。详见场景 15.4。

### 7.3 版本和取代

- 成稿每改一次就是一个新版本，头部写「取代 <旧 id>」。文件卡显示「第 3 版 · 取代 10/12 版」。旧版在文件页和搜索里标「已被取代」，默认只显示最新版〔断点 8〕。
- 同一条例行每天出的报告是一个序列，不互相取代；同一份东西被追问修改，才算新版本〔推断〕。
- 任意两个版本之间可以看改动〔P14〕。

### 7.4 留多久

- 一直留：事实、判断、纠正、被引用的出处快照、成稿。都是文本，按哈希去重。
- 7 天清理：.cache/ 里的原始抓取。
- 运行记录：每位同事分开存，超过上限的旧运行归档成文件，不再丢掉〔内核 constraints：现在全体共用 2,000 轮上限，超了丢最旧的〕。

## 8. 三种用户各自的第一位同事

### 8.1 金融版：「覆盖与判断」模板

名字由用户起，或由同事自己起。给个人投资者、5–9 人私募的研究员、买方研究员〔B§2.2 首批候选〕。

- **职责**：盯覆盖清单里的票；只报相对你的判断变了什么；需要时做个股深度（走计划）；到期对账。
- **底稿**：
  - 覆盖表.csv：代码, 简称, 市场, 分组, 关注理由, 启用。
  - 公告库.csv：公告ID, 代码, 披露时间, 类别, 标题, 关键数字的事实编号, 页码, 状态。
- **底账**：
  - 事实：公告里的数、财务数、收盘价。
  - 判断，每只票一组：一到三句看法；3–7 条假设，每条写验证方式和频率；红线三栏（条件 / 严重程度 / 触发后做什么）；可结算的预测（方向 / 阈值 / 期限）〔ai-berkshire 的论点追踪和卖出条件；鸣山；alpha-desk〕。
- **例行**：
  - 交易日 21:30 扫公告：脚本先跑，只为覆盖的票的新公告叫模型。
  - 交易日 16:00 结算到期的预测：只跑代码。
  - 周日 20:00 周度对账：代码出表，模型写两三句。
  - 财报日按日历来。
- **交付**：有变化时的短回话 + 文件卡；深度成稿（先事实包、后成稿）；对账表。
- **借用**：巨潮 / 上交所 / 深交所直连、liteparse、stock-sdk、alpha-desk 的结算规则、ai-berkshire 的假设表和「只比证据不比措辞」的漂移规则、financial_rigor。
- **第一周**：
  - 第 1 天：贴票、确认、看「此刻版」，学会点出处。
  - 第 2–5 天：多数晚上只有一行「没有碰到判断的变化」，有公告时 1–3 行。
  - 可以挑 2–3 只票写判断。
- **不做**：每天一份早报（通用资讯不是切入点〔B§2.1〕）；盘中盯盘。

### 8.2 AI 版先给谁

两种人都给。第一次打开时问一句：「你主要是自己做研究，还是要为团队做技术决定？」，按回答分到两个模板。如果只能先打磨一个，我的建议是先做技术经理〔推断〕，理由如下：

- **做 AI 研究的人**：
  - 证据最强的需求是引用核对，但它是每篇投稿前用一次，不是日常〔需求 R1〕。
  - 每天筛新论文已经有免费工具〔需求 6.9-1〕。
  - 实验在远程服务器上，而我们没有任何 SSH 支持〔B§3.3〕。
  - 付费意愿接近零，对手是跑在同一个底座上的免费技能包 ARIS〔需求 6.9〕。
- **技术经理**：
  - 他要的东西，只有装在本机、记得「我们在用什么」的长期同事做得了：下线和调价只在碰到在用清单时才报，决定的依据留着到期重审〔技经·keeping-up·1；技经·decisions·6〕。
  - 现成的下线追踪工具不覆盖国内供应商，也不知道你的哪个业务在用〔B§2.4〕。
  - 开发数据里的两位雷达同事就是这个形状〔评估 走查 4〕。
- 两个模板共用九成机制（事实、核对、挑错、规则、计划），差别只在模板内容。
- 注意：技术经理的需求调研还在复核〔B§2.4〕。

### 8.3 做 AI 研究的人：「文献与引用」模板

- **职责**：按课题每天筛新论文，并说明和课题相关在哪里；投稿前逐条核引用；维护课题文献表。
- **底稿**：
  - 课题表：课题, 正词, 负词, Zotero 分类。
  - 新论文.csv：日期, 标题, arXiv, 档, 相关在哪（事实编号，指向摘要里的原句）, 排除原因。
  - 引用表（每篇稿子一张）：引用键, 句子, 位置, 被引文献, 存在, 元数据, 支持度, 原文段与页码, 你。
- **例行**：每天 9:00 抓 arXiv 列表，脚本按关键词打分、去重（不花模型的钱），只为前 10 篇叫模型写「相关在哪」。页尾列出被排除的论文和原因〔dailypaper-skills；需求 6.9-1：重度用户要看得到被筛掉的部分〕。
- **按需**：投稿前核引用，走计划，见场景 15.3。
- **借用**：dailypaper-skills 的 fetch_and_score 思路、Zotero 本地接口、ARIS citation-audit 的判词和审稿人独立规则、verify_papers / refchecker 的多库比对、paper-qa「论断后跟文献加页码」的写法。
- **不做**：实验台账和夜间排队实验。我们够不着远程机器，职责里如实写明〔需求 6.9-3〕。

### 8.4 技术经理：「在用与变化」模板

**节奏是事件驱动的**〔B§2.4〕：

- **没有每日简报**。例行全是只跑脚本的「盯」：每 6 小时比对一次来源表里的页面，包括各家的定价页、弃用页、更新日志、状态页，models.dev 的 JSON，OpenRouter 模型列表，deprecations.info，关键依赖的发版。
- **只有变化碰到在用清单的某一行，才叫模型、才找你**。没碰到的只记进底账，「今天先看」里也不出现，到月度复盘时算成一个数〔Dependabot：把变化做成工作对象，送到工作发生的地方；技经·keeping-up·9：不追也不会错过要紧的事〕。
- **有截止日期的**（下线日、调价生效日）进「需要你」第 2 类，带倒计时，同时立刻推一条 IM。这类事的通知期可能不到五天〔技经·keeping-up·1〕。
- **每月 1 日一次月度复盘**：在用清单的变化、花费、到期该重审的决定。
- **另外两种触发**：你转来的通知（粘贴邮件正文）、老板的提问。

**「我们在用什么」怎么让它知道**：

- 在用清单.csv：类别, 名称, 型号或版本, 供应商, 用在哪个业务, 负责人, 月用量或花费, 计费与开票, 合规备注, 怎么知道的, 启用。
- 来路四种：你说或粘贴；你导出的账单 CSV；你指给它的配置文件（只读型号名，不读密钥的值）；dsh 自己的模型设置。
- 每一行由你认一次（上岗卡 1），之后新增的走提议〔推断〕。

**决定怎么留档、到期重审**：

- 决定是判断的一种，字段照 ADR：决定、背景、选项和不选的理由、依据（事实、对照结果）、重审条件、状态（有效 / 存疑 / 失效 / 被取代）、取代关系〔ADR / MADR〕。
- 重审条件举例：价格涨超过 x%；同一档出现新型号；在用型号出现下线公告；到某一天。
- 重审条件由程序盯。触发后进「需要你」，同事起草「要不要重审」和还需要补哪些依据。现在没有人对 AI 选型做定期的事后对照〔技经·decisions·6、10〕。

**在自己的任务上测**：

- 对照/ 目录里放三样：任务集（你给 10–30 条真实任务和判定方法）、一个用你的 key 调候选模型的 Node 脚本、结果表（质量、单次成本、时延）。
- 结果是「自测」类事实，附脚本和每条输出，可以重跑〔技经·cto·2：现在的对比靠下属临时手工做，不可重复〕。
- 主观题先由挑错用的模型按你写的标准打分，再给你抽 5 条看〔推断〕。

**向上解释的材料（一页说明）**：

```
结论（一段）：建议……；需要你 / CEO 定的是……，截止……
选项对比（表）：方案 | 在我们任务上的结果 | 单次成本 | 月成本 | 切换代价 | 采购与合规
风险（不超过三条）
如果……就重新看（重审条件）
依据：12 条 · 出处对上 9 · 我们自测 2（附脚本）· 厂商自报未核实 1
```

默认带一条写法规则：「短句，不用排比和套话」。一眼看出是 AI 写的管理材料，会让下属掉信任〔技经·team-level 信任〕。可以导出 PDF，或复制成文字贴进飞书文档。

## 9. 多位同事之间

- **共享的**：
  - 关于我，只有一份。
  - 出处快照：同一网址、同一时刻只存一份。
  - 挂起的阻塞：同一站点、同一账号合成一条，处理一次全部解开。
  - 事实可以跨同事引用，纠正会传给所有引用它的同事。
- **不共享的**：规则、判断、对话。
- **互读**：每位同事多一个只读工具，能查别的同事的底账、判断和成稿〔断点 12：同事之间没有读对方产出的工具〕。
- **一件事归谁**：
  - 覆盖清单里的主体、在用清单里的条目，各自只归一位同事。
  - 新建同事或新加覆盖时，MyWork 发现重叠就问一次「归谁」（用现成的选项卡）〔评估：探新和财联社记者各做了一遍 GitHub 热点，「归谁」悬了好几天〕。
  - 一条判断只属于一位同事。
- **两位同事报了同一件事**：「今天先看」里合成一行，标「两位都报了」。

## 10. 费用

- **怎么记账**：每轮运行记 token，按价格表折成钱。价格默认取 models.dev，你可以改；DeepSeek 的默认价内置〔B§3.3 dsh 有 token 计量服务；插件里能不能取到还没验证〕。挑错、计划的每一段、每条例行分开记。
- **在哪里看**：
  - 过程折叠的标题：「过程 · 12 步 · 3m · ¥0.31」。
  - 右栏例行每一行：「每次约 ¥0.2 · 本月 ¥5.8」，最近 10 次每次都带花费〔P24：Claude Code 把最耗的定时任务单列一行〕。
  - 同事资料页：「本月 ¥18.4」和它用的模型。
  - MyWork 资料页：「全部同事 本月 ¥62 / 预算 ¥100」，可以按同事、按例行排序。
  - 干活时，底部那一行加上「已花 ¥0.4」。
- **长任务开工前**：计划卡上给区间（见 6.2）。
- **预算**：每月总预算（在上岗卡 2 设）；每位同事可以另设；每个计划有单次上限。
- **撞线时**：
  - 例行的脚本部分照跑（不花钱），只停叫模型的部分。
  - 判断触发由代码判断，照样通知你。
  - 「需要你」出一条：「本月预算到了：3 条例行只跑了脚本，有 5 处变化没让它看 · [加预算] [本月就这样]」。
  - 计划撞线见 6.6。
  - 花到 80% 时提前提醒一次。
- **模型可以按同事选**：资料页「模型」一行。例行默认用便宜的（如 deepseek-flash），计划和挑错各自可以选〔P24 Quesma：便宜模型批量找、准的模型核；Rakazo issue 719：每位 bot 的模型选择埋得太深〕。

## 11. 桌面和手机的分工

| 做的事 | 桌面 | 手机 |
|---|---|---|
| 第一次见面、上岗卡 | 是 | 能看，不建议在手机上做 |
| 今天先看 | MyWork 对话里的卡 | 首页顶部，一条一屏 |
| 判断触发 | 看依据、改判断 | 知道了 · 让它深查 · 稍后 |
| 核对 | 核对条 + 在实时浏览器里看原文 | 一处一屏，看快照摘录；对 · 不对 · 稍后 |
| 「这条不对」 | 是 | 是，一键选原因 |
| 规则提议 | 是 | 记 · 不记 |
| 计划 | 定、改、看样本 | 样本卡的四个回答；停 |
| 登录、接手浏览器 | 是 | 只能「稍后到电脑上」 |
| 改判断、编辑规则、一页说明定稿 | 是 | 否 |
| 费用 | 全部 | 只看数字，加预算 / 就这样 |

**送达**：手机没有系统推送〔断点 11〕。

- 先用现成的 IM 推送：只推「需要你」第 1、2 类，每天早上一条合并推送；截止日在 7 天内的事立刻推〔内核 notifications：IM 推送已有，但没有设置默认目标的界面〕。
- 补一个设置 IM 默认目标的界面（小改动）。系统推送放在后面，是中等改动。

**手机上 5 分钟的样子**：IM 收到一条「今天先看 4 件」→ 打开 App 或中继网页 → 4 屏，每屏一个决定 → 第 5 屏写「其余不需要你」。

## 14. 去掉什么

1. **例行最后一行「变化：有 / 无」**：判错过一次，把一份 7 条的日报藏到现在都打不开〔断点 3〕。改由程序判断。

3. **整份文件的「有用 / 没用」**：66 份交付物一次都没被用过〔评估 realUse 3〕。收起，表态改到事实上（对 / 不对）。
4. **MyWork 晨报的散文综述**：换成「今天先看」卡〔评估 realUse 9〕。
5. **文件卡上由模型自己起名的关键数字**：换成状态计数〔断点 13〕。
6. **右栏「最近的文件」被原始抓取淹没**：原始抓取挪进 .cache/，不再列出；文件夹按 资料 / 底稿 / 成稿 / 计划 分组〔断点 10〕。
7. **「一打开就算已读」不再代表「看过」**：红色未读数保留，但「看过」改由核对状态和「需要你」的处理状态来表达〔评估 realUse 19：7 位同事在 8 分钟内被依次点成已读〕。
8. **approval 和 takeover 的 24 小时自动续跑**〔内核 constraints〕。
9. **界面之外的全局「关于我」**：搬进界面。
10. **「它记住的」这个名字**：改叫「规则」，原来的内容并进来。

保留不动的：一条对话、一句话建例行、默认按合理假设做完、MyWork 当分诊口、跳转只有一条规则、本机浏览器和接手〔B§3.2「应当保留的」〕。

## 15. 走一遍场景

### 15.1 个人投资者：12 只股票跟踪三个月，中间 3 次深度，最后找回结论

1. **第 1 天**：点「+」，选「覆盖与判断」。
   - 上岗卡 1 贴 12 个简称：10 个直接锁定，2 个有歧义，点选候选。
   - 卡 2 用默认来源，预算每月 ¥50。卡 3 用默认例行。卡 4 跳过。
   - 「此刻版」：近 3 个交易日的公告 5 份、事实 9 条。核对条显示「先看 2 处」，他点开一处，右栏打开巨潮公告 PDF 的第 2 页。
2. **第 2–20 天**：
   - 多数晚上只有一行：「没有碰到判断的变化 · 查了 12 只 · 新公告 3 份（无关）」。
   - 他还没写判断，所以同事只报新公告。有一次在回话末尾提了一句：「要不要给比亚迪写一句看法，以后只报碰到它的？」这只是回话里的一句话，不是门。
3. **第一次深度（第 3 周）**：他说「做一份比亚迪深度」。
   - 计划卡：60–90 分钟、¥3–5，预算内，自动开始。
   - 10 分钟后出样本卡。他标了 1 条「不对 · 口径不对（这是含少数股东的）」。规则提议「净利润默认用归母口径」，他点「记」。
   - 交付成稿第 1 版：86 条事实，「先看」7 处，他核完 7 处，再抽 3 条，都对。
   - 同事起草一组判断：比亚迪的看法、4 条假设、2 条红线、1 条可结算预测（12/31 前的方向和阈值）。他改了一条假设的门槛，点「认」（门 A）。
4. **之后每晚**：只有比亚迪的公告碰到假设门槛时才出声：「三季报单车毛利 x〔F…〕，低于假设 2 的门槛」，这条进「需要你」第 1 类。他看了依据，把判断改成「存疑」（门 A，由他自己改）。
5. **第二、三次深度**：流程相同。每次深度各是一份成稿，被追问修改才出新版本。
6. **每周日**：到期的预测由代码按收盘价判成命中 / 部分 / 落空 / 作废，写进判断的时间线。
7. **第 90 天找回**：
   - 从右栏「判断」点比亚迪：现在的一句话、状态「存疑（11/02 你改的）」、9 个时间线节点、14 条依据事实（原网页改版了，快照还在）、3 份深度成稿（第二份有第 2 版）。
   - 或者搜索「比亚迪 结论」，第一组就是判断。
   - 或者问同事，它的回答里引用 J4 和事实编号。

**哪里仍然不够**：
- 判断要人写，或者至少要人认。ai-berkshire 作者自己的 4 个论点文件里有 2 个从没更新过；只有例行自动触发的跟踪真的会发生〔finance crossCutting 15〕。没写判断的票，就退回到「只报新公告」。
- 他的 Excel 模型接不进来。xlsx 在界面里不能读，univer 在锁定的 dsh 版本上也不激活，所以财报季「新数填进模型」做不了〔需求 F5〕。
- 三个月下来有几千条事实，检索性能没测过。付费研报读不到。

### 15.2 买方研究员：40 页深度底稿，交回来后核 80 个数字

1. **给材料**：把 4 份 PDF（年报、两份券商深度、一份纪要）和一份 xlsx 拖进对话框。PDF 解析出页码和坐标；xlsx 存成文件，由同事用脚本读单元格。

5. **交付**：成稿写进 成稿/，不再塞进工具参数，另有一张底稿表。

**哪里仍然不够**：

4. **回到电脑**：点了「稍后」的两条排在「需要你」最上面；周报已经出了第 2 版。

**哪里仍然不够**：
- 他要靠 IM 推送才知道有事，而 IM 默认目标现在没有设置界面。
- 中继在大陆手机网络上能不能连通没实测；电脑关机时例行不跑。
- 在手机上读全文仍然不合适。

### 15.6 同事用了过期的数字，被纠正；两周后会不会再犯，用户怎么知道它记住了

1. **10/29**：成稿写「毛利率 31.2%〔F0388〕」。F0388 是 2025Q4 的数，而三季报 10/28 已经出了。时点检查只盯「最新」「本周」这类字眼，没拦住；挑错方也没挑出来。
2. **他纠正**：这处因为被结论用到，进了「先看」。他点「不对 · 过期了」，没填值。
   - F0388 标「待重查」，同事取三季报，写成新事实 F0412（21.3%）。
   - F0388 标「已被取代 · 你 10/29 纠正：过期」。
   - 成稿出第 2 版，两句话被改写，他在改动视图里留下了。
3. **规则提议**：「季度财务数字只用最近一期已披露的……能机查（最近一期披露日从巨潮公告列表取）」。他点「记」，成为 R5。右栏「它最近错过的」多一行。
4. **11/12，两周后**：他让同事做一份比亚迪对比。同事引用了 2025 年报里的毛利率。
   - 交付前程序执行 R5，发现违反，退回同事；同事改取三季报，第二次交付通过。
   - 页脚写：「按规则程序检查：R5 时效（14 个数字都是最近一期，交付前拦下 1 个）」。
5. **他怎么知道它记住了**：右栏规则 R5 显示「用到 3 次 · 拦下 1 次 · 被违反 0 次」。这不是同事自己说记住了，而是程序拦下的记录。
6. **如果规则没法让程序检查**：页脚写「它说用到了：R3」。再犯时他第二次纠正，R3 标「被违反 1 次」；挑错方下次拿到这条记录，相关句子排进「先看」第 3 类。

**哪里仍然不够**：
- 「最近一期」要知道每家公司的披露日期，取不到时 R5 退化成靠自觉，页脚会写明。
- AGENTS.md 追加内容后，活着的会话下一轮会不会重新读到，没验证〔内核 unknowns〕；短会话方案（6.7）可以绕开，但也要先验证。
- 规则多了会互相冲突，AGENTS.md 会变长（Claude Code 建议控制在 200 行内），第一版没有设计定期体检。

### 15.7 一件要跑两个小时的事，用户中途想改方向

1. **开工**：「对比国内外储能电池企业的产能和订单」。计划卡：12 家公司、100–140 分钟、¥7–10，预算内，自动开始。
2. **10 分钟**：样本卡，他认可。
3. **40 分钟**：进度「事实 31/90 · 海外 3 家已完成」。他发：「别管海外了，集中国内前三家，加上订单的客户结构。」
4. **同事处理改向**：这句话进入当前这一段，同事在这一段的检查点处理。计划卡出一行对照：
   > 作废：海外 6 家（3 家已做完，事实留在底账、不进成稿）· 国内后 3 家 · 新增：客户结构 3 步 · 保留：国内前三家已收集的 12 条 · 剩余预计 45–65 分钟 · ¥3–4
5. **如果此时有例行在跑**：他的话不再排到最后，而是标「会在这一段结束时接上（约 6 分钟）」。计划段之间的空隙优先处理用户的话〔评估 走查 7〕。
6. **他补一句**：「客户结构用公告披露的前五大客户，不要用新闻。」这句话成为计划的约束，同时提议一条规则，他点「记」。
7. **收尾**：花到 80% 时提醒一次；最终 95 分钟、¥6.1，交付后按第 4 节核对。

**哪里仍然不够**：
- 一段里的插话什么时候生效，靠模型在检查点自觉处理。
- 改方向后哪些事实已经无关，是模型判断的。
- 分段接续是新机制，没有样本，预计时间的误差不知道。

### 15.8 CTO 收到（或没收到）DeepSeek 的下线和调价通知

- **路径 A，他收到了邮件**：把正文粘进「在用与变化」同事的对话。
- **路径 B，他没收到**：06:00 例行比对 DeepSeek 的定价和模型页面，发现快照变了：定价表改了一行，脚注写着旧型号名将指向新型号。DeepSeek 确实做过把旧型号名静默重定向、写在脚注里的事〔技经·keeping-up 意外〕。
  - 同事写 3 条新事实：重定向、新单价、停服日。
  - 碰到在用清单的 2 行，进「需要你」第 2 类「截止 10/12 · 影响 2 个业务」，同时立刻推 IM。

之后两条路径一样：

1. **影响面成稿**：
   - 影响表：业务 | 负责人 | 现用型号 | 上月用量（来自账单）| 旧单价 | 新单价 | 月成本变化（程序计算）| 截止。
   - 可选做法三种：A 不动，接受新型号和新价；B 显式改用新型号名，回归测试后切换；C 迁到别家。
   - 建议先跑新旧型号对照（约 10 分钟、¥1.5），附一份给 CFO 的一页说明草稿。
2. **先看 3 处**：生效日、新单价、上月用量。他在实时浏览器里看了 DeepSeek 文档的对应段落，三处都点「对」。
3. **跑对照**：新型号 18/20，旧型号 17/20，有 2 条格式变了。
4. **改决定**：D1 改成「显式改用新型号名，10/11 前回归通过后切换」（门 A）。在用清单的行更新，由他认。
5. **给 CFO 的一页说明**：「下周起 DeepSeek 调价，我们两项业务每月约多 ¥1,200（按上月用量算，附计算表）；已在我们的任务上测过，效果不降；不需要换供应商。这件事需要你知道，不需要你批。」依据：出处对上 4 · 自测 1 · 估算 1（迁移工时）。
6. **通知负责人**：同事起草两条给负责人的消息，走现有的批准卡（对外动作，门）。

**哪里仍然不够**：
- 没有账单导入，就没有「上月用量」，月成本只能估。
- 我们读不到他的邮箱，通知要他自己转进来。
- 国内供应商的通知未必都在公开文档上，页面改版会误报。
- 「影响到哪些业务」完全取决于在用清单有没有维护，而清单本身没有自动发现。

## 16. 没把握的地方

**推断，需要试用或访谈验证的**：
1. 人愿不愿意逐条点「对 / 不对」。没有任何项目记录过人核一份底稿实际花多久〔finance unknowns〕；「先看 7 处」的 7 是拍出来的。试用时要记下每一处的用时。
2. 按风险排的顺序是我们自己定的，没有先例〔空位〕。
3. AI 版先做技术经理是推断；技术经理的调研还在复核；他会不会维护在用清单，没有证据。
4. 个人投资者愿不愿意写判断。ai-berkshire 作者自己的论点文件有一半没更新过。
5. 没有变化也留一行，用户会不会嫌吵。我推断它比漏报便宜，但没验证。
6. 计划给出的时间和费用估算误差有多大。
7. 多少用户愿意再配一家模型的 key 用来挑错；挑错方说「挑不出」时，用户会不会误以为没问题。

**技术上还没验证的**：
1. 字面核查在中文公告和研报上的命中率。「没查到」太多，核对清单就会变成噪音。
2. 事实的键（主体 / 指标 / 期间 / 口径）由模型来写，写错了，核对的继承和变化判断都会错。
3. liteparse 在中文年报的跨页表、合并单元格上的坐标质量；Chrome 里 PDF #page=N 能不能用。
4. 内核：插件里能不能取到 dsh token meter；AGENTS.md 追加后会不会重读；按同事放技能是否只有它自己看得到；ctx.tools.restrict；短会话从文件起步的效果。
5. 手机送达：IM 默认目标、中继在大陆移动网络上是否可用、系统推送。
6. 快照的存储增长。技术雷达 4 天 36.9 MB 是原始网页；只存正文应当能小一个量级，这是推断。
7. Windows：所有 Node 脚本都没在实机上跑过；Zotero 本地接口没测。
8. 「用已登录的浏览器读付费内容」仍然只是假设。本设计不依赖它，但「打不开」的条目会因此变多。

**建议放进访谈的问题**：
1. 一份东西你最多愿意花几分钟核？
2. 你会不会写下自己的判断和「什么情况算我错了」？
3. 没有变化时，你想看到一行字，还是什么都不出现？
4. 手机上，你通过什么渠道接收提醒？

# MyWork Kit v2 · 像 Manus 和 Muse 那样

> 一句话：**给个人的通用工作 agent。你说一个结果，它在后台干完，交给你一份东西，并且自己检查过。**

这是整个套件的形态改造，不是某个场景的。交易工作台是第一个场景插件，后面还有办公文档、上网调研、定时巡检等等。分支 `research-muse-paseo`，从 `main` 建，不动 `main`。

## 1. 为什么改

现在的 MyWork Kit 是「dsh 加一堆插件」：新建对话页、会话列表、工作区、模型选择器、访问模式、插件市场。用户看到的是拼装，用起来是聊天。Manus 和 Muse Code 好在四件事，我们一件都没有：

1. 单位是**任务和交付物**，不是对话。
2. 任务**在后台跑**，做完通知，你回来看结果。
3. **自己检查**：Muse 的验证观察者核对声称做过的事；Manus 重新规划并展示计划。
4. **概念少、入口一个**。

dsh 的会话仍然是执行引擎，只是不再是用户看到的东西。

## 2. 三个对象，一条主线

用户只认三个词：**任务**（你要的结果）、**交付物**（做出来的东西：报告、表格、演示文稿、网页摘要、一份清单）、**场景**（一类任务的做法，由插件提供）。

```
一句话 ──▶ 任务（后台：计划 → 执行 → 交付 → 核验）──▶ 通知 ──▶ 交付物页 ──▶ 评价 ──▶ 下次自带历史
                       ▲
                       └── 场景插件决定：怎么拆步骤、用什么工具、交付什么、怎么核验
```

任何按钮最终都是「创建任务」或「打开交付物」。

## 3. 界面

```
MyWork（一页）
  今日     一句问候 · 今天的清单（提醒 / 失败 / 在跑 / 今天交付的）· 例行（下次什么时候跑）· 底部输入栏
  侧栏     新任务 · 今日 / 任务 / 例行 · 历史（点开就是回答）· 设置
  设置     模型、通知、领域与成员、外观
```

没有「新建对话」「会话」「工作区」「插件市场」「MCP」「IM 助理」这些名字；它们退到设置里。对话原文折叠在交付物的「过程」里。

### 今日

一屏一件事（Grok 的纪律）。产品只有一页：一句问候、**今天的清单**、下面一小段**例行**（每条：名字、周期、右边是下次时间；点开进例行页管理）、底部一个输入栏。任务页和例行页保留：今日是今天的切面，任务是全部历史，例行是管理。清单一行一条，形状相同：状态图标、标题、右边一个状态或一个按钮。顺序：提醒（知道了）、失败（再来一次）、核验有问题、在跑的（当前步骤和耗时）、今天交付的（已交付 / 有变化 / 无变化）。没评价的交付物折成一行。没有分组标题，没有卡片，没有「最近」（侧栏就是最近）。今天没事就是一句话。

### 任务页

回答就是页面。返回箭头和一个「···」菜单（再来一次 / 重新核验 / 取消 / 原始对话），标题，一行元信息（核验结论 · 领域 · 时间），然后是交付物正文，全宽、纯文本排版，正文下面一行浅按钮（有用 / 没用 / 导出）。对话类任务显示往来消息。过程折成一行「过程 · 读取网页 9 次 · 搜索 3 次 · 3m」，点开才是工具流；跑的时候默认展开。最下面是追问框。任何宽度都是单列。

### 交付物页

一份文档：标题、场景标签、日期、核验徽章、右上四个动作（评价、再来一次、导出、过程）。正文由场景决定的渲染器画（报告、表格、幻灯片预览、摘要），默认是 Markdown。

## 4. 架构

新增一个套件成员 `dsh-mywork-tasks`（任务引擎），其余成员改成场景或退到设置。

### 任务引擎（宿主）

- **任务**：`{ id, title, scenario, input, status, steps[], sessionId, deliverableIds[], createdAt, finishedAt, error }`，存 `$DSH_HOME/mywork/tasks.json`。状态五个：排队、执行、交付、核验、完成（失败也是完成，带原因）。
- **执行**：一个任务 = 一个 dsh 会话。引擎用 dsh 的 `sessionController.prompt` 发起，监听 `session/event`（同 IM 插件的做法）推进步骤：工具调用映射到步骤（场景给映射表），`deliver` 工具调用即交付，会话空闲即完成。
- **并发**：默认同时跑两个任务，其余排队。
- **交付**：通用工具 `deliver({ title, kind, markdown, data?, scenario? })` 写入 `deliverables.json`；场景可以注册自己的交付工具（例如交易的 `oracle_report_save`）并声明渲染器。
- **核验**：可选的第二个会话，只做核对，提示词由场景给（默认：交付物里的事实是否与工具返回一致、有没有未完成的承诺）；结果写回交付物 `verification: { checked, passed, notes }`。
- **通知**：任务完成、交付物生成时发 `mywork/task` 全局事件；IM 插件订阅后推飞书（已有直推），前端订阅后弹应用内通知。
- **场景注册**：场景插件在启动时向引擎注册 `{ id, label, intro, examples[], compose(input, ctx) → prompt, steps[], toolStepMap, deliverableKinds, verifyPrompt, homeWidget }`。注册走 cordis 服务：引擎 `ctx.provide('myworkTasks')`，场景插件 `inject: ['myworkTasks']`（下面确认 dsh 的 cordis 是否支持，否则退到全局事件注册）。

### 场景插件

一个场景就是一个 kit 成员，最少提供一个 `compose` 和几条示例。现有成员的归宿：

| 现有成员 | v2 里的角色 |
|----------|-------------|
| dsh-mywork-oracle（交易） | 场景「交易」：市场温度看板、标的、报告交付物、核验提示词 |
| dsh-univer-office | 场景「办公」：表格 / 演示文稿交付物 |
| dsh-mywork-browser | 能力，不是场景：给所有任务用的真实浏览器；场景「调研」用它交付网页摘要 |
| dsh-mywork-schedule + dsh-automation | 「例行任务」：按时创建任务（早盘简报、每周汇总） |
| dsh-mywork-im | 通知渠道 |
| dsh-mywork-mcp、dshmarket、dsh-mywork-kit 成员管理 | 退到设置 |
| dsh-mywork-codex-ui | 壳：今日 / 任务 / 交付物 / 场景 / 设置 |
| dsh-mywork-shell | 风格 |

### 前端

codex-ui 的发行版模式扩成「v2 模式」：侧栏是四页加设置；今日页替换新建对话 hero；任务列表替换会话列表；交付物页新增。dsh 的模型选择器、访问模式、Agent Team、轨迹在 v2 模式下隐藏；模型档位由场景给（快问轻档，交付重档）。

## 4.5 例行：系统主动的那一半

Manus 是你发起它去做；Muse Code 和 OpenMuse 多了一半：**它替你盯着**。Muse Code 有目标跟踪观察者，OpenMuse 有 Goals & Tracking。搬到 MyWork：

- 一句带时间的话就是例行，不需要 cron 表：「每天 9 点…」「每周一…」「工作日 18 点提醒我…」「30 分钟后提醒我…」。
- 例行任务每次运行拿着上一次的交付物，先说**变化**。没变化的运行安静地存着，不通知、不推飞书；有变化才进「等你看」。打扰的单位是变化，不是运行。
- 提醒是退化的例行：不跑 agent，到点进「等你看」，点「知道了」才消失。
- 每次运行留回执，例行页能看每一次的结果。

## 5. 分期

1. **任务引擎**：tasks.json、创建 / 列表 / 详情路由、会话执行与步骤推进、`deliver` 工具、完成事件。前端：今日页的输入框与任务卡、任务页。用一个内置的通用场景（「随便问」）先跑通。
2. **交付物**：交付物页、Markdown 渲染、导出图片 / PDF、评价。
3. **核验**：第二会话核对，徽章。
4. **场景注册**：把交易（oracle）、办公（univer）、调研（browser）接成场景；今日页的场景看板；例行任务生成任务。
5. **去缝**：隐藏 dsh 的对话式控件；名字收敛；README 与演示重做。

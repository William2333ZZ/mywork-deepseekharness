# MyWork · 产品矩阵与生态

> **2026-10-05 更新**：这份文档写在同事模型之前。「内核 / 领域包 / 发行版」在同事模型下的写法，以及 AI 版和金融版两个产品的结构，见 [v2/EDITIONS.md](v2/EDITIONS.md)。下面的内容保留作历史记录。

> 一句话：**一个内核，多个发行版，一个领域包生态。** 内核是「任务 → 交付物 → 核验」的个人工作 agent；发行版是内核加一个领域包再加一套开箱即用的形态；领域包是第三方也能写的东西。

配合 [MYWORK-V2.md](MYWORK-V2.md)（形态）读。这份回答「做几个产品、怎么分层、别人怎么参与」。

## 1. 为什么不是「场景」

v2 第一版让用户在输入框里先选「通用 / 对话 / 调研 / 办公」。这是把系统该做的判断推给了人：Manus 不问你这是调研还是办公，Grok 不问你这是聊天还是任务。所以：

- 用户面前只有一个框。该回答就回答，该交付就交付，有浏览器就上网，有 Univer 就出文件。这些是**内核自己判断**的事。
- 「一类事怎么做」仍然存在，但它不叫场景，叫**领域包**，是生态的单元，不是界面的选项。领域包通过 `match(input)` 认领自己认识的输入；用户不选，最多在任务卡上看到一个标签，可以换。
- 发行版可以把某个领域包设成默认（交易工作台里一切输入先归交易包）。

## 2. 三层

```
┌─────────────────────────────────────────────────────────────┐
│ 发行版  Distributions   交易工作台 · MyWork（通用）· 后续垂直版      │
├─────────────────────────────────────────────────────────────┤
│ 领域包  Domain packs    交易 · 调研 · 内容 · 办公 · …（第三方可写）   │
├─────────────────────────────────────────────────────────────┤
│ 内核    MyWork Kit      任务引擎 · 交付物 · 核验 · 壳 · 能力成员      │
│                          （浏览器 · 办公文档 · IM · 定时 · MCP）      │
├─────────────────────────────────────────────────────────────┤
│ 底座    DeepSeek Harness (dsh) + 社区插件（dshmarket）             │
└─────────────────────────────────────────────────────────────┘
```

### 内核：MyWork Kit

不改 dsh 本体，全部是插件。对外只有三个词：任务、交付物、领域。

| 成员 | 角色 |
|------|------|
| dsh-mywork-tasks | 任务引擎：无头会话、步骤与活动流、`deliver`、核验会话、追问、`myworkTasks` 注册服务 |
| dsh-mywork-codex-ui | 壳：v2 侧栏（新任务 / 今日 / 任务 / 交付物 / 领域）、任务页、设置分组 |
| dsh-mywork-shell | 风格与缩放 |
| dsh-mywork-browser + 官方 browser-use | 能力：真实浏览器 |
| dsh-univer-office | 能力：表格 / 文档 / 幻灯片 |
| dsh-mywork-im + dsh-im-connect | 能力与通道：飞书 / 微信收发，任务完成推送，反向从 IM 下任务（待做） |
| dsh-mywork-schedule + dsh-automation | 例行任务：按时创建任务（待接） |
| dsh-mywork-mcp | 能力：MCP 连接器 |
| dsh-mywork-kit | 成员管理与安装 |

内核自己带的「通用」做法就是一个领域包，只是内置的。

### 领域包：生态的单元

一个领域包 = 一个 dsh 插件，`inject: ['myworkTasks']`，注册：

```js
ctx.myworkTasks.register({
  id, label, intro, examples,
  match: (input) => boolean,            // 认领输入；不写就只能被发行版设为默认
  compose: (input, ctx) => prompt,      // 这类事怎么做
  toolStepMap,                          // 工具调用 → 步骤名
  deliverableKinds, renderer?,          // 交付什么、怎么画（默认 Markdown）
  verifyPrompt?, verify?,               // 怎么核验
  permission?, model?,                  // 权限与模型档位
  homeWidget?, routines?,               // 首页看板、例行任务（待做）
})
```

领域包还可以带自己的工具（`ctx.tools.register`）、数据源、设置页和首页看板。它们和普通 dsh 插件一样发布到 npm，出现在 dshmarket 里，装进 profile 就生效。

第一批（按优先级）：

| 领域包 | 交付物 | 核验 | 数据 / 能力 | 状态 |
|--------|--------|------|-------------|------|
| **交易研究** | 概率报告、每日简报 | 数字对得上数据源；事后打分成胜率 | 十三个免费交易数据源（packages/oracle） | 已有，待从 digital-oracle-work 迁成包 |
| **调研** | 带来源的摘要、对比表 | 每个事实有网址 | 真实浏览器 | 目前折在通用里，做重了再拆 |
| **内容** | 文章、视频脚本、发布计划 | 事实与引用可查、平台规则 | 浏览器、办公文档 | 待做 |
| **办公** | 表格、纪要、幻灯片 | 数字可追溯、待办闭环 | Univer、飞书文档 | 目前折在通用里 |
| **个人运营 / 客服** | 回复稿、FAQ、周报 | 口径一致 | IM、知识库 | 待做 |

### 发行版：给一类人的成品

发行版 = 内核 + 一个或几个领域包 + 默认设置 + 名字和外观 + 安装形态。

| 发行版 | 给谁 | 默认领域包 | 形态 |
|--------|------|-----------|------|
| **MyWork** | 有电脑、有很多杂事要交付的个人 | 通用 | Web / 桌面 |
| **交易工作台** | 有持仓、没研究团队的个人投资者 | 交易研究（默认认领一切输入） | 桌面 + 飞书简报 |
| 后续：内容工作台、调研工作台 … | 自媒体 / 分析师 | 内容 / 调研 | 同上 |

发行版的差异只在 `kit.json`（装哪些成员、默认领域包、名字）和一份 README；代码不分叉。交易工作台分支现在还是「改了壳的 kit」，下一步是反过来：壳不改，只装交易包。

## 3. 一件事在生态里怎么流动

```
用户一句话 ──▶ 路由（领域包 match / 发行版默认 / 通用）──▶ 任务（无头会话）
      ▲                                                         │
      │                                              工具：能力成员 + 领域包工具
      │                                                         ▼
   追问 ◀── 任务页 ◀── 通知（应用内 / 飞书）◀── 核验会话 ◀── deliver ──▶ 交付物
                                                                  │
                                              评价、导出、例行再跑、被下一次任务引用
```

## 4. 形态矩阵

| 形态 | 现状 | 缺什么 |
|------|------|--------|
| Web（dsh web） | 有 | |
| 桌面（Electron，apps/desktop） | 有 | 按发行版出包 |
| 飞书 / 微信 | 只有推送 | 反向：在 IM 里下任务、收交付物 |
| 例行任务 | dsh-automation 独立跑 | 让它创建任务，产出进交付物 |
| 命令行 / API | HTTP 同源 API | 给脚本和其他 agent 用的 token API |

## 5. 别人怎么参与

- **写领域包**：一个 npm 包，几十行注册代码就能上线；模板放在 `packages/tasks/README.md`。
- **写能力成员**：普通 dsh 插件，注册工具即可，内核的通用做法会按能力自适应（有浏览器就用浏览器）。
- **做发行版**：fork 一份 `kit.json` 和 README，指定默认领域包，跑 `scripts/install.sh`。
- **贡献核验规则**：领域包的 `verifyPrompt`，或者内核里的通用核验项。

## 6. 顺序

1. 把交易工作台改成「内核 + 交易包」：`packages/oracle` 注册 `myworkTasks`，`match` 认领标的与宏观问题，报告成为交付物，市场温度成为首页看板。
2. IM 反向：飞书里说一句话就是任务，交付物推回去。
3. 例行任务创建任务。
4. 领域包模板与 dshmarket 分类。
5. 内容 / 调研两个包。

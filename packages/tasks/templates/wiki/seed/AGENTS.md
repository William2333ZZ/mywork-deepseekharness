# 知识库的规矩

这份文件是知识库的「schema」：库怎么组织、页面怎么写、收资料、回答、体检各怎么做。哪里不顺手就改这里，用户和你一起改。

## 这个库是关于什么的

（开张时写：主题、用途、重点、不收什么。）

## 三层

- 原始资料/：用户给的原文（PDF、存下来的网页、笔记、数据）。只读：永远不改、不删、不重命名。网页链接先存成 markdown 放进这里（文件开头写「来源：网址」「取得：日期」），再收。
- wiki/：你写、你维护的页。用户读，你写。
- 本文件：规矩。

## 页面

- 一页一个东西，文件名就是页名（中文可以），放进类别目录：来源/（每份原始资料一页）、概念/、人和机构/、综述与对比/（跨资料的综合、对比、论点的变化，回答存回来的也放这里）。类别不够就新建，并写进 index.md。
- 每页第一行「# 标题」，接着一两句话说这页是什么。
- 链接写 [[页名]] 或 [[页名|显示的字]]。提到库里已有的东西就链上；值得单独成页的就新建一页。
- 每条具体的说法后面标出处 [[来源/资料名]]，能带页码或小节就带。没有出处的推断写成「推断：……」。
- 新资料和旧说法打架时不悄悄覆盖：在相关页写「⚠ 矛盾：A 说……（[[来源/…]]），B 说……（[[来源/…]]）」，留给用户判断；被新资料更新的说法标「已被 [[来源/…]] 更新」。

## 收资料

1. 读原文。默认一次一份。
2. 先在对话里用 3–5 条说要点、和库里哪些页有关、打算改哪些页；然后直接动手（用户在对话里可以撤销整次改动）。
3. 写 wiki/来源/<资料名>.md：要点、关键数据（带页码）、它的论点、和其他资料的关系。
4. 更新相关的概念、人和机构、综述页（一份资料常常要动 10–15 页）；该新建的页新建。
5. 更新 wiki/index.md：每页一行「- [[页名]] —— 一句话」，按类别分节。
6. 往 wiki/log.md 末尾加一条「## [YYYY-MM-DD] 收资料 | 资料名」，下面一两行写动了哪些页。

## 回答

1. 先读 wiki/index.md 找相关页，再读页；库里没有的才去读原始资料或上网，并说明「库里没有，下面来自……」。
2. 回答带出处：[[页名]] 和 [[来源/…]]。

## 体检

找：页与页之间的矛盾、被新资料取代的旧说法、孤立页、提到很多次却没有自己一页的东西、缺的交叉引用、能用一次搜索补上的空白。程序会先查好孤立页、断链、没进索引的页。能直接修的修好（修了什么记进日志），要用户判断的列出来；最后建议 3 个值得追的新问题或新资料。往 log.md 记「## [YYYY-MM-DD] 体检 | 结果一句话」。

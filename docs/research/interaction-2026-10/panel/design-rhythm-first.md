# MyWork 交互设计：节奏和看的人

## 核心主张

1. 同事只在两种时候开口：你的东西出了「事实变化」（换了说法不算），或者有一件只有你能办的事。其余的活照做、照记，但不出声。
2. 「你的东西」要写下来，落在两张表里。一张是清单：持仓、在用的模型和依赖、课题。另一张是判断：假设、决定、前提，每条都带重审条件。每条变化都要指明动到了哪一行，指不出来的就进「看过」，用户看得见，但同事不出声。
3. 有没有变化，由脚本在调用模型之前判断，不再看模型最后一行写没写「变化：无」。第一次运行一律是基线。静默只是不打扰，任何东西都不藏。
4. 说话分三档。立刻说：运营类变化、碰到重审条件、只有你能办的事，走 IM。到你读的时候说：其余绑定到你东西上的变化，汇进 MyWork 对话里的「今天」卡；这张卡由代码拼，不由模型写。不说：记进「看过」。
5. 「需要你」是界面上唯一带数字的地方。例行也能往里放东西，但不挡活。同一个阻塞，所有同事加起来只出一次。它靠事实解决（登录成功就自动消失），或靠你的一句话解决，不靠一条条清掉。
6. 把判断记下来，是为了日后叫回来：条件碰到了或到期了，同事带着当初的依据和新事实来问你「维持 / 改 / 延后」。
7. 交付物里的每个数字都是一条带出处的「论断」。机器先做字面核查，再交给另一家模型挑错，然后按风险排好顺序给你。你一条一条核；纠正记在那一条上，下次交付前的检查会用到它。
8. 规矩要你点头才进长期记忆。用到了或拦下了错，交付物上会写明。
9. 长事先给计划和费用估算，然后按步骤跑：每步一轮，状态存在文件里。中途改方向，在下一个步骤边界说清哪些保留、哪些作废。
10. 单位仍是同事。清单、判断、计划都在同事的文件夹和对话里，没有任务页，也没有全局看板。手机上只做三件事：读「今天」，办「需要你」，点一下重审和核对。

---

## 0. 用词

新加四个用户看得见的名词：**清单、判断、变化、计划**。改一个名：「它记住的」改叫**规矩**。其余沿用现有的：同事、对话、例行、文件卡、找你卡、需要你、文件夹、表。「论断」和「出处」是交付物内部的行，不算新对象。

## 1. 对象模型

### 1.1 一览

| 东西 | 是什么 | 存在哪（同事文件夹内，除注明外） | 界面在哪 | 生命周期 | 为什么现有的不够 |
|---|---|---|---|---|---|
| 同事（不变） | 一条对话 + 文件夹 + 例行 + 规矩 | 现有 | 现有 | 现有 | — |
| **清单** | 你的东西：持仓 / 在用 / 课题。每行一个对象，有唯一的负责同事 | `清单.csv`（表头由模板定，中文，只往后加列） | 右栏「资料」第一栏（显示行数，点开就是表）；变化卡上的「动到」 | 第一次见面时建立。行由你加，或由同事提议、你确认。不删行，只把「启用」改成否 | 现在同事并不知道哪些东西是「你的」。变化没有东西可以挂，只能写成新闻（任务书 3.2-3、调研 F9「只看相对我的框架变了什么」；research-keeping-up 需求 1「也不会告诉你自己的哪个业务在用」） |
| **判断** | 你持有的一条假设、决定或前提，带依据、没选的方案、重审条件和到期日 | `判断.csv` | 资料第二栏「判断 n · 待重审 m」；重审卡 | 由你写下，或同事提议、你确认，此后只改状态。要「改」就新增一行取代旧行，旧行指向新行（ADR 的做法）。状态：有效 → 待重审 → 维持（回到有效）/ 已改 / 已撤 | 现在计划、决定、口径没有落点（kernel: memory）。技术经理要求「决定的依据要留得住、到期重审」（任务书 2.4，research-decisions 需求 6：没人对 AI 选型做事后对照）。投资者要求判断能结算（understand-finance crossCutting：判断必须在下的时候就写成结构） |
| **变化** | 一条绑定到清单行或判断的事实变化，带出处、类别、档位 | `变化.csv`（只追加；「看过」的也记，档位标「看过」） | 对话里的变化卡；「今天」卡；搜索 | 生成后档位就不再改。没有「已处理」状态，不需要清 | 现在的例行产物是一整份简报，变化埋在正文里（realUse #8：一个早上 26,702 字）。「没有变化」靠模型写一行字，会把真东西藏掉（realUse #9） |
| **需要你** | 只有你能办的一件事：登录、拍板、重审、核对存疑、签收、预算 | 共享：`$DSH_HOME/mywork/needs.json` | 对话里的卡片；同事头像上的红色数字；铃铛「需要你」；「今天」卡第一段 | 打开 → 解决（事实成立，或你答了一句）/ 延后到某天。批准、重审、接手这三类永远不自动过期 | 现在例行不能提问（engine.js ask() 直接拒绝），阻塞只能写进报告正文，一拖 4 天（realUse #10） |
| 交付物（扩展） | 成稿：一份 Markdown 加论断清单，有版本 | deliverables.json 照旧；另写一份 `交付/<系列>-v<n>.md` 加 `.claims.json` | 文件卡（卡上显示核对进度，不再是 6 行关键数字）；阅读视图加核对栏 | v1 → v2 → …，新版取代旧版。文件页和搜索默认只出最新版，旧版用「前一版」打开 | 现在没有版本（breakpoint 8），数字和出处不成对（breakpoint 1），同事自己也读不到旧交付物（breakpoint 4） |
| 表（扩展） | 同事维护的底稿，每行带出处列：出处、出处日期、摘录 | `底稿/*.csv` | 右栏「电脑 → 它维护的表」（清单和判断置顶） | 照旧；体例由模板固定 | 表是现有形式里最稳的累积物（strengths #2），只缺出处列和固定词表（realUse #13 的「级别」两套词） |
| **计划** | 一件长事的步骤、来源、交什么、停在哪、估算，加进展日志 | `计划/<日期-题目>.md`（含步骤状态）加 `进展.md` | 对话里的计划卡（原地更新）；资料栏「手上的计划」 | 草稿 → 进行中 → 停在检查点 / 等你 → 交付 / 停止。文件一直留着 | 现在单轮 20 分钟封顶，超时就失败，没有检查点（breakpoint 7） |
| **规矩**（改名） | 这位同事的长期规则，分四节：口径 / 来源 / 格式 / 教训。每条带日期和出处链接 | AGENTS.md 分节；草稿放 `.mywork/规矩草稿.json`（不载入） | 资料栏「规矩」，可以就地增删改；「待你确认 n」 | 草稿 → 记下 → 你改或删 | 7 天只记了 3 行，全是偏好，没人审，界面上也改不了（realUse #12） |
| 纠正记录 | 一次纠正，记在某一条论断上 | `纠正.csv` | 论断行上的「按纠正 #n」标签；资料栏「它最近错过的」 | 只追加 | 「把一次具体的纠错记到那条事实上」，没有任何项目做过（任务书 4.3） |
| 关于我（搬进界面） | 所有同事都读的一份：你是谁、你什么时候读、什么事要立刻告诉你、你向谁汇报、写作偏好 | `$DSH_HOME/AGENTS.md`（现有） | MyWork 的资料栏可改；其他同事的资料栏只读显示，旁边有「去 MyWork 改」 | 你改 | 现在它在产品界面之外，和 MyWork 自己记的口径还不一致（realUse #12） |

### 1.2 不加什么

- **不加「研究项目」层。** 一次深度研究 = 一个计划 + 它交出的成稿。项目这一层就是同事本身：一位同事管一个覆盖范围或一个课题。依据：买方分析师的自建体系指出，按公司另开项目会造成孤岛，没法跨公司、跨季度关联，知识应该按覆盖范围整体建（understand-finance：「美股大白话」第 7 条）；ARIS 的技能默认工作目录就是一个课题的根（understand-ai：dsh-aris）。
- **不加独立的「事实表」对象。** 事实落在两处：交付物的论断清单，以及底稿表的出处列。再单设一张会和底稿重复（推断）。
- **不加任务、收件箱、看板。** 负责人否决过（任务书 1）；外部也有现成的反面例子：Vibe Kanban 关闭，agent-inbox 归档（任务书 4）。

### 1.3 文件夹的样子

```
mates/<id>/
  AGENTS.md          规矩（口径/来源/格式/教训）
  清单.csv  判断.csv  变化.csv  纠正.csv
  底稿/              同事维护的表（带出处列）
  交付/              成稿副本 + 论断清单（引擎写）
  计划/  进展.md
  材料/              你拖进来的文件
  快照/              抓取的原文；被论断引用的永久保留，其余 30 天后清理；界面上折叠
  .mywork/checks/    例行预检脚本（Node）
  .dsh/skills/       只给这位同事的技能
```

依据：技术雷达 4 天积了 101 个文件，其中 99 个是原始抓取，把右栏淹了（realUse #14）。

## 2. 第一次见面

**入口。** 有三个：用户点「+」后选模板；仍可以只写一句职责（现有方式保留）；或者用户对 MyWork 说一件长期要盯的事，MyWork 照旧用选项卡问「新建同事 / 你来做就行」（strengths #6）。

**第一步：开工单卡**（结构化表单，不靠模型提问）。依据：自我介绍那一轮不能提问（engine.js introPrompt）；叶青的首次定制是 4 轮对话，加上 client_rules.md 的 TEMPLATE→ACTIVE 门禁，是唯一把「开工前人要给什么」做成流程的（understand-finance）；Rakazo 新建 bot 时会先问你几个问题（survey-persistent）。卡上最多三问：

```
开工 · 持仓研究
1 你的东西      [粘贴代码或名称]  [拖入文件]        例：600519 茅台 3成
2 这些事立刻告诉我（模板预勾）
   [x]减持增持 [x]问询函/处罚 [x]停复牌 [x]业绩预告与修正 [x]实控人变更 [ ]大宗交易
3 其余的什么时候给你看   交易日 08:30（取自关于我，可改）   每月预算 ¥30（预计 ¥8–15）
                                                      [交给它]
```

技术选型模板的第 1 问可以拖入 `package.json`、`requirements.txt`、网关配置（one-api / new-api / LiteLLM 的配置文件）和上月 API 账单 CSV。课题模板的第 1 问是一句话的贡献点、3–5 篇种子论文（arXiv 号或 .bib），以及投稿截止日期。

**第二步：同事回一张清单确认卡**（这已经是用户发起的一轮，可以问）。卡上是表的前 10 行，每行有一列「怎么知道的」（你粘贴的 / 从 package.json 读到的 / 从账单读到的）。名称有歧义时走主体确认：唯一命中就自动锁定，否则最多给 5 个候选让你选，选定后只用代码和信用代码（照企查查的交互，understand-finance）。按钮是「对 / 我改一下（打开表）」。

**第三步：最多三条判断草稿。** 只从你说过的话里提，不替你下判断（任务书 2.1「判断不交」）。例如：

```
想记成判断？  J-01 假设：宁德的增长主要来自储能
   依据：你 10/06 说的   重审条件：储能出货同比 < 20%（季报）   到期：2027-04-30
   [记] [改一下] [不记]
```

这一步可以整个跳过。

**第四步：开工卡。** 一屏写清：我盯什么（12 只）；什么事立刻说；其余几点说；没变化不出声，但「今天」卡里会有一行「看过 n」；读不到的来源会列出来；每月大约花多少、上限多少；用哪些来源。只有一个按钮「开工」，不设倒计时。开工这一步只发生一次，等一下的代价很小（推断）。

**第五步：马上出基线。** 不等到明早。第一份是「基线：12 只的现状已记下，以后只报相对这份的变化」，再回补最近 3 个交易日里绑定到这 12 只的变化（EDITIONS 4：「第一份不用等到明早」）。基线永远出声，因为第一次运行没有「没变化」可言。依据：产品雷达第一次运行写了「变化：无」，结果被整轮藏掉（realUse #9）。

目标是从点「+」到看到基线不超过 10 分钟（EDITIONS 8 阶段 0 的过关标准；OpenClaw 退潮的第一原因是装上之后用不上，任务书 4）。

## 3. 日常节奏

### 3.1 说话规则：什么时候说、说什么、对谁说

| 档位 | 什么时候 | 说什么 | 对谁、经哪里 | 谁定 |
|---|---|---|---|---|
| 立刻 | 发生时 | ① 运营类变化碰到清单行（技术选型：下线、调价、改名或重定向、限区域、封号、工具下架；持仓：开工单勾选的公告类别；课题：撞题论文）；② 变化碰到某条判断的重审条件；③ 只有你能办、且有截止日期的事 | 你；同事对话 + IM 推送（packages/im 现成）+ 手机打开时置顶 | 类别由模板预设，你在开工单或关于我里改；档位由代码按类别判，不由模型判 |
| 到你读的时候 | 关于我里的「读的时间」 | 其余绑定到你东西上的事实变化；到期结算 | 你；同事对话里随时可看，但不推送；到点汇进 MyWork 的「今天」卡 | 代码 |
| 不说 | — | 重复、噪音、换了说法、和清单无关的 | 记进「看过」，在卡底折叠并显示条数 | 代码判重复，模型判噪音和说法（模型只能往「看过」里放，不能往上放） |

另外还有一类听众：**你要转给的人**（CFO、出资人、导师、团队）。同事只写草稿，标明「给谁看」并用外行话写，由你来发。对外发送永远是批准卡，并且永不自动续跑（见 3.4）。

依据：
- ChatGPT Pulse 从 2025-09-25 上线到 2026-06-17 下线，改成用户自己定义的定时任务，监测类只在有值得报告的事时通知（survey-briefing shifts）。所以本设计里没有一条主动内容不是用户自己定义的清单或判断引出来的。
- 技术经理是事件驱动的，免费渠道够用，要第一时间知道的是运营类变化（任务书 2.4；research-keeping-up surprises）。
- 用户付钱是为了少收到东西（Simon Willison 的付费档，research-keeping-up）。
- 「换了说法就报有变化」是反面做法（任务书 4.2）。只比证据、不比措辞，借自 ai-berkshire 的 thesis-drift。

### 3.2 例行到点之后

例行仍然是「到点替你发给某位同事的一句话」（strengths #3），中间加一个**预检**：

1. 引擎先跑这条例行的预检脚本（Node，模板自带，放在 `.mywork/checks/`）。脚本按清单逐行去读规定的来源，存快照，和上一次比较，输出 `{变化:[{事件键, 清单行, 类别, 摘要, 出处, 日期}], 未读到:[{来源, 原因}], 看过: n}`。
2. 没有变化：**不调用模型**。运行记录里写一行「看过 41 · 无与你有关的变化 · 未读到 1（x.com：要登录）」。对话里不出东西，「今天」卡的末尾累加一行。
3. 有变化：调用模型，把变化 JSON 当素材。模型的活只有四件：打开一手出处确认；判断是事实变了还是说法变了；对照判断表看有没有碰到重审条件；用新工具 `mywork_change` 写变化记录并出变化卡。最后由代码按类别定档位。
4. 来源没法用脚本读的（要登录的社交平台、开放检索），照旧由模型做。但产出必须走 `mywork_change`，而且必须填「动到」。填不出「动到」的自动进「看过」。

变化卡（同事对话里）：

```
变化 · 2 条动到你的东西                              交易日 08:30
宁德时代（持仓 3成）  实控人一致行动人拟减持 ≤1%         立刻
  碰到 J-01 的重审条件？否；碰到「大股东减持」提醒类别
  出处 巨潮 10/05 公告 第2页「……不超过1%……」  [看出处]
比亚迪（自选）  三季度储能出货同比 +34%                  到点
  动到 J-04「储能出货同比 ≥ 25%」：仍成立
  出处 公司投资者关系纪要 10/05  [看出处]
看过 63 · 重复 12 · 噪音 47 · 换了说法 4                 [展开]
未读到 1：x.com（要登录，见「需要你」）
```

每行可以做三件事：「看出处」（在实时浏览器里打开，或打开快照并高亮摘录）；「这类以后不报」（写进规矩·来源，出一行小字）；「改判断」。没有「已读」「完成」这类按钮。

依据：
- 例行先跑脚本、没变化不叫模型，是现成的易加项（任务书 3.3；index.js runRoutine 已有提醒类的分支）。安静的运行照样花掉一次完整的模型费用（kernel: routines；EDITIONS 6-5：40 次例行只有 2 次安静）。
- 三分法加「被筛掉的也看得见」（patterns：鸣山的重复 / 噪音 / 新变化；dailypaper-skills 在页尾列出被排除的及原因；国内研究者「怕漏」，user-needs 6.9 第 1 点）。

### 3.3 「没有变化」

- **由谁判、凭什么判**：由脚本判，看的是清单行上的结构化差异。模型最后一行的「变化：无」不再参与判断（engine.js quietFor 改写）。
- **静默的含义**：只免掉推送和未读点。这一轮如果交了文件，文件照样进文件页和搜索（改 index.js shownFile）；右栏运行记录里「没有变化」那行可以点开，展开是这次看过什么、没读到什么。
- **第一次运行算变化**：一律是基线。
- **读不到不等于没变化**：「未读到」单独一行，灰色。同一来源连续两次读不到：如果是你能解决的（登录、key），升级成「需要你」；不是的，写进规矩·来源里那一行的状态。依据：EDITIONS 6-8「没读到和没有新消息现在分不开」；realUse #10（X 连续 4 天被拦）。
- **对事件驱动的读者给一行心跳**（可选，技术选型模板默认开）：每周一的「今天」卡里写「上周检查 214 次 · 无影响你的变化 · DeepSeek、百炼、智谱、OpenAI、Anthropic 都读到了」。依据：research-keeping-up 需求 9「想确认不追也不会错过」（强）。这一行由代码拼，不花模型的钱。

### 3.4 只有你能办的事

新工具 `mywork_need`，例行运行里也能调用。它**不挡活**：同事接着按默认做完，只把这件事挂出来。几种类型：

| 类型 | 卡片上写什么 | 怎么消失 |
|---|---|---|
| 登录 / 接手 | 哪个来源、哪几位同事卡在这、不管的后果（「x.com 停用，覆盖行会写缺」）。按钮：去电脑上处理 / 今晚提醒我 / 不管它 | 下一次抓取成功时自动消失，对话里出一行「x.com 已恢复」；或者你点「不管它」 |
| 重审 | 见 7.3 | 你选维持（必须写一句理由）/ 改 / 延后到某天 |
| 核对存疑 | 某份交付物里，第二方判「对不上」且驱动结论的论断 | 你在核对栏里处理 |
| 签收 | 要交给别人的周报或日报草稿 | 你签收，或者说改哪里 |
| 预算 | 撞上限，见 10 | 你选一项 |
| 拍板（现有的找你卡） | 用户发起的事里的问题 | 照旧 |

规则如下：

- **同一个阻塞只出一次。** 阻塞按资源记（比如 `x.com 登录`），每位受影响的同事对话里各有一张引用同一条记录的卡；在任何一处解决，所有地方都消失。依据：两位雷达被同一个 X 登录各自卡住（breakpoint 12）。
- **报告正文里不再重复写阻塞**，只写一行「x.com 未读到（见需要你）」。
- **批准和接手永不自动续跑。** 现在 24 小时没人答会按假设继续，批准类也不例外（engine.js 826-840），这对有后果的动作是错的。文字和选择题照旧可以自动续，前提是问题里写明了默认怎么做。
- 「需要你」可以延后到某天（借 Linear 的 Snooze），**不能一键全清**。重审没有「别再提醒」。

### 3.5 几位同事早上一起交东西

- **一个人只有一个读的时间。** 各位同事按各自来源的节奏去跑，跑多早都行；到点的变化在各自对话里随时可看，但统一到「读的时间」才汇总。只有「立刻」档会推送。依据：现在 3 条例行同在 9:00、并发 2、排队 60–91 秒，晨报 8:40 出，看不到 9:00 那三位（realUse #8）。
- **「今天」卡**放在 MyWork 的对话里，由代码在读的时间拼出来，不调用模型：

```
今天 · 10/08 周三 08:30
需要你 2
  x.com 登录 · 技术选型、课题都卡在这           [去电脑上] [今晚提醒]
  J-03 到了重审条件 · 技术选型                  [看]
变化 5
  技术选型  DeepSeek-V3.2 10/22 下线（客服、代码审查在用）      立刻·07:10已推
  持仓研究  宁德 实控人一致行动人拟减持 ≤1%
  持仓研究  比亚迪 储能出货同比 +34%，J-04 仍成立
  课题      2 篇相关新论文（另有 1 篇撞题，见课题）
  宏观周报  周报草稿待签收（另见需要你）
没开口：看过 139（持仓 63 · 技术选型 45 · 课题 31）
昨天花费 ¥3.20 · 本月 ¥41 / ¥150
```

  - **排序**：需要你在前，有截止日期的排最前；变化部分立刻档在前，再按清单行的权重排（仓位、在用的月花费、课题权重）。每位同事最多 3 行，多出的写「还有 4 条」并链到它的对话。整张卡控制在手机一屏内。依据：买方分析师要的是 5 分钟看完、知道当天先做什么（understand-finance「美股大白话」）；鸣山每天只把两三条上交给人（patterns）。
  - **每行都跳到那位同事对话里的那一轮并高亮**（沿用唯一的跳转规则，strengths #9）。
  - **你打开之前，卡片原地更新**；打开之后再来的，以「08:52 补：……」的形式追加在卡底，不另起一张卡。
  - **跨同事去重**：同一个事件键在两位同事的清单里都出现时，「今天」卡只出一行，后面列出两个名字。
  - 它**不是看板**：只是 MyWork 对话里的一条消息，没有勾选，没有「全部已读」；明天它就是历史记录。依据：用户喜欢总管式的汇报（任务书 4）；现在的晨报自己说了没有依据的话，而且漏掉 9:00 的同事（realUse #11、breakpoint 5）。用代码拼可以同时解决这两个问题。
- **MyWork 默认的「晨报 08:40」由「今天」卡取代。** 周报保留为可选，仍由模型写，但必须引用各位同事的那一轮和论断。

### 3.6 手机上的 5 分钟

手机只做三件事：**读「今天」**、**办「需要你」**里能在手机上办的（重审、签收、批计划、核对高风险的几条）、**跳进去看某条变化的出处**。登录和接手只能「今晚提醒」（手机不做电脑画面，TEAMMATES 9.6）。具体走法见场景 5。

### 3.7 交给别人的周期产出

宏观固收的日报周报、信用的负面监控、一级市场给出资人的报送，是「替别人写的东西」，到点必出（任务书 2.1；user-needs M1、M4、V1）。它们照常出，只是文件卡下多一个「签收」的需要你，签收前不会发给任何人。依据：周期性产出缺的是「带出处、能签字、有变化才叫人」（user-needs F4）。

## 4. 核对

### 4.1 论断：核对的单位

`deliver` 的 `data.claims` 用来放结构化的论断（字段已经存在但没人读，kernel: deliver）：

```
{ id:"C12", 正文:"2025年毛利率31.2%", 值:31.2, 单位:"%", 期间:"2025",
  类型:"事实|估算|推断", 驱动结论:true,
  出处:{种类:"pdf|网页|表|你给的", 位置:"材料/宁德2025年报.pdf", 页:47, 摘录:"…31.2%…", 取于:"10/06"},
  算式:{脚本:"计算/c12.mjs", 输入:["C3","C7"]} | null,
  状态:"对上|对不上|没查到|查询失败|未绑定", 第二方:"支持|弱|不对|拿不准", 你:"对|不对|未看" }
```

正文里的数字带 `[C12]` 标记。依据：「事实包先于成文，写的人只许引用事实编号」（天风，patterns）；「先落底稿再写成稿，撰写只吃底稿」是所有认真流程的共同点（understand-finance crossCutting）。

### 4.2 机器先做的三层（不能是同一个模型审自己）

1. **数字门禁**（在 engine.deliver 里，脚本做）：正文里带单位的数字必须对得上某条论断，对不上的退回给同事重做。计算类论断必须带算式脚本。依据：交付前在 deliver() 里拒收是现成口子（kernel cheapExtensions）；go-stock 的事实门禁、ai-berkshire 的 financial_rigor.py（understand-finance）。
2. **字面核查**（脚本做）：值必须出现在摘录里，摘录必须出现在出处原文里（PDF 用 liteparse 抽出的文本，网页用抓取时存的快照）；期间早于已知最新一期的标「可能过期」；和纠正记录冲突的拦下（见 5.3）。做法和代码借 dsh-research-verify（零宿主依赖，移植到 Node）。
3. **第二方挑错**：开一个新的只读会话，换一家模型（「核对用的模型」在 MyWork 设置里填，比如 Kimi / Qwen / GLM 的 key）。只给它论断清单、摘录和原文路径，让它自己去读，**不给执行方的自述**，每次都新开。它逐条判「支持 / 弱 / 不对 / 拿不准」，并摘出自己找到的原文句子。范围是全部驱动结论的论断加上其余的随机抽样，总量写进计划的估算里。没配第二家 key 时，用同一家模型的新会话，卡上写明「同一家模型，独立会话」。依据：ARIS 的硬规则是每轮新开线程（沿用旧线程时分数从 3/10 虚涨到 8/10），并且禁止把「我修了什么」传给审稿方（patterns）；现有的核验看不到工具返回，用的又是同一个模型（kernel: verification）。

### 4.3 给人的核对栏（桌面）

阅读视图不再替换整个中栏，改成「正文 | 核对栏」两列（改 client/index.js ReadingView）。核对栏**按风险排序**，这是任务书 4.3 列出的空位，规则由我们自己定：

1. 第二方判「不对」或字面「对不上」的；
2. 驱动结论、但只有一个来源的；
3. 两个来源打架的（相差超过 1%，ai-berkshire 的阈值）；
4. 计算得出的（展开显示输入和脚本）；
5. 二手来源（聚合站、媒体转述、厂商自报）；
6. 估算和推断；
7. 其余。

每行写：编号、一句话、状态，以及第二方的一句意见。点一行，正文滚到 `[C12]` 并高亮，出处在右栏「电脑」里打开：网页在实时浏览器里开；PDF 送进实时浏览器并试 `#page=47`（未验证）；表就高亮那一行。三个动作：**对 / 不对（写一句）/ 改值（填对的值和出处）**，键盘 j/k 上下移动。另有「我来抽 5 条」：从没看过的里随机抽，结果记在这份文件上（patterns：随机抽检）。

文件卡上原来的 6 行关键数字，换成一行核对进度：

```
宁德时代深度 v1                                       10/06 15:40
论断 80 · 机器对上 69 · 打架 4 · 没核到 7 · 第二方判不对 2
你核了 0 · 驱动结论 14 条待看                         [打开]
```

手机上只给第 1–3 档，每条一张卡（摘录、来源、日期、对 / 不对 / 跳过）。宽表和并排对照放不进手机（patterns：格子点回原文）。

### 4.4 「没核到」

列在**正文顶部的框里**，不放在文末，按原因分组：没查到 / 打不开 / 付费墙 / 只有一个来源 / 查询失败。「没查到」不能写成「不存在」，引用核对的措辞照 hallucinator 的：已对上 / 作者不符 / 没查到 / 查询失败，不写「虚构」（understand-ai；ICLR 2026 误报的教训，user-needs 6.9 第 5 点）。

### 4.5 你说「这条不对」之后

1. 在那条论断上记一条纠正：错的值、对的值、出处、原因类别（过期 / 口径 / 单位 / 来源错 / 算错），写进 `纠正.csv`。
2. 同事只重做这一条和依赖它的论断（顺着算式的输入找下游），以及引用了这些论断的结论句，交出 v2。对话里出一行「v2 · 改了 5 处（2 个数，依赖它们的 3 处）」。
3. v2 打开时默认是改动视图（旧的划掉，新的上色）。你已经核过「对」的论断，没改就保留标记；改过的回到未看。借 GitHub「文件在你看过之后又变了，会被自动取消已看标记」（patterns：评审式逐条过）。
4. 如果这次纠正能推广（比如「PE 一律用 TTM」），同事出一张规矩草稿卡（见第 5 节）。

### 4.6 签过

驱动结论的论断都被你点过「对」之后，文件卡显示「你签过 · 10/07」。这一步不强制，因为门设多了会被一路点过去（patterns 失败模式）。只有签收类（要交给别人的）才有门。

## 5. 纠正与记忆

### 5.1 三层

| 层 | 内容 | 在哪看、谁能改 | 进入要不要你点头 |
|---|---|---|---|
| 关于我 | 跨同事的事实和偏好、读的时间、立刻档的类别、向谁汇报 | MyWork 资料栏可改；其他同事处只读 | 你自己写的直接进；同事提议的要点头 |
| 规矩（每位同事） | 口径 / 来源 / 格式 / 教训，每条带日期和「来自哪一轮」的链接 | 该同事资料栏可以就地增删改（需要一个写回接口，参照 POST /mates/file） | 要。`mywork_remember` 改成只写草稿；只有你说「记住……」时直接记下，原话照录 |
| 纠正记录（每条论断） | 见 4.5 | 资料栏「它最近错过的」；论断行上的标签 | 不需要。它是事实记录，不进上下文，只给检查器和搜索用 |

依据：「记忆分草稿区和正式区，进正式区要人点头」（patterns）；没人审的记忆库半年后会变成自信的错误（user-needs 四-9、6.3 R7）。

### 5.2 一次纠正怎样变成一条看得见的规矩

纠正之后，同事在那一轮下面出一张卡：

```
想记一条规矩（口径）：PE 一律用 TTM EPS，并写明截至哪一季
来自：10/06 宁德 PE 被你纠正（纠正 #3）
只记在持仓研究 / 记进关于我（所有同事）      [记] [改一下] [不记]
```

带上「只记在这 / 记进关于我」的二选一，是因为同一句偏好用户 2 分钟内对两位同事各说了一遍（realUse #12）。没处理的草稿留在规矩栏的「待你确认 n」里，不载入上下文。

### 5.3 怎样让你知道它下次用到了

- **交付物页脚**写「这份用到的规矩：口径 #2（10/06）」。由 deliver 的 `rulesApplied` 字段要求同事声明。
- **拦下记录**，这是最硬的信号：字面核查发现新论断的值和某条纠正里的错值一致，或者违反了能写成检查条件的规矩（期间必须是最新一期、单位必须是某种），就退回重做。成功之后文件卡上出一行「交付前按口径 #2 改了 1 处」。做法借 PerryLink 的「负知识」：被证伪的句子再出现时会被拦下（understand-finance）。
- **资料栏「它最近错过的」**：最近被你退回的、第二方判不对的、到期对账落空的，每条一行，带日期，点了跳回那一轮（patterns：「把自己上次错在哪摆出来」）。

**规矩改了之后怎么生效**：例行和长事都在每次新开的会话里跑（见 13-17），开会话时读一次规矩，绕开了「AGENTS.md 追加后活着的会话下一轮能不能读到」这个没验证的问题（kernel unknowns）。主对话在规矩改动后轮换到新一代会话，沿用改职责时已有的机制（kernel: mateLifecycle）。

## 6. 长任务

**什么时候走计划。** 同事预计超过 15 分钟，或者超过 20 页、30 条论断，或者你说「好好做」，就先回一张计划卡，不直接开干（patterns：开工前可改的计划；Claude Code 计划模式的理由是避免方向错了之后的昂贵返工）。

```
计划 · 宁德时代深度（第2次）                                   草稿
要回答  1 储能占比还能升多少  2 毛利率的拐点  3 估值区间
用这些  巨潮 2023–2026 年报与公告 12 份 · 你给的 3 篇研报 · stock-sdk 行情
不用    自媒体、聚合站（只当线索）
会交    底稿表 约60行（每行带出处）· 成稿 ≤6页 · 没核到清单
步骤    1 取材料  2 抽底稿  3 先交10行给你看列对不对【停】  4 全量
        5 计算（脚本）  6 写  7 字面核查 + 第二方
做到什么算完  3个问题各有带出处的回答；驱动结论的数都有两个来源或标明单源
遇到这些停下来问你  打不开的材料 >3 份；驱动数字两源相差 >5%；花到上限
预计    60–90 分钟 · ¥6–12（按你上次 40 页的用量估）· 上限 ¥15
                                          [开始]   直接回话就是改计划
```

- **开工规则**：预计花费低于关于我里的「免确认上限」（默认 ¥5），10 分钟没回应就自动开始；高于上限的一律等你点。依据：Devin 默认等 30 秒；对离开屏幕的人来说，30 秒等于没问（patterns 失败模式）。
- **中途看到什么**：计划卡原地更新每一步的状态（线条图标：空圈 / 进行中 / 完成 / 问号）。底部状态行从「在干活 · 步骤 · 40s」变成「第 4/7 步 抽底稿 · 38/60 行 · 41 分钟 · ¥5.2 / ¥15」。中间文件出现在右栏「电脑 → 文件夹 → 这份计划」下面。
- **检查点**：卡片上有表的预览，回复借 ARIS 的四种：继续 / 自定义指令（直接回话）/ 跳过第 N 步 / 停。
- **改方向**：你发的话照旧是插话。气泡下面出一行小字，说明它什么时候生效，比如「第 4 步做完当前这批（约 3 分钟）后改」，免得你以为没生效又发一遍（realUse #20 的重复）。到了步骤边界，同事出一张改向卡，写明**保留**什么、**作废**什么、**新增**什么、新的估算，按钮是「好 / 再改 / 停在这里交中间结果」。
- **超时和中断**：每一步是独立的一轮，单轮的 20 分钟上限照旧，但只管一步。一步超时，引擎把这一步拆小，重试一次；还不行就把这一步标成问号，按计划里写的停或者跳过。程序重启后，对话里出一张卡：「计划到第 4 步，接着做？[接着] [先停]」。状态全在 `计划/*.md` 和 `进展.md` 里，进展里也记走不通的路（patterns：总计划加进展日志，「没有它们，后续会话会重新尝试同样的做法」）。
- **和例行的关系**：长事跑着的时候，同一位同事的预检脚本照常跑，立刻档照常推；需要模型的例行轮在后台会话里排队，不插进长事。
- **这算不算任务？** 不算。计划只是同事文件夹里的一个文件，在对话里显示为一张卡，在资料栏「手上的计划」里占一行（同一位同事同一时间只跑一个计划）。这对应 dots 资料页上的 Activity 面板（survey-persistent），没有全局列表。

## 7. 找回与延续

### 7.1 三个月后找回「上次对某只票的结论和依据」

入口有三个，结果都落到同一个地方：

1. **判断表**：资料 → 判断 → 那只票那一行。「依据」链到交付物系列的最新版，打开后正文滚到结论句，核对栏显示当时你核过哪些。旁边一栏是「之后的变化 7 条（1 条碰到重审条件，11/20 维持，你的理由：……）」，从 `变化.csv` 里按清单行筛出来。
2. **问同事**：新工具 `mywork_lookup` 检索本同事全部交付物的全文、表行、判断、变化和对话，回答里每一句都带跳转链接。依据：现在工具清单里没有读旧交付物的工具（breakpoint 4）。
3. **搜索**：改成全文索引，覆盖交付物全文、表行、判断、变化、消息。可以按同事、类型（成稿 / 变化 / 判断 / 表行）、时间筛，结果分页，没有 20 条上限，每组只出系列的最新版。用纯 JS 的本地索引（MiniSearch 一类，Windows 上没有编译问题；这个项目是推断，材料里没有）。依据：7 天的数据里就有 39% 的正文搜不到，表也不进搜索（realUse #19）。

**依据保留到什么程度**：论断带着摘录和快照路径。被论断引用的快照永久保留，所以不需要留工具返回的内容（现在过程记录只留全体最新 60 轮，store.js ACTIVITY_KEEP）。运行记录不再受 2000 条的全体上限挤掉，旧的运行按月归档到文件里，仍然能「加载更早」（kernel constraints）。

### 7.2 老板问「为什么不用某个新模型」，半小时内拿出依据

见场景 4。关键在于三样东西事先就有：判断表里那条选型决定（带没选的方案和理由）、在用清单（带哪里在用、月花费）、一个自测集（见 8.3）。三样都没有时，同事会如实说「当时没记」，然后用现有证据补一份，标明「这是今天补的依据，不是当时的」。

### 7.3 版本和取代

- 交付物有系列号。v2 取代 v1，文件卡上写「取代 v1：改了 4 个结论句、11 个数」。旧版只能从「前一版」打开，不再进默认搜索。
- 判断不改原行。新行写「取代 J-03」，旧行状态改为「已改 → J-11」。
- 「补全版」这种没有来由又交一份的情况（realUse #22），要么以新版本出现，要么不出现。

## 8. 三种用户各自的第一位同事

### 8.1 金融版：持仓研究（暂名）

- **给谁**：独立投资者、5–9 人的私募（任务书 2.2 的首批候选）。
- **职责**：盯清单里的持仓和自选（建议不超过 30 只），只报绑定的变化；按需做深度研究（走计划）；判断到期就结算。**默认不出每日早报**：每天要不要出声，取决于有没有绑定的变化。
- **例行**（结构化时间加交易日历）：交易日 21:30 扫公告（脚本：巨潮、上交所、深交所直连，PDF 用 liteparse 带页码解析）；交易日 15:30 取收盘价，并按判断里的价格条件做结算（stock-sdk）；财报日前后各一次「财报对账」（预测和实际逐项对照，借买方分析师的复盘表）。
- **维护的文件**：`清单.csv`（代码、简称、市场、仓位、成本、为什么看、权重、启用）；`判断.csv`（加两列：方向 / 阈值 / 时限、结算结果：命中 / 部分 / 落空 / 作废，结算规则借 dsh-alpha-desk 的四条：理由必填、失效条件单列不参与结算、缺数记作废、不回填）；`底稿/公告库.csv`、`底稿/<公司>.csv`（事实七字段借天风：指标、期间、单位、前值、预期、来源位置、核验状态）。
- **交付**：变化卡、深度研究成稿（带论断）、财报对账表、到期结算。
- **可选变体模板**：信用的「主体负面监控」（几百个主体，立刻档 = 负面事件，周期产出 = 晨会用的负面汇总，要签收；user-needs M4）；一级市场的「画像扫描」（清单 = 画像条件，企查查 MCP 的新设、融资、专利，立刻档 = 命中画像；user-needs V4）。
- **能力的取舍**：评分和关键价位可以给（任务书 1 不设合规限制），但只作为「同事的提议」，你确认后才进判断表。

### 8.2 AI 版先给谁

**两个模板都带，第一次打开只问一句「你主要是：管技术选型和团队 / 在做一个课题」，按回答只建一位。** 优先打磨技术选型这一位，理由有四：

1. 它的价值恰好在「事件驱动 + 绑定到你在用的东西」上，现成工具都不覆盖：deprecations.info 只有 18 星，只覆盖海外九家，也不告诉你哪个业务在用（research-keeping-up）；国内供应商的通知期可能不到五天（任务书 2.4）。
2. 做 AI 研究的人付费意愿接近零，每日筛论文已经免费，实验在远程 GPU 上，而我们没有任何 SSH 支持（任务书 2.3、3.3），能接住的环节有限。
3. 开发数据里现成的技术雷达、产品雷达离它最近（evaluate realUse #2）。
4. 技术经理花的是公司的钱（research-spend differsFromDoers）；不过没有找到他们为资讯筛选软件付费的自述（同文件 surprises），这一点要访谈。

### 8.3 技术选型（暂名）：给技术经理

**「我们在用什么」怎么让它知道。** 只用四个来源，每行都记「怎么知道的」：

1. 你粘贴的或在表里改的；
2. 拖进来的依赖文件：`package.json`、`requirements.txt`、`pyproject.toml`、`go.mod`。脚本抽出 AI 相关的 SDK（openai、anthropic、dashscope、zhipuai、langchain 等），并在你给的代码目录里找模型 ID 字符串；
3. 网关配置：one-api / new-api / LiteLLM 的渠道和模型映射；
4. API 账单 CSV：从各家控制台导出，得到每个模型的用量和花费。同事不拿你的密码；要读控制台页面，就由你在实时浏览器里自己登录（任务书 1）。

**「哪里在用」这一列只能由你填**，这正是它和现成下线追踪的区别。留空也可以，影响说明里会写「哪里在用：未填」。

**在用清单的列**：名称、类型（模型 / 接口 / 工具 / 框架 / 仓库）、供应商、模型 ID 或版本、哪里在用、负责人、月用量或花费、备选、怎么知道的、启用。

**事件驱动的节奏（没有每天一份简报）**：
- 预检脚本每 6 小时跑一次，读各家的弃用页、更新日志、定价页（DeepSeek、百炼、智谱、Moonshot、火山方舟、OpenAI、Anthropic、Google），加上 models.dev 的 JSON、OpenRouter 模型列表、deprecations.info 的 RSS、依赖仓库的发版 RSS。只比清单里在用的那些行。定价页要连「模型名映射」一起比：DeepSeek 文档的脚注里出现过旧模型名继续可调、背后已换成新模型并按新价计费的情况（research-keeping-up surprises）。
- 立刻档只有运营类：下线、调价、改名或重定向、限区域、封号或停用、工具下架，并且必须碰到在用的行。推送正文里要有影响面（哪里在用、按上月用量算的月费变化，由脚本算）和通知期。
- 每月一次「在用与花费」：你拖入当月账单后自动出；不拖就不出。依据：技术经理每月看一次用量数据（research-cto aDayOrWeek）。
- 判断按到期日重审，默认 6 个月（Will Larson 的策略范例：半年刷新一次）。
- 平时一声不响；周一的「今天」卡里有一行心跳（3.3）。
- 新模型发布不算运营类，进「看过」。只有当某条判断的重审条件写了「出现某类候选」时，才升成重审。依据：「选哪个模型」的重要性在下降（research-cto surprises）；技术经理要的是「会改变我某个决定的变化」（research-team 需求 5）。

**自测集**：文件夹里的 `自测/`，10–30 条团队自己的真实任务，每条带检查方式。候选模型出现、或者你说「测一下」时，先给估算再跑。结果表的每一格都带「我们测的」标签，原始输出存档。依据：他们只信自己团队在真实任务上跑出来的结果，现在是下属临时做一次对照表，不可重复（任务书 2.4；research-team 需求 1）。跑测的工具建议用 promptfoo（Node，YAML 写用例，能接 OpenAI 兼容接口）。**这个项目材料里没有，是我的推断，需要核实它在 Windows 上和对国内各家接口的可用性。**

**向上解释的材料长什么样**（交付物模板「给 <谁> 的一页」）：

```
给 CFO：客服机器人要不要换模型                       草稿 · 你来发
结论    建议继续用 DeepSeek，切到 V4；月费 +¥2,300，或换 Qwen 省 ¥800 但要 2 周改造
发生了什么    DeepSeek 10/22 下线 V3.2（官方公告 10/08）
对我们        客服、代码审查在用；上月 ¥5,000；14 天内必须切
我们怎么比的  在我们 20 条真实客服任务上测：V4 18/20，Qwen-x 16/20，现用 17/20 [我们测的]
              价格 [官方定价页 10/08]；能开票 [供应商合同]；封号风险 [无先例]
不选的和理由  GPT-x：不能对公开票 [采购记录]
什么情况下再改  价格再涨 >30%；国产候选在同一 20 条上 ≥19/20
出处          ……（每个数字一条）
```

每个数字带四种标签之一：「我们测的 / 账单 / 官方 / 第三方」。依据：他们信一手出处和自己的结果，不信厂商数字和 AI 的归纳（任务书 2.4）；材料要开头一段就给结论和要决定什么，后面有备选和不选的理由、风险，十几分钟能读完（research-decisions 需求 5）；管理者自己用 AI 写的材料被下属一眼认出会掉信任（任务书 2.4），所以用平实的固定格式，并且由你改完再发。

**决定怎么留档、怎么到期重审**：判断表的一行就是一条精简的 ADR：背景用依据链接代替；决定、状态、没选的和理由、重审条件、到期日都有；被取代时两行互相指向（research-decisions 需求 6：ADR、RFC 的 revisit date）。重审由三件事触发：变化碰到条件、到期、你主动问。重审卡：

```
重审 J-03（2026-03-12 定）：客服用 DeepSeek-V3.2
当初的依据  便宜（¥2/百万输出）· 能开票 · 自测 17/20       [看依据]
新事实      V3.2 10/22 下线；deepseek-chat 改指 V4，输出价 ¥3  [出处]
碰到的条件  「下线」「价格上涨 >30%」
[维持（写一句理由）] [改：新建一条决定] [延后到 __]
```

ADR 写了放进仓库也没人读，「不接自动化就等于没有」（research-decisions surprises）。重审卡就是这个自动化。

### 8.4 课题（暂名）：给做 AI 研究的人

- **清单**：课题一句话、关键词、种子论文、相关作者、贡献点（一两句，用来判断撞题）、投稿目标和截止日期。
- **例行**：工作日早上用脚本取 arXiv 当日列表和 papers.cool 的关键词订阅，按种子论文和 Zotero 库的相似度排序（借 zotero-arxiv-daily 的 reranker 思路，用 zotero-mcp 的命令行技能读本地库，不要 key）。只对排在前面的候选调用模型，写明「和你的哪篇、哪个贡献点像」。档位：和贡献点高度重合的「撞题」进立刻档；相关的到点报，最多 5 篇；被筛掉的写在页尾，附原因（dailypaper-skills 的做法）。依据：15 位学者里 13 位谈到被抢发的焦虑（user-needs 6.3 R6）；国内研究者不用算法先筛，怕漏（6.9 第 1 点）。
- **判断**：类型是「前提」，例如「还没有人在 X 上做 Y」。撞题论文就是这条前提的重审触发。
- **按需走计划**：投稿前的引用核对（场景 3）、相关工作查全（交付时写明搜了哪里、还缺哪类，R2）、对比表（每个数带评测设置和页码，R3）。
- **借用**：ARIS 只取 `citation-audit`、`paper-claim-audit`、`research-wiki` 和 `shared-references/` 里的几份规范，放进这位同事的 `.dsh/skills/`；**不装整个 dsh-aris**，因为它会改掉全体同事的默认模型，在 Windows 上会让整个 profile 启动失败（任务书 5）。审稿方用 Kimi / Qwen 当异家族，或走人工中转。
- **第一版不碰实验台账和夜间实验**：没有 SSH（任务书 3.3）。课题模板里写明这一条，免得用户以为能做。

## 9. 多位同事之间

- **共享的**：关于我；「需要你」里的阻塞（按资源记，一处解决处处消失）；价格表 `$DSH_HOME/mywork/prices.json`（技术选型同事维护，费用显示也用它）；彼此的产出，通过 `mywork_lookup` 只读检索，引用时带回链。
- **不共享的**：对话和规矩。不做多同事群聊，也不在一条对话里 @ 多位。依据：Dust 放弃了一条对话 @ 多个智能体，理由是只有一对一时中途插话才可靠（任务书 4）。
- **一件事归谁**：清单的每一行只有一个负责同事。同事往清单加行时，先用 lookup 查别的同事的清单；撞上了就出选项卡「转给 X / 两个都盯（X 报，我只引用）」。MyWork 建同事前照旧查重（kernel: mywork_mates）。依据：探新和财联社记者各做了一遍 GitHub 热点，「归谁」悬了多天（breakpoint 12）。
- **转交**：每张卡上都有「转给…」，把卡片内容和出处作为一条消息发进另一位同事的对话（复用 say()）。比如把课题同事看到的一篇评测论文转给技术选型同事去补自测集。
- **早上谁说话**：每位同事在自己的对话里说（不推送）；「今天」卡汇总；只有立刻档推送；同一事件只推一次。

## 10. 费用

- **数据来源**：每一轮用 dsh-token-meter 的用量（未缓存输入、输出、缓存读写）乘价格表。价格表来自 models.dev 和各家官方定价页（kernel: costAndModels；能不能从插件里拿到 tokenMeter 要先验证）。
- **在哪里看**：
  - 每一轮的「过程」行：「过程 · 12 步 · 3 分钟 · ¥0.42」；
  - 同事资料栏「花费」：本月合计，以及每条例行一行，比如「每次检查约 ¥0 · 本月 31 次检查、模型 6 次 · ¥1.9」，加上每个计划一行；
  - MyWork 资料栏：全体同事合计和月总预算；
  - 「今天」卡一行；铃铛「在干活」组里显示已花多少。
  - 依据：Perplexity 在定时任务旁实时显示已花多少（survey-briefing shifts）；常驻智能体的计费已从包月转向用量（任务书 4）。
- **跑之前的估算**：计划卡给一个区间，按这位同事过去同类工作的「每页 / 每条的用量」推算，第一次用模板的经验值并标「首次估算，误差大」。建例行时给「每月约 ¥2–6」。这是任务书 4.3 列出的空位，现成产品都没做。
- **预算和上限**：每位同事一个月预算（模板给默认值）、全体一个月预算、每个计划一个上限。还可以按同事选模型：例行和预检后的确认用便宜档，长事和第二方用强档。现在模型在会话创建时就钉死了（kernel），拆出后台会话以后，按会话选模型才做得到。
- **撞线时**：
  - 计划撞线：在下一个步骤边界停，中间结果先存好，出「需要你」：[加 ¥10 继续] [就到这，交已有的] [换便宜模型续]。不硬停。依据：Quesma 半小时烧完额度，只完成 25 项核验，最后一无所得（user-needs 四-7；patterns 失败模式）。
  - 月预算撞线：需要模型的例行暂停，预检脚本照跑；立刻档改成只发脚本原文，并标「未经同事核对」；同时出「需要你：本月预算到了」。

## 11. 桌面和手机的分工

- **C（长事、费用、找回）最后。** 17 和 18 是仅有的两项大改；在它们做完之前，长事先用「在主会话里按步骤连续发轮」的降级方案：引擎在每一轮结束后自动发「继续第 N 步」。

对现有模型的唯一结构性改动是 17：**「一位同事一条 dsh 会话」变成「一位同事一条用户可见的对话，背后有若干会话」**，对话的连续性改由文件承担。理由有三：上下文 3 天从 2.4 万涨到 20 万 token（EDITIONS 6-5）；例行和用户的话撞车（Rakazo CHANGELOG）；审稿要新开（ARIS）。用户看到的单位和对话不变。

## 14. 去掉什么

| 拿掉或收起 | 为什么 |
|---|---|
| 模型末行「变化：有 / 无」决定静默 | 会把真东西藏掉（realUse #9），而且不省钱 |

| `mywork_remember` 直接追加 | 改成草稿 |

## 15. 走一遍场景

### 场景 1：个人投资者，12 只股票，三个月，3 次深度研究，然后找回结论

1. **第 0 天，第一次见面。** 用户点「+」，选「持仓研究」，在开工单里粘贴 12 只代码（有 4 只写了仓位）；第 2 问保留模板预勾的类别；读的时间设交易日 08:30；预算 ¥30。同事回清单确认卡，「长城」有 3 个候选，用户选一个。同事从用户的话里提了 1 条判断草稿（J-01，宁德储能），用户点「记」。开工后马上出基线，再补报最近 3 个交易日的 2 条变化。
2. **平常的交易日。** 21:30 脚本扫公告，多数日子清单里有 0–2 条新公告。没有新公告就不调用模型，「今天」卡里只有一行「持仓研究：看过 23 条公告标题」。有新公告时，同事打开 PDF（liteparse 带页码），写变化卡，08:30 出现在「今天」卡里。某天 19:40 出了一条减持公告（立刻档），IM 推送，正文里写明这条有没有碰到某条判断。
3. **第 1 次深度研究。** 用户说「给我做一次宁德深度」。同事回计划卡（60–90 分钟，¥6–12），用户点开始；第 3 步检查点改了一列的口径；交付 v1，带 80 条论断。用户在核对栏里核了 14 条驱动结论。同事提议「把结论记成判断？」，生成 J-04，依据链到 v1 和其中 3 条论断，重审条件「毛利率 < 25%（季报）」，到期日设为下个财报日加 3 天。
4. **第 2、3 次深度研究**（同一只票隔 6 周一次，另一只票一次）。宁德那份交 v2：「取代 v1：改了 4 个结论句、11 个数」。J-04 到期，同事出重审卡，用户选「改」，生成 J-09 取代 J-04。
5. **到期结算。** 带价格条件的判断由脚本按收盘价结算，结果在读的时间出现。判断表头写「到期 14 条：命中 6 · 部分 3 · 落空 5」。
6. **三个月后。** 用户在手机上打开持仓研究的资料 → 判断 → J-09。依据链接打开 v2，正文滚到结论句，核对栏显示当时核过的 14 条（都带「你：对」）。下面「之后的变化 7 条」里有一条碰到过重审条件（11/20 维持，理由在旁边）。也可以直接问同事「上次对宁德的结论和依据？」，同事用 lookup 回答，每句都带跳转。

**仍然不够**：如果用户从不确认判断，找回就退回到全文搜索；能搜到，但不如判断表干净。港股、美股的来源和付费终端里的一致预期够不着（user-needs 5.7）。用户自己的 Excel 模型读不进来，也写不回去。PDF 跳页没有验证。三个月里「看过」会积累上万行，搜索性能没测过。

### 场景 2：买方研究员，40 页深度底稿，核 80 个数字

1. 研究员把 40 页的 PDF 拖进对话，存进 `材料/`，说「按我的框架做一份底稿和成稿」，再把框架列粘贴进来。
2. 计划卡：用 liteparse 抽文本和坐标；抽底稿（约 90 行）；第 3 步交 10 行；数字全部由脚本算；成稿 ≤6 页；字面核查加第二方（Qwen，只查驱动结论的加 20% 抽样）；60–90 分钟，¥8–15，上限 ¥20。研究员点开始。
3. 检查点：10 行预览里「收入」用了分部口径，研究员回一句「收入一律用合并口径」。同事出改向说明（已抽的 10 行重算），同时出一张规矩草稿卡，研究员点「记」。
4. 交付后的文件卡：「论断 80 · 机器对上 66 · 打架 4 · 没核到 8 · 第二方判不对 2」。正文顶部的「没核到」框里：5 条「只有一个来源」，2 条「打不开（附注扫描件）」，1 条「没查到」。
5. 桌面核对栏按风险排序。先处理第二方判不对的 2 条：点开，PDF 在实时浏览器里开到第 47 页，确认 1 条是同事把万元当成了元；点「不对」，填对的值。再看打架的 4 条，各选一个来源，其中 1 条改值。然后过 14 条驱动结论，再看 7 条计算类（展开看输入和脚本）。最后点「我来抽 5 条」。大约 40 分钟，核了 32/80。
6. 同事交 v2：「改了 6 处（2 个数加依赖它们的 4 处）」。改动视图里只需要重看这 6 处，其余「对」的标记保留。驱动结论全部核过后，文件卡显示「你签过」。

**仍然不够**：交回的东西如果要进他自己的 Excel 模型，现在 xlsx 只能下载，没有「值加出处链接」写进单元格的路径（patterns：Daloopa 的做法发生在 Excel 里）。扫描件里的表格抽取要靠 MinerU 上传到外部。口径用得对不对，机器核不了，只能靠人看。80 条都走第二方的费用，要真实跑过才知道。

### 场景 3：博士生，跟课题新论文，投稿前核 60 条引用

1. 选「课题」模板：一句话贡献点，拖入 `.bib` 和 3 篇种子论文，填上投稿截止日期。
2. 工作日早上：脚本取 arXiv 列表和 papers.cool，按种子论文和 Zotero 库排序，只对前 10 篇调用模型说明相关在哪。某天有一篇和贡献点高度重合，进立刻档，IM 推送，同时出「前提 P-01 的重审」卡（还没有人在 X 上做 Y？）。其余相关的到点报，最多 5 篇，页尾列出被排除的及原因。
3. 投稿前两周，他把 `main.tex` 和 `.bib` 拖进来，说「把 60 条引用核一遍」。计划卡分 6 步，每步 10 条：存在性和元数据（refchecker 或 verify_papers 查 arXiv、CrossRef、Semantic Scholar、DBLP）；对每处引用，取引用句和被引原文的相关段（已入库的用 zotero 按页读，没入库的抓 arXiv）；Kimi 只看这两段，判支持 / 弱 / 不对 / 拿不准，并摘出原文句子和页码。预计 40–70 分钟，¥3–8。
4. 结果进核对栏：已对上 41 · 作者或年份不符 9 · 原文不支持或弱 6 · 没查到 3 · 查询失败 1。没有一行写「虚构」。他先看 6 条「不支持或弱」：每条左边是他论文里的那句话，右边是被引原文那段，选「换引用 / 改说法 / 保留」。
5. 同事交一份改好的 `.bib` 和一份改动清单，作为文件卡，不直接改他的论文。

**仍然不够**：被引原文在付费墙后面时，只能标「打不开」。「支持与否」判断的准确率没有任何数据（user-needs R1）。一句话里引了好几篇时，上下文怎么切会影响结果。实验台账和夜间实验做不了，因为没有 SSH。审稿方要用 Kimi 或 Qwen 的 key，没有就只能「同一家模型，独立会话」。

### 场景 4：技术经理想知道和在用的模型、框架有关的变化；老板问「为什么不用某新模型」

1. **建立。** 选「技术选型」模板，拖入两个仓库的 `package.json`、网关配置和上月三家的账单 CSV。同事回出 14 行在用清单，每行写「怎么知道的」。他补了 6 行「哪里在用」。同事从他口述里提了 3 条判断草稿（客服模型、编程工具、向量库），他确认了 2 条，其中一条是 J-03。
2. **平常几周。** 一声不响。每周一的「今天」卡里有一行心跳。中间有一次立刻档：某个依赖仓库发了破坏性版本，正文写明「动到：推荐服务（package.json 里 ^2.3）」。新模型发布都进了「看过」。
3. **老板发问。** 下午 3 点老板问「我们为什么不用 Kimi K3」。他在手机上对同事说了一句。2 分钟后同事回复，内容有四块：J-03（2026-03）的结论和没选的方案；K3 在 9/20 出现过，当时进了「看过」，因为不在在用清单里，也没碰到重审条件；价格对比（官方定价页）；约束（开票和合同）。最后问「要在我们 20 条客服任务上测一次吗？约 15 分钟 ¥3」。他点了「测」。
4. 15 分钟后自测结果出来，同事出「给老板的一页」草稿，每个数字都带标签。他改了一句话，导出发出去。从提问到发出约 25 分钟。

**仍然不够**：如果自测集还没建，第一次建要他提供 20 条真实任务，半小时内拿不出「我们测的」那一列，同事会如实写「还没在我们的任务上测过」。「哪里在用」完全靠他填。全团队、别人电脑上的用量看不到。没有 K3 的 key 就测不了。读海外文档可能要分域名走代理（EDITIONS 6-11）。

### 场景 5：4 位同事，早上各交了东西，手机上只有 5 分钟

前提：读的时间 08:30；四位同事是持仓研究、技术选型、课题、宏观周报（周五要交给团队）。

1. 07:10 技术选型推过一次 IM（DeepSeek 下线），他当时扫了一眼。
2. 08:35 在地铁上打开手机 App，进 MyWork 的对话，最上面是「今天」卡（第 0–30 秒）。
3. 「需要你 2」：x.com 登录（技术选型和课题都卡在这），点「今晚提醒」，延后到 20:00；周报签收，点开看第二方判不对的 1 条，摘录卡一看是单位问题，点「不对，用亿元」，同事去改，签收留到改好以后（30 秒–2 分钟）。
4. 「变化 5」：点持仓研究那一行，跳到它的对话，看变化卡，点「看出处」，弹出摘录卡；返回（2–3 分钟）。
5. J-03 重审卡：前一天已经改过，这里显示「已改 → J-11」，不再要求动作。另一条持仓的判断 J-02 碰到了条件，他点「维持」，写一句「减持比例小，逻辑没变」（3–4 分钟）。
6. 课题的撞题论文：点开看摘要和「像你的哪一点」，点「转给…」不合适，就点「加进清单对比」（4–5 分钟）。
7. 关掉 App。没有什么要「清」的，「看过 139」他没打开。

**仍然不够**：手机没有系统推送，不在前台时只有 IM 能找到他。登录在手机上做不了。周报正文在手机上读起来吃力。中继在大陆移动网络上的可用率没测过（EDITIONS 7）。

### 场景 6：同事用了过期的数字，用户纠正；两周后会不会再犯

1. 10/06 的变化卡里写「宁德 PE 18 倍」，用的是 2025 年报的 EPS。字面核查已经标了「可能过期」（期间早于已知最新一期），但卡还是发出来了。用户点这条论断，选「不对」，写「用 TTM」。
2. `纠正.csv` 记下纠正 #3（错值 18、对值 21.4、出处、原因「过期」）。同事重做，卡片出 v2「改了 1 处」。紧接着出规矩草稿「口径：PE 一律用 TTM EPS，写明截至哪一季」，选项「只记在持仓研究 / 记进关于我」，用户选前者，点「记」。规矩栏多一行「口径 #2 · 10/06 · 来自纠正 #3」。
3. 10/20，同事算比亚迪的 PE，第一稿又用了年报 EPS。交付前，检查器按「口径 #2：期间必须是 TTM」拦下，同事改完再交。文件卡上出一行「交付前按口径 #2 改了 1 处」，页脚写「用到的规矩：口径 #2」。
4. 资料栏「它最近错过的」里有两行：10/06 PE 用了过期 EPS（已改，记成口径 #2）；10/20 交付前拦下 1 处同类。

用户就是靠这三处知道它记住了：拦下的那一行、页脚、规矩栏。

**仍然不够**：只有能写成论断级检查条件的规矩（期间、单位、来源时效、口径标签）才能被机器拦。像「注意估值的可比性」这种散文规矩，只能靠模型自觉，只能看页脚的声明。主会话重读规矩靠轮换会话这个现有机制，长对话里的效果没验证。

### 场景 7：一件要跑两个小时的事，用户中途想改方向

1. 计划卡：7 步，100–140 分钟，¥12–20，上限 ¥25。用户点开始。
2. 第 50 分钟，第 4 步做到 38/60 行。用户发「别做海外了，只看储能，再加一张和比亚迪的对比」。气泡下面出小字：「第 4 步做完当前这批（约 3 分钟）后改」。
3. 3 分钟后出改向卡：

```
改了方向
保留  第1–3步全部；第4步已抽38行中储能相关29行
作废  第4步剩余的海外部分；第6步原提纲
留着不用  已抽的9行海外数据（在底稿里，不进成稿）
新增  第4b步：比亚迪储能数据约12行
还要  55–70分钟 · ¥7–10（合计 ¥15–19，在上限内）
[好] [再改] [停在这里交中间结果]
```

4. 用户点「好」。第 5 步超过 20 分钟，引擎把它拆成两半重试，成功了。第 1 小时 40 分钟用户合上了电脑；再打开时出卡「计划到第 6 步，接着做？」，点「接着」。交付。

**仍然不够**：单步本身超过 20 分钟、又拆不开的工作（比如一次很长的网页操作）还会失败。步骤状态依赖同事正确更新计划文件，引擎只能校验格式，校验不了内容。电脑睡眠时一切都停（要靠 EDITIONS 6-2）。第一次跑的估算区间会很宽。

### 场景 8：CTO 收到（或没收到）DeepSeek 下线和调价的通知

1. **没收到通知。** 14:00 预检脚本发现 DeepSeek 的文档和定价页变了：V3.2 在 10/22 下线，deepseek-chat 改指 V4，输出价从 ¥2 变成 ¥3。这是运营类变化，碰到在用清单 2 行，进立刻档。同事调用模型确认一手页面，写变化卡，同时推 IM：

> 技术选型｜DeepSeek：V3.2 10/22 下线，deepseek-chat 改指 V4 并按新价计费。动到：客服机器人（上月 ¥4,100）、代码审查（¥900）。按上月用量，月费 +¥2,300（脚本算，见算式）。碰到 J-03 的重审条件。通知期 14 天。

   **收到了邮件**：他把邮件文字粘贴进对话，或者截图拖进来，同事从第 2 步开始走同样的流程，并用官方页面核对邮件内容。
2. **他打开对话。** 变化卡上有出处（官方页面快照，带日期）、影响表（来自在用清单加账单）、月费变化的算式（输入：上月 token 数乘新旧价差）。下面是 J-03 的重审卡。同事追加一句：「要在客服 20 条上测 V4 / Qwen-x / GLM-y 吗？约 20 分钟 ¥4」。他点了「测」。
3. **「影响到哪些地方、该怎么办」。** 测完后，同事给出三个选项的对照：继续 DeepSeek 切 V4、换 Qwen、换 GLM。每个选项写效果（我们测的）、月费（脚本算）、切换工作量（按清单里的「哪里在用」和你填的负责人）、开票和合规。同事不替他选。
4. **「怎么跟 CFO 说」。** 他点「写给 CFO 的一页」，得到 8.3 那个格式的草稿：结论一句，钱和时间，我们怎么比的，不选的理由，什么情况下再改，每个数字带标签。他改完导出成飞书文档自己发，同事不发。
5. **定下来。** 他在重审卡上点「改」，新建 J-11：「10/08 客服切到 V4，继续用 DeepSeek；理由……；重审条件：价格再涨 >30%、国产候选在同一 20 条上 ≥19/20；到期 2027-04」，J-03 状态变为「已改 → J-11」。

**仍然不够**：通知如果只出现在控制台站内信或邮件里、公开页面上没有，同事看不到，除非他转发或者自己在实时浏览器里登录控制台让同事读。「哪里在用」和账单如果从没提供过，影响面只能写「未知」。月费变化只覆盖这台电脑上能看到的账单。其他国内供应商的页面结构变了，预检脚本就会失效，要靠热修通道。

## 16. 没把握的地方

**推断，需要用户验证的：**

1. 用户愿不愿意在第一次见面时写下清单，更不用说判断。整套「绑定」都建立在这上面。用得浅的人是多数（任务书 2.1），很可能多数人只填清单、从不确认判断。设计里判断是可选的，但重审和找回的价值会跟着打折。
2. 「读的时间」一人一个够不够。宏观固收要在数据发布当天几小时内出点评，这类可能要按同事单独设节奏。
3. 「今天」卡会不会被当成又一份简报，或者被忽略。它只汇总绑定的项、不带数字的催促，但有没有人每天打开，只有试用能回答。
4. 立刻档的默认类别（尤其持仓的公告类别）会不会太吵。阈值是拍的（patterns 失败模式）。可能要借 Dependabot 的做法：长期不理就降频。
5. 技术经理会不会提供依赖文件和账单，「哪里在用」会不会有人填。没有这一列，技术选型同事和 deprecations.info 没什么区别。
6. AI 版先打磨技术选型这一位，依据是需求和现成工具的空位，不是付费证据（research-spend surprises：没找到为资讯筛选付费的自述）。
7. 核对栏的风险排序是我定的规则，没有任何产品或数据检验过（任务书 4.3 的空位）。

**技术上没验证的：**

8. dsh-token-meter 能不能从 MyWork 插件里取到；后台会话按会话选模型在 0.1.6-alpha.2 上是否稳（kernel unknowns）。
9. 计划执行能不能交给 dsh 自带的 goal、workflow、todo；不能的话第 18 项是一个新机制。
10. PDF 在实时浏览器里用 `#page=N` 跳页（kernel unknowns）。
11. 按同事放 `.dsh/skills` 和按同事挂 MCP 是否只对那一位生效（kernel unknowns）。
12. 第二方核对在国内需要用户再有一家模型的 key；没有时「同家族、独立会话」能发现多少问题，没有数据。
13. 「支持与否」类引用核对的准确率没有数据（user-needs R1）。
14. promptfoo、MiniSearch 不在材料里，是我按经验推荐的，要核实 Windows 下的表现和对国内接口的支持。
15. 预检脚本读海外页面在大陆不挂代理时的可用率（EDITIONS 10-1）。

**数据本身的限制：**

16. 所有「真实使用」的数字都来自开发者自己 7 天的自测（evaluate realUse #1）。技术经理的调研还在复核（任务书 2.4）。场景 1、2、3、6、7 里描述的用户行为是推断。

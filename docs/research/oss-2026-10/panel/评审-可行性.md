# 可行性审查：三份方案对照 v2 代码

路径约定：`V2=/Volumes/KESU/deepseek_harness_projects/Mywork_deepseekharness-v2`，`DSH=$V2/.dsh-dev-home/npm/node_modules/@deepseek-ai`。下文"未验证"指只读了代码或日志，没有跑通。

## 0. 实测基线（三份方案都没用到，结论多半由它决定）

1. **每步固定开销约 2.4 万 token。** 财联社记者的会话日志（`$V2/.dsh-dev-home/home/sessions/…mate-mup77d6nb7e6a9…/session.v3.jsonl.zstd`）里，首个请求历史为空，input 已是 23,828 token：94 个工具 schema 共 65.7 KB，加约 10 KB 系统提示。还没接任何厂商 MCP。
2. **永久会话线性膨胀。** 同一会话 13 轮（3.3 天，每天 3 次例行），单步上下文从 24k 涨到 210k token，日志里 0 条压缩事件。累计 input 约 10.9M（缓存命中 10.53M，未命中 0.36M），output 5.9 万。
3. **工具表一变，缓存全失效。** 10-04 工具从 94 变 96 个，下一轮单步 199,847 token 未命中缓存。接或停一个全局 MCP 会让所有同事付一次全价上下文。
4. **"变化：无"不省钱。** 它是模型跑完后从回话里解析的（`packages/tasks/src/engine.js:547-551, 571`）。开发环境 40 次例行只有 2 次安静，每次 11–204 秒、0–20 次工具调用。
5. **调度器不认方案里的写法**（实跑 `parseSchedule`，`routines.js:61-118`）：
   - "交易日 07:30…"返回 null，`createRoutine` 直接抛"没看出时间"（`index.js:576`）。
   - "盘中每 10 分钟""交易时段每 30 分钟"变成全天候 interval，夜里和周末照跑。
   - "周日 20:00""周六 10:00"不带"每"字，变成一次性。
   - `nextRun` 只往后找 8 天（`routines.js:152`），找不到时 `ran()` 把例行永久停用（`:199`）。2024 年春节连续 10 个自然日不开市，朴素地加"交易日"判断会在长假把例行关掉。
6. **桌面壳不是常驻程序。** 关窗即杀 dsh 并退出（`apps/desktop/main.js:182`）；没有托盘、防睡眠、开机自启、单实例锁、自动更新。错过的例行在唤醒后一次全跑（`index.js:916-917`），并发 2、单次 20 分钟（`index.js:36`）。
7. **没有升级路径。** `ensureHome()` 只在 profile 不存在时复制模板（`main.js:52-58`）。老用户装新版，内核代码和版本包都不会更新。
8. **沙箱：读任何地方，写只能在自己文件夹。** macOS seatbelt 是 `(allow default)(deny file-write*)` 加可写根（`$DSH/dsh-sandbox-local/lib/index.js:65-75`），同事会话审批策略是 never（`engine.js:233`）。Windows 走另一套 ACL 沙箱，未验证。
9. **Windows 上没有 bash。** `tool-bash` 在 win32 禁用，只留 pwsh（`packages/tasks/presets/mate-base/agent.cordis.yml`）；没装 PowerShell 7 时回落到 5.1（`$DSH/dsh-pwsh-local`）。Windows 包从未实机运行过（`apps/desktop/README.md` 已知限制）。
10. **打包版的"真实浏览器"是 Electron 自己的 Chromium。** `MYWORK_DESKTOP=1` 时插件不启动 Chrome，只附着 Electron 的 DevTools 端口（`packages/browser/src/index.js:57-58`，`main.js:39-43`）。Chrome for Testing 只给 Univer 渲染用（README），而 Univer 0.3.2 前端在这版 dsh 上不激活（`kit.json`）。
11. **安装包实际体积。** v1 的 win zip 682 MB，mac dmg 858 MB；其中 Chrome for Testing 压缩包占 205 / 191 MB。
12. **dsh 0.1.6-alpha.2 已有按同事隔离工具的原生手段（未验证）。** `tools.restrict({allow,deny})` 作用于 agent 作用域（`$DSH/dsh-tools/lib/index.js:2893`）；mcp-client 支持"Agent-scoped MCP servers"（`$DSH/dsh-mcp-client/lib/index.js:769`）。每位同事本来就有一份生成的 preset（`index.js:102-108, 234-246`）。"MCP 全局"是 dsh-mywork-mcp 把条目挂在 loader 根上造成的（`packages/mcp/src/index.js:32-37`）。
13. **引擎守卫。**
    - 每轮最多问 2 次（`store.js:52`）。
    - system 和 routine 运行不能问（`engine.js:674-675`）。
    - `mywork_mate_create` 只在 user 触发的运行里可用（`index.js:852`）。
    - 例行运行不能建例行（`index.js:757`）。
    - 职责上限 2000 字（`store.js:43`）。
    - 新同事的 intro 运行见到职责里有时间就让模型再建一条例行（`engine.js:177`），会和模板种的例行重复。
14. **存储撑不住高频。** `tasks.json` 上限 2000 条运行，超出丢最旧的，也就是对话历史（`store.js:54, 101`）；每次更新整文件重写；现在 72 条已 557 KB。表格阅读上限 512 KB（`index.js:517`）。
15. **现有表头是中文**（`类型,名称,地址或账号,关注什么,权重,启用`）。同一批同事的 CSV 有的带 BOM 有的不带，说明模型自己维护的表已经在漂移。

## 方案 A（user-day）

### (1) 严重问题

- **首次打开与引擎守卫冲突。** "MyWork 开场，最多问三件事"是 system 触发的运行，不能问，且每轮上限 2 次；随后建第一位同事也被 `index.js:852` 拒绝。"第 2–4 天 MyWork 每天提议一位新同事"来自例行运行，同样不能问、不能建（基线 13）。内核第 3 条标"小"不成立，需要新的运行类型或非模型的引导卡。
- **留人钩子依赖电脑醒着且窗口开着。** 07:30 盘前、21:30 夜班、盘中每 10 分钟都如此（基线 6）。合盖的笔记本 9 点开机时所有同事的积压例行一起排队，盘前早报到手已开盘。内核清单里没有常驻这一项。
- **2 周范围里的同事用到 6 周才有的内核。** 值班的"每 2 小时哨兵，只在有新条目时叫醒模型"依赖内核 5（排在 6 周）。在那之前它每天叫醒模型 12 次，每次重读整段上下文（基线 2）。"每位同事每天几毛钱"没有依据；10 分钟一次的哨兵若记成运行，会把 `tasks.json` 的 2000 条上限在几周内打满（基线 14）。
- **共享表和密钥库按设计不可用。** `$DSH_HOME/mywork/shared/` 在同事文件夹之外，写入被沙箱拒绝。`secrets.json` 设 0600 挡不住同用户的 shell，读是全放开的（基线 8）；现有 `.credentials.yaml` 和 `mcp.json` 同理。
- **自己的规则与自己的供给矛盾。** "版本包不能是 dsh 插件"，但圈内用 zhengjy01/dsh-jike、富途用 yangzhe1991/dsh-futu-mcp，两者都是 dsh 插件，只能在打包时作为 kit 成员装进 profile。运行时装插件需要 pnpm，打包版不带（README）。OpenCLI 需要 Browser Bridge 扩展，而打包版浏览器是 Electron（基线 10）。
- **"只靠 Node 完整可用"等于约 20 个站点脚本全部自写。** 包括五家快讯（财联社签名）、巨潮和两所公告加 82 子类分类、东财研报、宏观直连、快讯实体聚类。gaps.txt 确认中文金融事件抽取"only stale research code"，也没有 Node 的巨潮 skill。这部分工作量藏在"两个版本包"里，没进任何估算。"6 周配齐 13 位"对一个人更接近 3–4 个月。

### (2) 与 STRUCTURE.md 或负责人决定的出入

- 下单类工具"按名字直接拒绝"，而现有机制是"先问再做"（`mywork_ask` approval）。
- 版本包带 `NOTICE` 文件：许可不是标准，无害但多余。
- "发布时刻后的哨兵"需要例行运行时再建一次性例行，被 `index.js:757` 禁止。

### (3) 对的，必须保留

- 默认名册只靠 Node，Python 是加装，MCP 默认不挂（它自己写了这条退路）。
- `routines[]` 里时间用结构化 `schedule`，不靠句子解析。
- 分阶段名册（day1 / week1 / onDemand）和 `handoff`（专门同事加入后通才让出那段活）。
- 2 周只做每个产品第一位同事，加一次真实大陆线路实测。
- 风险 3（例行改用新会话加文件状态）和风险 7（内核晚了先只发 AI 版）。
- 观点台账第一版就有；花费记录确实是小改动（usage 已在 `assistant/message` 事件里）。

## 方案 B（supply）

### (1) 严重问题

- **金融版首日压在最脆的一环上。** Python 默认在首次打开时后台装，并假设"第三方 Python skill 不用改就能跑"：
  - Windows 只有 PowerShell（基线 9），SKILL.md 里的 `python3`、heredoc、`curl | jq` 都会失败。开发日志里模型自己就习惯写 `curl … | python3 -c`。

- **登录态路线选错了浏览器。** "托管 Chrome 预载 OpenCLI 桥接扩展"针对 Chrome for Testing，但打包版登录态在 Electron 的 WebContentsView 里（基线 10）。X、知乎、小红书、雪球、东财整条 T4 路线没有落点。

- **第一位同事在 2 周时建不出来。** 盯盘要的交易日历、预检、共享表都排在 6 周；"交易日 08:30"在 2 周时解析不出（基线 5）。B 的 `routines[].input` 是"带时间的一句话"，完全依赖这个解析器。盯盘还要读"快讯"同事的库，而首次打开只建一位。

- **"写一行即触发"没有机制。** 公告往共享待办表写一行触发深研：引擎没有文件触发，tick 只跑到期例行和过期提问（`index.js:916-919`）；共享目录也写不进去。数字核验闸门标"中"，但 `deliver` 没有交付前钩子（`engine.js:655-663`），派生数字（涨跌幅、合计）会被误删。

### (2) 与 STRUCTURE.md 或负责人决定的出入

- Chrome for Testing 当登录浏览器，与 v2 桌面实现不符。
- 交易类工具"按名称拒绝"，同 A。

### (3) 对的，必须保留

- `mw-collect` 先做成第一方 skill，零内核改动，写入都在同事文件夹内，与沙箱相容。

## 方案 C（platform）

### (1) 严重问题

- **按它自己的工时标尺，2 周装不下。** 包加载器（中，3–7 天）、采集器（大，超过 1 周）、skill 清单、两平台安装包、base 包、两位同事、引导卡、探测，合计 15–25 个工作日，而 2 周只有 10 个。把最大的内核件放在见到第一份简报之前，是三份里内核风险最高的开局。
- **第一位金融同事在 2 周时拿不到数据，也排不了班。**
  - 采集器初版只有 rss 和 json，巨潮列表是带表单的 POST，要等 6 周的 script 模式。
  - `"when": "交易日 8:00"` 是字符串，解析为 null；"交易时段每 30 分钟"变成每天 48 次全天候运行（基线 5）。
  - 前置步骤的安静条件是"没有新条目"，行情和快讯永远有新条目，等于每次都叫醒模型。
  - 早报镜像"公告"同事的表，但其余同事是"待上岗"，源表不存在。
- **"版本包纯数据、加载器拒绝 bin 和 dsh.bundle"与供给冲突。** dsh-jike 和 dsh-futu-mcp 是插件，HiThink CLI 是 npm bin，liteparse 是原生二进制（不可能"单文件"）。skill 脚本的 npm 依赖怎么装、ESM 从 `<同事>/.agents/skills/…` 怎么解析到它们，都没设计。"第三个产品内核零改动"在需要新插件或原生工具时不成立。
- **"两个安装包共用一个数据目录"在现有代码上会出事。** 第二个安装包的 `ensureHome` 见到已有 profile 直接返回（基线 7），新包不会出现。两个应用可同时运行，`main.js` 没有单实例锁，两个 dsh 进程会同时整文件重写 `tasks.json`。
- **连接器代办标"中，3–7 天"偏小。** 它包含自带 MCP 客户端、密钥库、白名单、审批、额度、落盘、URL 打码、密钥输入界面，实际 3 周以上。"密钥只在宿主"同样被读全开的沙箱打破；随包的 HiThink CLI 在同事 shell 里跑，本身就需要 key。
- **关键件排得太晚。** 更新通道、用量预算、观点台账结算都在 12 周。
  - 它的可靠性方案靠"包更新修补信源行"，前 12 周修不到用户手里。
  - 交易日历文件 2026-12-31 到期，12 周节点是 12-28。
  - 早报第 2 周就给评分和价位，台账第 12 周才结算，与"问责闭环"的卖点相反。

### (2) 与 STRUCTURE.md 或负责人决定的出入

- 英文表头（`source_id, tier, mode…`、`code,name,market…`）与现有中文表不一致。表是用户在界面和手机上直接看的，也要迁移现有 6 位同事。
- 共用数据目录把"两个产品"做成"一个应用两个包"，与"effectively TWO PRODUCTS"有出入，需负责人确认。
- 包签名（`integrity.json`）、npmmirror 分发、信源表与状态表并排显示，都是新基础设施或三端界面改动（桌面、手机网页、APK），不属于"小的后端改动"。

### (3) 对的，必须保留

- 信源表（人和同事改）与信源状态（只由采集器写）分开，避免脚本和模型抢写同一个 CSV（基线 15 是现成证据）。
- 表镜像：主人的表留在自己文件夹，宿主在运行前拷只读副本。这是唯一与沙箱相容的共享方式。
- `brief@1` 把覆盖情况放进 `deliver` 现有的 summary 行（`index.js:726`），零界面改动。
- "待上岗"面板一键上岗，不经模型，绕开全部提问守卫。
- 安装包自带 CPython 压缩包，默认不解压。
- 代办工具"先列后调"并按调用者会话查白名单：宿主工具能识别调用者（`index.js:714-716`），形状可行，只是工时要改。
- 动作闸门是"审批"而不是"拒绝"，与现有机制一致。
- pack-lint 试跑全部信源行；`skills.lock` 的 `adapted` 字段；脚本核验在模型核验之前；按天的工时标尺。

## (4) 排名与合成

**可行性排名：A > C > B。**
- A 在见到第一份简报前要动的内核最少，默认名册不依赖任何未验证件。
- C 的边界划得最对，但开局最重，内部有几处自相矛盾。
- B 的供给地图最全，但踩在最多"代码今天做不到"的假设上。

**哪些"2 周"其实是 2 个月**

| 项目 | 方案里的说法 | 我的估计（一个人） |
|---|---|---|
| v2 安装包加 `--edition`，含 Windows 实机验证 | 小到中 | 1.5–2 周 |
| 模板实例化加首次运行（改 intro、放开守卫或做引导卡、三端界面） | 中加小 | 2 周 |
| 采集器（四种模式、游标、健康、按主机限速） | B 放 2 周；C 标"大" | 3–4 周 |
| 五家快讯加四个公告端点加分类 | B 放 2 周 | 2–3 周 |
| 连接器代办加密钥库加界面 | 中 | 3–4 周 |
| 托管 Python（镜像、Windows 路径与杀软） | 中 | 2–3 周，且此处无法测试 |
| 13 位同事名册 | 6 周 | 3–4 个月（每位约 1 周，含脚本和 5 天观察） |

**合成必须拿的**
- 从 A：Node-only 默认名册；默认不挂 MCP；结构化 `schedule`；分阶段名册加 `handoff`；2 周只做两位第一同事加大陆实测；台账第一版就有。
- 从 B：采集器先做成 skill；`pre / window / stale / cooldown / maxAlerts` 字段；T0–T4 和"T4 可缺"；错峰；按增益排的连接清单。
- 从 C：信源表与状态表分开；表镜像；`brief@1` 用 summary 行；"待上岗"面板；自带 CPython；"先列后调"代办；审批式闸门；pack-lint。

**合成必须丢的**
- A：经 `mywork_ask` 的三问开场和例行里的每日提议；文件夹外的共享目录；把 0600 当隔离；OpenCLI；6 周 13 位。
- B：Python 默认开；Chrome for Testing 加扩展路线；随包约 24 个第三方 skill（每位同事留 1–2 个改写过的）；数字核验闸门的现有表述；2 周清单。
- C：前 12 周的 npm、签名分发和"拒绝 bin 与插件"的纯度（改为随安装包带，另留"按版本的 kit 成员"出口）；共用数据目录；英文表头；内核采集器包放进头 2 周。

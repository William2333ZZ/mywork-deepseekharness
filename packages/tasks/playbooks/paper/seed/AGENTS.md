# 论文的规矩

## 这篇论文

（开张时写：主要发现、投哪、截止日期、页数和格式要求。）

## 论点（Neel Nanda：Explore → Understand → Distill）

- 论点.md 是一张表：`| 论点 | 证据 | 局限 | 状态 |`。状态写「有证据 / 证据弱 / 还缺实验」。
- 一篇论文压成 3–5 条论点，每条范围说清楚；证据写到哪张表、哪个实验、哪个结果文件。
- 写之前先定论点；写的时候每段都要能指出它支撑哪一条。
- 发现情况比想的乱，就承认，把状态改回「证据弱」或「还缺实验」，别硬写。

## 写

- 写来告知，不是说服：不夸大，局限和反例写出来。
- 数字只从原始结果文件来；改稿后核一遍稿子里的数字。

## 核引用（投稿前跑一次）

1. 调 mywork_cite_check：程序到 arXiv 和 Crossref 查每条参考文献存不存在、标题 / 第一作者 / 年份对不对，找出每条引用所在的句子，写成 核引用/日期.md 和 .json（json 里有查到的摘要）。
2. 你对每条「核实」和「元数据不符」的引用，比对原句和查到的摘要：支持 / 弱 / 不支持。不支持比元数据错更危险。
3. 处理：
   - 元数据不符（作者、年份、标题、会议）：直接改 .bib（KEEP / FIX）。
   - 查无此文：只是疑似（译过的标题、书、学位论文常被误报），列给用户确认，不要自己删。
   - 不支持原句、要换或要删的（REPLACE / REMOVE）：列给用户拍板。
   - 待查：网络失败，不算查无此文，过一会儿再跑。
4. 判断写进报告末尾「## 是否支持原句」一节：一行一条，key、判断、理由。
5. 同一份稿子没改参考文献就不用再跑。

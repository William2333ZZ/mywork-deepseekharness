# 交易工作台 · 立意与形态（v2 提案）

> 一句话：**你的市场研究员。只看交易数据，给出概率，敢被复盘。**

## 1. 立意

信息过载的时代，新闻、观点、短视频都在争夺注意力，它们顺着情绪走。只有一种信息是被真金白银投过票的：价格。有效市场的核心洞察是「所有公开信息都已经在价格里」。交易工作台的立意就是这一句的产品化：

**把价格翻译成概率，替你做一个研究员的工作。**

它对用户承诺三件事：

1. **只用交易数据。** 预测市场、期权、国债曲线、机构持仓、内部人交易、资金流。不引用新闻，不引用观点。
2. **每个结论带概率和时间窗口。** 不说「看多」，说「6 到 12 个月正收益概率 52%」。
3. **每个结论敢被复盘。** 报告存档、同题历史、事后对错。它愿意被你打分。

它不是什么：不是行情软件（不画 K 线），不是资讯（不推新闻），不是荐股，不下单。

用户是谁：有持仓、有想法、但没有研究团队的个人投资者。他每天问自己三件事：市场在哪、我的仓怎么样、今天有什么不一样。

## 2. 形态：从聊天工具到出报告的工作台

现在的形态是「带市场数据的聊天工具」：驾驶舱是一页，提问是一页，报告是聊天记录事后存的卡。Manus 和 Muse 的形态好在围绕交付物、少概念、有质量回路、可以离开再回来。我们要变成：

| 概念 | 现在 | v2 |
|------|------|----|
| 用户的动作 | 发一条消息 | 下达一个任务 |
| 系统的产出 | 一段对话 | 一份报告（页面，可导出） |
| 过程 | 工具调用行 | 计划步骤：取数 → 交叉 → 结论 → 核验 |
| 质量 | 模型写一次 | 核验回合，报告头显示「已核验 n/n」 |
| 时间 | 同步盯着 | 后台跑，完成通知，随时回来 |
| 每天 | 数据摘要推飞书 | 早盘简报是一份报告，推飞书的是它的摘要和链接 |
| 名字 | 驾驶舱 / 提问 / 分析记录 / 报告 / 巡检 / 市场先知 | 今日 / 任务 / 报告 / 持仓 / 设置 |

三个核心对象：**任务**（一个问题或一只标的）、**报告**（任务的交付物）、**持仓与自选**（任务的对象）。驾驶舱的信号不再是一页，而是「今日」页顶部的一条状态和早盘简报里的内容。

## 3. UI

### 导航（左栏）

```
交易工作台
  今日        早盘简报 · 市场状态 · 进行中的任务 · 提问框
  任务        所有任务：排队 / 取数 / 推理 / 核验 / 完成，一句结果
  报告        交付物列表，按标的、主题筛，同题历史，对错
  持仓        自选与持仓一张表，每行「研究这只」
  设置
```

没有「驾驶舱」「提问」「分析记录」「市场先知」这些名字了。dsh 的会话是引擎，藏在报告的「过程」里。

### 今日（首页）

从上到下：

1. 一行日期和一句市场状态（规则算出：风险偏好、实际利率、曲线、黄金、加密杠杆）。
2. **提问框**：「问一个市场问题，或者选一只标的」，框里有示例；回车即创建任务。框下三个芯片：研究我的持仓 · 今天的变化 · 某个宏观问题。
3. **早盘简报**卡：巡检生成的报告，一句结论加三条变化，点开是完整报告页。
4. **进行中**：任务卡片，显示当前步骤与耗时；完成的显示概率和一句结论。
5. **我的持仓**：最多五行，最新、日变化、浮动盈亏、最近报告，行尾「研究」。

### 报告页（交付物）

编辑部式版式，宽边距，一份文档：

1. 头部：标题、标的与主题标签、日期与取数时间、「已核验 12/12 数据点」徽章、右侧动作：对 / 错、导出、再问一次、过程。
2. 结论区：大号概率数字、时间窗口、一段结论。
3. 分层信号表（每层一个小表：信号、数据、含义、时间窗口）。
4. 矛盾分析（两栏：一边说什么、另一边说什么、如何解释）。
5. 概率场景（三行：上涨 / 震荡 / 下跌，各自概率与依据）。
6. 监测阈值（信号、当前、触发条件）。
7. 数据来源与取数时间；同题历史（概率随时间的小折线）。
8. 「过程」折叠区：计划步骤与每步耗时、取了哪些数据源、对话原文的链接。

### 任务卡与任务页

卡片：标题（问题）、状态点与步骤名、耗时；完成后变成概率和一句结论。任务页：步骤时间线（取数：8 个数据源，14 秒；交叉：3 个矛盾；结论；核验：12/12），下面是报告或错误。

### 视觉

保留市场终端家族：中性底、一个蓝色动作色、语义涨跌色、Geist 配 JetBrains Mono、1px 线、4px 圆角。报告页字号放大一级（正文 14，标题 22），概率数字 40 到 48。去掉所有平台痕迹：模型选择器、标准模式、Agent Team、轨迹标签、成员管理。

## 4. 实施

1. 任务模型（宿主：任务队列、状态、计划步骤、完成通知；会话作为执行器）。
2. 报告页渲染（从 oracle_report_save 的结构化数据生成页面；工具的参数扩成完整报告结构：结论、信号层、矛盾、场景、阈值、来源）。
3. 核验回合（第二次模型调用，只做核对，写回报告）。
4. 导航与首页重排（今日 / 任务 / 报告 / 持仓 / 设置），去缝。
5. 早盘简报改为报告任务（巡检触发一个任务，推送摘要加链接）。

先做 1、2、4，让形态立起来；3、5 随后。
